# 튜닝
이 사이트를 빠르게 하기 위한 설정을 확인합니다. "설정: 시스템" → "튜닝"(URL은 `/tuning`)에서, 설정하면 Exment가 빨라지는 항목과 지금의 상태가 목록으로 나옵니다.

※ 이 화면은 Exment v7.2.1 이후에서 쓸 수 있습니다.  
※ 이 화면을 볼 수 있는 것은 시스템 관리자뿐입니다.

![튜닝](../ja/img/tuning/tuning1.png)

## 화면 보는 법
- 항목마다 "설정 완료"나 "미설정(설정 권장)"이 나옵니다. "미설정"인 항목은 아래에 나오는 내용을 설정하십시오.
- 버튼이 있는 항목은 이 화면에서 바꿀 수 있습니다.
- 서버의 설정(php.ini·.env)은 서버 관리자에게 요청하십시오.
- 같은 내용은 설치 화면의 "더 빠르게 하려면(선택 사항)"과 `php artisan exment:checkrequire`의 "== 튜닝(선택 사항) =="에도 나옵니다. 결과는 "설정 완료"나 "미설정"뿐이고, 설치는 멈추지 않습니다.

## Exment가 직접 적용할 수 있는 설정(권장 설정)
Exment가 안전하게 바꿀 수 있는 설정은 체크를 넣어 이 화면에서 적용할 수 있습니다. 이 서버에서 필요한 것만 나옵니다.

| 설정 | 내용 |
|---|---|
| Exment 캐시 | `.env`에 `EXMENT_USE_CACHE=true` |
| 화면 파일 | JS·CSS가 갖추어져 있지 않을 때 `exment:publish`로 다시 둔다 |
| 캐시 저장 위치 | Redis를 쓸 수 있을 때(PHP에서 Redis에 닿을 때)만 캐시를 Redis에 |
| 세션 저장 위치 | 마찬가지로 Redis에(이 화면에서만. 셋업에서는 내보내지 않습니다) |
| 라우트 캐시 삭제 | 라우트 캐시가 있으면 지운다(플러그인의 화면을 열 수 없게 되기 때문) |
| 설정 캐시 생성 | `config:cache`(권한 640). `.env`를 쓰는 설정 뒤에 만듭니다 |
| 기밀 파일의 권한 | `.env`와 설정 캐시를 640으로(PHP의 사용자가 소유자일 때만) |

- "선택한 설정 적용"을 누르면 적용할 설정의 목록을 확인한 뒤에 적용합니다. 적용한 것은 작업 로그에 남고, 지난번의 결과(적용됨·이미 설정됨·실패와 그 이유)가 아래에 나옵니다.
- **셋업에서도 고를 수 있습니다**: 설치한 뒤의 초기 설정 화면에 같은 설정이 체크된 상태로 나옵니다. 체크를 뺀 것은 적용하지 않습니다.

  ![셋업의 권장 설정](../ja/img/tuning/tuning_setup.png)

- php.ini·PHP-FPM·OPcache·cron·큐는 바꾸지 않습니다. 아래 항목을 보고 서버 관리자가 설정하십시오.
- `.env`에 `EXMENT_TUNING_SERVER_ACTIONS=false`가 있으면 이 칸도 셋업에서의 설정도 나오지 않습니다.

## 항목
### OPcache
PHP 프로그램을 컴파일한 결과를 메모리에 보관해 둡니다. Exment는 파일이 많으므로 메모리와 파일 수의 상한도 크게 합니다(메모리 128MB 이상, 파일 수 20,000 이상이면 "설정 완료").

php.ini를 다음과 같이 설정하고 PHP(PHP-FPM·웹 서버)를 다시 시작하십시오.

~~~ini
opcache.enable=1
opcache.memory_consumption=256
opcache.interned_strings_buffer=16
opcache.max_accelerated_files=20000
opcache.revalidate_freq=60
~~~

### PHP 버전
PHP는 새 버전일수록 빠르게 동작합니다. PHP 8.2의 보안 지원은 2026-12-31까지입니다. PHP 8.3 이상으로 업그레이드하는 것을 권장합니다.

### 디버그 모드(APP_DEBUG)
디버그 모드에서는 요청마다 자세한 정보를 모으고, 오류의 상세를 화면에 내보냅니다. 운영 환경에서는 OFF로 합니다.

~~~
# .env
APP_DEBUG=false
~~~

### 설정 캐시(config:cache)
설정 파일을 하나로 모아, 요청마다 읽어 들이는 일을 줄입니다. 화면의 "설정 캐시 생성", "설정 캐시 삭제" 버튼이나 다음 명령으로 만들 수 있습니다.

~~~
php artisan config:cache
~~~

- `.env`를 손으로 고쳐 썼을 때는 다시 만드십시오(다시 만들 때까지 고친 내용이 반영되지 않습니다).
- Exment가 `.env`를 고쳐 썼을 때(설치·복원 등)는 캐시를 자동으로 지웁니다.
- `bootstrap/cache/config.php`에는 `.env`의 비밀(데이터베이스의 비밀번호·`APP_KEY` 등)이 들어갑니다. 하나의 서버에서 사이트마다 다른 OS 사용자로 실행하고 있을 때(멀티테넌트)는 다른 사이트에서 읽을 수 없도록, 만든 뒤에 권한을 640으로 하십시오(umask 027로 실행한다).
- 라우트 캐시(`route:cache`)는 쓰지 않습니다. 플러그인의 라우트를 데이터베이스에서 만들고 있기 때문에, 플러그인의 화면을 열 수 없게 됩니다.

### 클래스 로딩 최적화(composer)
composer로 클래스의 목록을 만들어 두면 PHP가 클래스 파일을 찾는 시간이 줄어듭니다.

~~~
composer install --optimize-autoloader --no-dev
~~~

### Exment 캐시(EXMENT_USE_CACHE)
테이블·열·설정 등의 정의를 캐시에 넣어, 요청마다 데이터베이스에서 읽지 않게 합니다.

~~~
# .env
EXMENT_USE_CACHE=true
~~~

### 캐시 및 세션 저장 위치
캐시와 세션을 Redis 등에 두면 파일보다 빨라집니다. 웹 서버가 여러 대일 때는 필요합니다. Redis를 쓸 수 있을 때는 다음과 같이 설정합니다(선택 사항).

~~~
# .env (Redis)
CACHE_STORE=redis
SESSION_DRIVER=redis
~~~

### 큐(메일 등 백그라운드 처리)
큐가 `sync`일 때는 메일 전송 등을 화면의 처리 안에서 하기 때문에, 끝날 때까지 화면이 기다리게 됩니다. 다음과 같이 설정하고 큐의 워커를 실행하십시오(supervisor·systemd 등).

~~~
# .env
QUEUE_CONNECTION=database
# 워커를 계속 실행한다
php artisan queue:work --tries=3
~~~

### 대시보드 집계 캐시(EXMENT_DASHBOARD_CACHE_SECONDS)
집계 뷰의 그래프는 대시보드를 열 때마다 테이블을 집계합니다. 결과를 정한 초 수만큼 보는 사람별로 남기고, 그동안에는 다시 집계하지 않습니다. 초기값은 `0`(쓰지 않음)입니다.

~~~
# .env(초)
EXMENT_DASHBOARD_CACHE_SECONDS=60
~~~

- 데이터를 저장·삭제했을 때는 다시 집계합니다.
- 공유나 소속의 변경 등은 남기는 시간이 지난 뒤에 표에 나옵니다.

### 조사용 로그
시스템 성능 로그와 `.env`의 디버그 모드(`EXMENT_DEBUG_MODE_REQUEST`·`EXMENT_DEBUG_MODE_SQL`·`EXMENT_DEBUG_MODE_SQLFUNCTION`·`EXMENT_DEBUG_MODE_SQLFUNCTION1`·`EXMENT_DEBUG_MODE_SCHEDULE`)는 요청마다 로그를 씁니다. 조사가 끝나면 OFF로 합니다. 시스템 성능 로그는 "시스템 성능 로그 끄기" 버튼으로 멈출 수 있습니다.

### 검색 인덱스
1만 건보다 많은 테이블에서, 필터·정렬에 자주 쓰는 열에 "검색 인덱스"를 붙이면 목록·검색·집계가 빨라집니다. [사용자 정의 열](/ko/column)의 설정에서 자주 쓰는 열에 "검색 인덱스"를 붙이십시오.

### 예약 작업(schedule:run, cron)
알림·스케줄·배치 등은 cron이 매분 실행하는 `schedule:run`으로 합니다. 매분 PHP와 Exment를 시작하므로, 무거운 처리가 있으면 화면 처리의 CPU가 줄어듭니다. 마지막으로 실행된 시각과 1분당 가장 긴 시간이 나옵니다. cron이 동작하지 않을 때나 무거운 작업이 있을 때 알립니다.

### PHP-FPM 프로세스
`pm = ondemand`이고 대기 시간(`pm.process_idle_timeout`)이 짧으면, 한동안 쓰이지 않은 뒤의 첫 번째가 프로세스를 깨우는 만큼 느려집니다. `pm.max_children`은 서버의 메모리에 맞춥니다.

### 라우트 캐시(route:cache)
Exment는 플러그인 화면의 라우트를 요청마다 데이터베이스에서 더합니다. 라우트 캐시가 있으면 나중에 설치한 플러그인의 화면을 열 수 없습니다. **없는 것이 올바른 상태**입니다.

### 기밀 파일의 권한(.env, 설정 캐시)
`.env`와 설정 캐시(`bootstrap/cache/config.php`)에는 비밀번호와 APP_KEY가 들어 있습니다. 서버의 다른 사용자가 읽을 수 없도록 640 등으로 합니다(위의 "Exment가 직접 적용할 수 있는 설정"에서도 고칠 수 있습니다).

### 화면 파일(JS, CSS)
로그인 화면 등이 읽어 들이는 JS·CSS가 갖추어져 있는지, 브라우저가 기억해 둘 수 있는 설정(Cache-Control·Expires)인지를 확인합니다. URL에는 버전(`?v=`)이 붙으므로 오래 기억하게 해도 괜찮습니다.

### 슬로우 쿼리 로그(데이터베이스)
MySQL·MariaDB의 slow query log를 ON으로 하면 시간이 걸린 쿼리가 기록되어, 느린 원인을 찾을 수 있습니다.

### 검색 인덱스 열의 인덱스(데이터베이스)
"검색 인덱스"를 붙인 열에는 데이터의 표에 전용 열과 인덱스가 있습니다. 복원이나 변경의 실패로 인덱스가 없으면, 필터·정렬을 할 때마다 전체 건을 읽습니다. 인덱스가 갖추어져 있는지를 확인합니다.

## 그 밖에 속도에 관계되는 설정
### 목록 뷰의 그래프(EXMENT_CHART_LIST_MAX_ROWS)
목록 뷰의 그래프는 한 행에 점 하나를 그립니다. 초기값(`0`)에서는 모든 행을 읽습니다. 큰 테이블에서 메모리나 시간이 모자랄 때는 `.env`에서 상한을 정할 수 있습니다(예: 1000). 상한을 넘었을 때는 "집계 뷰의 차트로 해 주십시오"라는 뜻의 메시지가 나옵니다. 큰 테이블의 그래프는 집계 뷰로 만드십시오.

~~~
# .env(상한을 정할 때)
EXMENT_CHART_LIST_MAX_ROWS=1000
~~~

## 화면의 버튼을 내보내지 않기(EXMENT_TUNING_SERVER_ACTIONS)
하나의 서버에서 여러 사이트가 코드를 공유하고 있을 때(멀티테넌트 등)는 `.env`에 다음과 같이 쓰면, 서버 전체를 바꾸는 버튼(설정 캐시 생성·삭제)을 내보내지 않습니다. 화면에는 "이 서버에서는 화면에서 변경할 수 없습니다(서버 관리자가 설정합니다)."라고 나옵니다.

~~~
# .env
EXMENT_TUNING_SERVER_ACTIONS=false
~~~

## 화면을 숨기기
- 튜닝은 "[기능 관리](/ko/feature)"의 기능 중 하나이며, 처음부터 "사용"입니다. 사이트의 시스템 관리자는 기능 관리에서 "사용 안 함"으로 할 수 있습니다.
- 서버 쪽(SaaS 등)에서 숨길 때는 `.env`에 `EXMENT_FEATURES_LOCKED=tuning`을 씁니다(다른 기능과 함께 막을 때는 쉼표로 구분합니다). 화면은 404가 되고 메뉴에도 나오지 않습니다.
