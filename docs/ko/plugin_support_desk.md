# 서포트 데스크(공식 플러그인)
"서포트 데스크"(「サポートデスク」)는 IT 지원·헬프데스크를 위한 Exment의 **공식 플러그인**입니다. 고객의 의뢰(메일·접수 폼·전화)와, 모니터링이나 오류 로그에서 찾은 문제를 "티켓"으로 관리하고, **진행 상황을 고객과 로그인 없이 공유**합니다. 무료로 사용할 수 있습니다.

- 소스 코드·설명: [exceedone/exment-plugins(support-desk)](https://github.com/exceedone/exment-plugins/tree/main/support-desk)
- 라이선스: GPL-3.0(Exment와 같음)
- 플러그인 목록에 나오는 이름: Exment Support Desk（サポートデスク）. 내부 이름은 `ExmentSupportDesk`, URL은 `/plugins/exment_support_desk` 입니다.

## 할 수 있는 것
| 분야 | 할 수 있는 것 |
| --- | --- |
| 담당자의 화면 | 전용 **접수함**(접수함의 종류와 건수·티켓 목록·대화와 항목의 3열). 티켓을 바꿔도 페이지를 다시 읽지 않습니다. 키보드 조작(`J`/`K` 위아래·`R` 답장·`N` 사내 메모·`Ctrl+Enter` 보내기·`A` 내가 담당·`E` 해결·`?` 목록), 초안의 자동 저장, 다크 모드, 스마트폰 표시 |
| 접수 | **메일**(IMAP으로 5분마다 수신. ISO-2022-JP·Shift_JIS·첨부 파일 지원), **접수 폼**(로그인 없음·먼저 FAQ를 안내), **전화·방문**(담당자가 등록), **모니터링·오류 로그**(API. 같은 오류는 1건으로 모아 횟수를 셈), **IT 자산의 기한**(유지 보수·라이선스·도메인·인증서의 기한이 가까워지면 자동으로 티켓 등록) |
| 주고받기 | 고객에 대한 답장은 메일로 도착하고, 고객이 그대로 답장하면 같은 티켓에 들어갑니다. 인용 부분은 자동으로 없앱니다. **사내 메모**는 고객에게 보이지 않습니다. **상용구**와 **지식의 후보**를 답장 칸 옆에 냅니다 |
| 이중 대응 방지 | 다른 담당자가 같은 티켓에 답장을 쓰고 있으면 화면에 나옵니다 |
| 고객과의 공유 | **로그인 없는 링크**(그 티켓 1건만 보임·기한과 취소·연 기록). 중요한 티켓은 **확인 코드**(메일로 6자리). 로그인하는 고객은 **고객 포털**(회사의 관리자는 회사의 모든 티켓) |
| SLA | 고객별·우선순위별의, 첫 답장과 해결의 기준. **영업 시간과 공휴일로 세고**, **고객의 답장을 기다리는 동안은 멈춥니다**. 기한이 가깝거나 넘으면 담당자에게 알립니다 |
| 자동화 | 종류별 담당자나 대응 중인 건이 적은 사람에게 자동으로 배정. 답장 대기의 요청 → 자동으로 해결 → 자동으로 완료. 해결하면 만족도(5단계)를 묻습니다 |
| 지식(FAQ) | 공개한 글은 고객의 FAQ 페이지와 접수 폼에 나옵니다. 티켓에서 한 번의 클릭으로 초안을 만들 수 있습니다 |
| IT 자산 | 고객의 PC·서버·라이선스 등을 등록하고 티켓과 연결합니다 |
| 리포트 | 접수·해결·SLA의 달성률·첫 답장까지의 시간·만족도 등. **고객별 작업 시간과 계약 시간의 비교**(월 보고에), CSV |
| 검색 | 제목·본문·주고받은 내용·메일·번호의 부분 일치. 공백으로 AND, 태그는 AND/OR를 고를 수 있습니다 |
| 사용자 정의 | 모두 Exment의 테이블이므로 항목·화면·목록·워크플로·API를 Exment의 화면에서 바꿀 수 있습니다. 티켓의 보드(칸반)도 붙어 있습니다 |

## 동작 요건
- Exment 7.0 이상(PHP 8.2 이상). 추가 PHP 확장은 필요 없습니다.
- 메일 수신에는 접수용 메일함(IMAP)이 필요합니다. 전송은 Exment의 [메일 전송 설정](/ko/mailsend_setting)을 사용합니다.
- 자동 처리(메일 수신·SLA·답장 대기·완료·자산의 기한)는 5분마다 동작합니다. [작업 스케줄](/ko/additional_task_schedule)을 설정해 주십시오.
- 화면은 일본어뿐입니다.

## 설치
1. 플러그인을 설치합니다. Exment v7.2.1 이상은 "기능 관리"에서, 그보다 이전은 zip 업로드입니다. [공식 플러그인](/ko/plugin_official)을 참조하십시오.
2. Exment v7.2.1 이상에서는 "관리자 설정" → "[기능 관리](/ko/feature)"에서 「サポートデスク：受付箱」(서포트 데스크: 접수함)을 켭니다(꺼져 있는 동안은 설정 화면도 열 수 없습니다). 접수함은 사용할 수 있는 역할 그룹을 고를 수 있습니다. 고객 창구(`/support`)·메일 수신·모니터링에서의 티켓 등록을 사용한다면 「サポートデスク：お客様の窓口」(서포트 데스크: 고객 창구)도 켭니다(접수함이 켜져 있을 때만 동작합니다).
   - 새로 설치한 사이트에서는 둘 다 처음에는 꺼져 있습니다. 기능 관리 이전부터 서포트 데스크를 사용하던 사이트에서는 둘 다 켜진 채로 남습니다.
   - 접수함을 "사용 안 함"으로 하면 메뉴의 「サポートデスク」도 사라집니다. 티켓 등의 테이블은 데이터로 남고, Exment의 보통 테이블로서 URL(`/data/sd_ticket` 등)이나 "관리자 설정" → "사용자 정의 테이블"에서 열 수 있습니다. 메뉴에 내고 싶을 때는 "관리자 설정" → "메뉴"에서 테이블을 추가해 주십시오. 보이지 않게 하고 싶을 때는 역할 그룹에서 테이블의 권한을 빼 주십시오.
3. 메뉴의 「サポートデスク」(또는 `/plugins/exment_support_desk`)를 열고 「セットアップする」(설정하기)를 누릅니다. 테이블·메뉴·권한·SLA·종류·상용구·FAQ의 예까지 들어갑니다.
   - 왼쪽 메뉴는 「サポートデスク」 하나뿐입니다(열면 접수함). 티켓 표·지식·고객·연락처·IT 자산·상용구는 접수함 위의 메뉴에서, 모든 테이블(티켓의 종류·SLA도)은 「設定」(설정)의 「テーブル・権限」(테이블·권한)에서 엽니다.
   - 1.0.6까지의 「ITサポート」 폴더(접수함과 테이블 8개)는 1.0.7로 올린 뒤 처음 접수함을 열었을 때 하나로 합쳐집니다. 관리자가 직접 추가한 메뉴는 남습니다.
4. 「設定」(설정)에서 접수용 메일함(IMAP)과 창구의 주소를 넣어 저장하고, 「IMAP につながるか試す」(IMAP에 연결되는지 시험)을 누릅니다. 메일 수신을 사용한다면 「差出人の確認」(보낸 사람 확인)과 「受信サーバーの名前」(수신 서버의 이름. 받은 메일의 Authentication-Results의 맨 앞 이름)도 넣습니다. 넣을 때까지는 메일로 온 티켓이 "사칭 의심"이 됩니다.
5. 담당자를 역할 그룹 「サポートデスク 担当者」(서포트 데스크 담당자)에 넣습니다. 로그인하는 고객은 「サポートデスク お客様」(서포트 데스크 고객)에 넣고, 「お客様の担当者」(고객의 담당자)의 「Exment のユーザー」(Exment의 사용자)로 연결합니다.
6. 고객에게는 창구의 URL(`https://당신의 Exment/support`)을 안내합니다.

## 사용 방법

### 접수함
메뉴의 「サポートデスク」(서포트 데스크)를 열면 접수함이 나옵니다. 화면은 3열입니다.

| 열 | 내용 |
| --- | --- |
| 왼쪽 | 접수함의 종류와 건수: 「対応が必要」(대응 필요)·「自分の担当」(내 담당)·「担当者なし」(담당자 없음)·「お客様から返事」(고객의 답장)·「SLA 注意・超過」(SLA 주의·초과)·「お客様の返事待ち」(고객의 답장 대기)·「保留」(보류)·「監視・エラー」(모니터링·오류)·「解決」(해결)·「完了」(완료)·「すべて」(모두). 아래에 메일 수신의 켜짐·꺼짐과, 자동 처리가 마지막으로 동작한 시각이 나옵니다 |
| 가운데 | 티켓 목록. 제목·본문·주고받은 내용·메일·번호로 찾을 수 있습니다. 필터(상태·우선순위·담당자·고객·종류·태그)와 정렬 순서(기한이 가까운 순·우선순위 순·새로운 순·오래된 순·업데이트 순)를 고를 수 있습니다. 여러 개를 고르면 상태·우선순위·담당자를 한 번에 바꿀 수 있습니다 |
| 오른쪽 | 고른 티켓의 대화와 답장 칸. 그 오른쪽에 항목(상태·우선순위·담당자·종류·고객·태그·「お客様に見せる」(고객에게 보이기)·「開くときに確認のコード」(열 때 확인 코드)), SLA, 고객, 고객의 링크, 지식, 파일, 같은 고객의 티켓, 합치기 |

| 키 | 하는 일 |
| --- | --- |
| `J` / `K` | 다음·이전 티켓 |
| `/` | 찾기 |
| `R` | 고객에게 답장 |
| `N` | 사내 메모 |
| `Ctrl` + `Enter` | 보내기 |
| `A` | 나를 담당자로 하기 |
| `E` | 해결로 하기 |
| `\` | 오른쪽 칸 열기·닫기 |
| `?` | 단축키 목록 |
| `Esc` | 닫기·입력에서 나가기 |

전화·방문·사내에서 찾은 일은 위쪽 메뉴의 「チケット」(티켓)에서 등록합니다(「受付のメール」(접수 메일)을 고르면 고객에게 번호와 링크를 보냅니다).

### 티켓의 흐름
상태는 다음 6가지입니다.

新規(신규) → 対応中(대응 중) → お客様の返事待ち(고객의 답장 대기)／保留（社内）(보류, 사내) → 解決(해결) → 完了(완료)

- 메일·접수 폼으로 온 티켓은 「新規」(신규)입니다. 담당자가 고객에게 답장하면 「対応中」(대응 중)이 됩니다. 담당자가 등록한 티켓은 처음부터 「対応中」입니다.
- 답장 칸의 「送ったあとの状態」(보낸 뒤의 상태)로, 보내면서 상태를 바꿀 수 있습니다(예: 고객에게 질문하면 「お客様の返事待ち」).
- 「お客様の返事待ち」·「解決」·「完了」인 티켓에 고객이 쓰면 「対応中」으로 돌아갑니다. 완료에서 14일보다 뒤에 썼을 때는 이전 티켓을 가리키는 새 티켓이 됩니다.
- 「お客様の返事待ち」인 채로 답장이 없으면, 마지막 답장에서 3일에 부탁 메일을 보내고, 7일에 「解決」로 합니다.
- 「解決」는 `E` 키, 오른쪽 칸의 상태, 고객 링크의 「解決しました」(해결되었습니다)로도 할 수 있습니다. 해결로 하면 고객에게 만족도(5단계)를 묻습니다.
- 「解決」에서 7일이 지나면 「完了」가 됩니다.
- 일수는 「設定」(설정)의 「自動で進める」(자동 진행)에서 바꿀 수 있습니다(0이면 하지 않습니다).

### 답장과 사내 메모
- 답장 칸의 「お客様へ返信」(고객에게 답장)은 메일로 도착합니다. 제목의 맨 앞에 티켓 번호(예: `[SUP-00012]`)가 붙고, 진행 상황의 링크도 들어갑니다. CC도 넣을 수 있습니다.
- 「社内メモ」(사내 메모)는 고객에게 보이지 않습니다. 메일도 보내지 않습니다.
- 답장마다 작업 시간(분)을 넣을 수 있습니다. 고객별로 합계하여 계약 시간과 비교합니다.
- 고객이 그대로 답장하면, 제목의 번호나 어느 메일에 대한 답장인지(Message-ID)로 같은 티켓에 들어갑니다. 인용 부분은 없앱니다. 의뢰한 사람·CC·같은 회사의 사람이 아니면 같은 티켓에는 들어가지 않습니다.
- 다른 담당자가 같은 티켓에 답장을 쓰고 있으면 화면에 나옵니다.

### 담당
- 오른쪽 칸의 「担当者」(담당자)에서 고릅니다. `A` 키로 내가 담당이 됩니다. 담당자가 없는 티켓에 답장이나 사내 메모를 보내면, 보낸 사람이 담당자가 됩니다.
- 자동으로 정할 때는 「設定」(설정)의 「担当者の決め方」(담당자를 정하는 방법)에서 고릅니다.
    - 種類ごとの「最初の担当者」(종류별 "첫 담당자", 초깃값): 티켓의 종류에 정한 사람입니다.
    - 種類で決まらなければ、対応中が少ない人(종류로 정해지지 않으면 대응 중인 건이 적은 사람): 역할 그룹 「サポートデスク 担当者」(서포트 데스크 담당자) 안에서, 끝나지 않은 티켓이 가장 적은 사람입니다.
    - 自動では決めない(자동으로 정하지 않음)

### 기한(SLA)
- 티켓마다 「最初の返事の期限」(첫 답장의 기한)과 「解決の期限」(해결의 기한)을 넣습니다. 기준은 「SLA」 테이블에서 우선순위(緊急 긴급·高 높음·中 보통·低 낮음)별로 정합니다. 첫 답장은 분, 해결은 시간입니다.
- 고객에게 SLA가 정해져 있지 않을 때는 「標準にする」(표준으로 하기)의 SLA를 사용합니다. 설정하기로 「標準」(표준. 영업 시간만 셈)과 「プレミアム（24 時間）」(프리미엄, 24시간)이 들어갑니다.
- 「営業時間だけで数える」(영업 시간만 세기) SLA는 「設定」(설정)의 「営業時間（SLA の時計）」(영업 시간, SLA의 시계)의 영업일·시간·휴일만 셉니다. 일본의 공휴일은 설정하기 때 올해와 내년 것이 들어갑니다. 연말연시 등은 직접 추가합니다.
- 「お客様の返事待ち」(고객의 답장 대기)인 동안은 시계를 멈추고, 멈춘 만큼 해결의 기한을 뒤로 미룹니다.
- 남은 시간이 적어졌을 때(남은 시간이 전체의 4분의 1, 또는 30분보다 적어졌을 때)와 기한을 넘었을 때, 담당자에게 벨과 메일로 알립니다. 담당자가 없을 때는 담당자 모두에게 알립니다.

### 상용구와 지식
- 답장 칸의 「定型文…」(상용구)에서 고르면 본문에 들어갑니다. `{name}`(고객의 이름)·`{ticket_no}`·`{subject}`·`{link}` 는 티켓의 값으로 바뀝니다. 상용구에 상태가 정해져 있으면 「送ったあとの状態」(보낸 뒤의 상태)도 바뀝니다. 상용구는 위쪽 메뉴의 「定型文」(상용구)에서 추가할 수 있습니다.
- 오른쪽 칸의 「ナレッジ」(지식)에 제목에 맞는 글이 나옵니다. 찾을 수도 있습니다. 누르면 공개한 글은 제목과 링크가, 그 밖은 본문이 답장에 들어갑니다.
- 「このチケットからナレッジを作る」(이 티켓으로 지식 만들기)로 글의 초안이 만들어집니다.

### 고객 쪽
고객 창구는 `https://당신의 Exment/support` 입니다(「サポートデスク：お客様の窓口」(서포트 데스크: 고객 창구)와, 「設定」(설정)의 「お客様の窓口（ログインなし）」(고객 창구, 로그인 없음)의 「使う」(사용)가 둘 다 켜져 있을 때).

| URL | 내용 |
| --- | --- |
| `/support` | 창구의 첫 화면. FAQ 찾기·의뢰하기·내 의뢰 보기 |
| `/support/request` | 접수 폼(로그인 없음). 이름·메일 주소·제목·내용이 필수이고, 파일은 5개까지(1개 10MB까지) |
| `/support/faq` | 공개한 지식(FAQ) |
| `/support/mine` | 내 의뢰 보기. 메일 주소를 넣으면 의뢰 목록의 링크가 메일로 도착합니다(7일간 사용할 수 있습니다) |
| `/support/t/…` | 티켓 1건의 페이지. 메일의 링크에서 엽니다 |

- 티켓의 페이지에서는 접수·대응 중·해결·완료의 어디까지 진행되었는지와, 주고받은 내용(사내 메모는 나오지 않습니다)이 보입니다. 답장과 파일을 보낼 수 있고, 「解決しました」(해결되었습니다)를 누를 수 있습니다.
- 링크는 티켓이 완료되고 30일이 지나면 열 수 없게 됩니다(「設定」(설정)의 「リンクの期限」(링크의 기한)).
- 오른쪽 칸의 「開くときに確認のコード」(열 때 확인 코드)를 켠 티켓은, 등록된 메일로 도착하는 6자리 코드가 없으면 열 수 없습니다.
- 로그인하는 고객(역할 그룹 「サポートデスク お客様」(서포트 데스크 고객))이 「サポートデスク」를 열면, 자신의 의뢰 목록(`/plugins/exment_support_desk/my`)이 나옵니다. 고객의 담당자 중 「お客様の管理者」(고객의 관리자)인 사람에게는 회사의 의뢰가 모두 나옵니다.

### 메일 접수
- 「設定」(설정)의 「メールで受け付ける（IMAP）」(메일로 접수, IMAP)에서 「受信する」(수신)를 켜고, IMAP 서버·포트와 암호화(SSL/TLS·STARTTLS)·사용자 이름·비밀번호·폴더를 넣습니다. 비밀번호는 암호화하여 저장합니다.
- 수신은 5분마다입니다(1회에 50통까지). 「いますぐ受信する」(지금 바로 수신)로도 받을 수 있습니다. 아직 읽지 않은 메일을 읽고, 읽음 표시를 붙입니다.
- ISO-2022-JP·Shift_JIS 메일, 첨부 파일(1통에 20개까지)을 가져올 수 있습니다.
- 새 메일은 「新規」(신규) 티켓이 되고, 고객에게 접수 메일(번호와 링크)을 보냅니다. 제목의 "Re:" 등은 없애고, 본문에 「至急」「緊急」「止まって」(긴급, 멈춤) 등이 있으면 우선순위를 「高」(높음)로 합니다.
- 보낸 사람의 주소가 등록한 연락처에 있으면 그 고객의 티켓이 됩니다. 없으면 주소의 도메인이 고객의 「メールのドメイン」(메일의 도메인)과 맞는 고객의 티켓으로 하고, 연락처를 만듭니다. 모르는 보낸 사람은 「知らない差出人」(모르는 보낸 사람) 설정에서, 티켓으로 할지(고객 없음) 가져오지 않을지를 고를 수 있습니다.
- 답장 메일의 처리와 사칭 의심 메일은 위의 "답장과 사내 메모"와 아래의 "안전을 위한 규칙"을 참조하십시오.

## 모니터링·오류 로그에서 티켓 등록하기
모니터링 시스템에서 API로 티켓을 만들 수 있습니다. 키는 설정 화면에 있습니다.

~~~sh
curl -X POST https://당신의 Exment/support/intake/alert \
  -H "X-SD-Key: (설정 화면의 키)" \
  -H "Content-Type: application/json" \
  -d '{"title":"Disk full on web01","source":"web01.example.co.jp","severity":"error","detail":"/var 98%"}'
~~~

| 항목 | 의미 |
| --- | --- |
| `title`(필수) | 제목(`message` 로도 받습니다) |
| `source` | 발생한 곳(`host` 로도 받습니다). 도메인이 고객의 "메일의 도메인"과 맞으면 그 고객의 티켓이 됩니다 |
| `severity` | 우선순위가 됩니다(`level` 로도 받습니다). critical·emergency·alert·fatal은 "긴급", error·high는 "높음", 그 밖은 "보통" |
| `fingerprint` | 같은 오류를 모으는 표시(없으면 발생한 곳과 제목으로 만듭니다) |
| `detail` | 본문 |
| `customer` | 고객 코드 |

원래의 메일을 그대로 보낼 수 있는 구조(Postfix의 파이프 등)에서는 `/support/intake/mail` 에 POST할 수 있습니다(같은 키).

- 모니터링에서 만든 티켓은 처음에는 고객에게 보이지 않습니다.
- 기능 관리에서 「サポートデスク：お客様の窓口」(서포트 데스크: 고객 창구)가 꺼져 있을 때는 `/support/intake/alert` 와 `/support/intake/mail` 은 404가 됩니다.

## 안전을 위한 규칙
- 고객의 링크는 추측할 수 없는 긴 번호이며, 데이터베이스에는 해시만 저장합니다. 링크로 보이는 것은 그 티켓 1건뿐입니다(사내 메모·다른 고객·담당자의 메일 주소는 나오지 않습니다).
- 확인 코드는 10분·5회까지·한 번뿐입니다. 링크마다 코드를 보내는 것은 1시간에 5회까지, 틀리는 것은 하루 10회까지입니다(넘으면 그 링크의 코드는 다음 날까지 사용할 수 없습니다).
- 제목에 티켓 번호를 써도, 의뢰한 사람·CC·같은 회사의 사람이 아니면 그 티켓에는 들어가지 않습니다.
- 보낸 사람 확인은 초깃값(권장)에서는 "수신 서버의 확인(DMARC 또는 From의 도메인에 맞춘 DKIM·SPF)에 합격한 메일만 믿는다"입니다. 확인할 수 없는 메일은 "사칭 의심"으로 받고, Cc를 넣지 않으며, 연락처도 만들지 않습니다. 지금 있는 티켓에 대한 답장이면 고객에게 보이지 않는 사내 메모(태그 「要確認」(확인 필요))가 됩니다. 설정에서 "확인에 떨어진 메일만 의심한다"로도 할 수 있습니다.
- 접수 폼은 접수한 화면에 링크를 내지 않고, 입력된 주소로 메일로 보냅니다. 그 링크를 열 때까지 티켓에 태그 「メール未確認」(메일 미확인)이 붙고, 연락처는 만들지 않습니다.
- 자동 답장·반송 메일·자신의 주소에서 온 메일은 가져오지 않습니다.
- 만족도의 링크는 열기만 해서는 저장하지 않습니다.
- 담당자의 화면을 사용할 수 있는 것은 티켓 테이블을 "모두 편집"할 수 있는 사람(역할 그룹 「サポートデスク 担当者」 등)뿐입니다. "자신의 데이터만 편집"으로는 사용할 수 없습니다.

### 로그인 없는 페이지에 대하여
Exment는 안전을 위해 플러그인의 `config.json` 에서는 로그인 없는 페이지를 만들 수 없게 하고 있습니다. 헬프데스크에는 계정이 없는 고객의 입구가 필요하므로, 이 플러그인은 Exment가 시작될 때 `/support/...` 페이지를 직접 등록합니다. Exment의 공개 폼과 같은 생각으로, URL의 비밀이 열 수 있는 것만 보여 줍니다.
