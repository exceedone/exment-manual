# v7.3.0 업데이트 절차
v7.2.x에서 v7.3.0으로 올리는 절차입니다. v7 안의 업데이트지만, <span class="red bold">v7.3만은 `composer update`만으로는 올라가지 않습니다.</span>

v7.3에서는 관리 화면 라이브러리 "exceedone/exment-admin-core"가 1.x에서 **2.x**로 바뀝니다. 지금까지의 `composer.json`은 admin-core를 `^1.0`으로 정하고 있으므로, 그대로 `composer update`를 해도 "Nothing to install, update or remove"라고 나오고 v7.2.x 그대로입니다.

| | v7.2.x | v7.3.0 |
| ---- | ---- | ---- |
| PHP | 8.2 이상 | 8.2 이상(변경 없음) |
| exceedone/exment-admin-core | 1.x(`^1.0`) | **2.x(`^2.1.1`)** |
| QR 코드 라이브러리 | simplesoftwareio/simple-qrcode | bacon/bacon-qr-code 3.x |
| Laravel | 12 | 12(변경 없음) |
| MySQL / MariaDB | 8.0 이상 / 10.11 이상 | 변경 없음 |

업데이트 중 오류가 나면 [트러블슈팅](/ko/troubleshooting)을 보십시오.

## 1. 백업하기
<span class="red bold">반드시 올리기 전에 백업하십시오.</span>

- 데이터베이스와 Exment 폴더 전체(`composer.json`, `composer.lock`, `vendor`, `public/vendor`, `.env`, `storage` 포함)를 백업합니다.
- <span class="red bold">백업 파일이 만들어졌는지 직접 확인하십시오.</span> `php artisan exment:backup`은 mysqldump가 실패해도(예: 데이터베이스의 TLS 인증서가 자체 서명일 때) 오류 없이 끝날 수 있습니다.

## 2. composer로 설치한 사이트
Exment를 설치한 폴더(프로젝트 루트)에서 다음을 순서대로 실행합니다.

~~~
# 1. composer.json에 simplesoftwareio/simple-qrcode 줄이 있을 때만
composer remove simplesoftwareio/simple-qrcode --no-update

# 2. exment와 exment-admin-core를 7.3 버전으로(-W가 필요합니다)
composer require "exceedone/exment:^7.3" "exceedone/exment-admin-core:^2.1.1" -W

# 3. 데이터베이스 등을 새로 함
php artisan exment:update --force
~~~

- **1.** v7.2의 zip이나 boilerplate로 설치한 사이트의 `composer.json`에는 `simplesoftwareio/simple-qrcode` 줄이 있습니다(v7.3에서는 사용하지 않습니다). 남아 있어도 올라가지만, 사용하지 않는 줄이 남으므로 지우기를 권장합니다.
- **2.** `-W`(`--with-all-dependencies`)를 붙이십시오. 붙이지 않으면 "bacon … fixed to 1.0.2 by a partial update"처럼 멈춥니다. 이것으로 exment 7.3, exment-admin-core 2.1.1 이상, bacon/bacon-qr-code 3.x가 됩니다(dasprid/enum도 들어갑니다).
    - 사이트가 직접 `bacon/bacon-qr-code` 1.x를 require하고 있을 때는 `"bacon/bacon-qr-code:^3"`도 같은 줄에 추가합니다.
- **3.** `--force`는 본번(`APP_ENV=production`)에서의 확인을 생략합니다.
- `composer.json`에 exment-admin-core도 simple-qrcode도 적혀 있지 않은 사이트(`exceedone/exment`만 require하는 사이트)는 일반적인 `composer update`와 `php artisan exment:update`로 올라갑니다.
- 끝나면 브라우저에서 **Ctrl+F5**(강력 새로고침)를 누르십시오.

## 3. zip으로 설치한 사이트·임대 서버
v7.3의 zip으로 교체합니다.

1. `php artisan down`으로 유지보수 표시로 합니다.
2. 위의 "백업하기"를 합니다.
3. 지금 폴더의 이름을 바꿉니다(예: `exment` → `exment_old`).
4. v7.3의 zip을 [다운로드](https://exment.net/download/)하여 원래 이름의 폴더에 압축을 풉니다.
5. 새 폴더의 `storage`를 지우고, 이전 폴더의 **`storage` 전체**와 **`.env`**를 복사합니다.
6. 새 폴더의 `bootstrap/cache/*.php`를 지웁니다.
7. `php artisan exment:update --force`를 실행합니다.
8. `php artisan up`으로 유지보수 표시를 끝냅니다.

| | 처리 |
|---|---|
| `.env`, `storage` 전체(`app/admin`, `app/plugins`, `app/backup`, `app/templates`, `oauth-*.key` 등) | 이전 것을 그대로 사용 |
| `public`에 직접 둔·바꾼 파일, `config/*.php`를 손으로 바꾼 부분, 직접 composer require한 패키지(ldaprecord 등) | 이전 폴더를 보면서 손으로 되돌림 |
| `app/Exment/bootstrap.php`에 쓴 자신의 코드 | 손으로 되돌림(파일은 `exment:update`가 다시 만듭니다) |
| `vendor`, `composer.json`, `composer.lock`, `public/vendor`, `bootstrap/cache` | 새 것(이전 것은 사용하지 않음. `public/vendor`는 `exment:update`가 다시 만듭니다) |

## 4. v7.3에서 바뀌는 점
### 플러그인·자체 소스: 메시지는 문자로 표시됩니다
admin-core 2.x에서는 `admin_info()`, `admin_success()`, `admin_warning()`, `admin_error()`(`*_once()` 포함), `admin_toastr()`의 메시지가 **HTML이 아니라 문자로** 표시됩니다. 이름이나 오류 문장에 `<` 등이 들어 있어도 그대로 문자로 나오므로 안전합니다.

메시지에 HTML(`<br>`이나 링크 등)을 사용할 때는 `admin_html_message()`로 감싸십시오. 안에 넣는 값은 `e()`(또는 `esc_html()`)로 감쌉니다.

~~~php
// v7.2까지
admin_info('완료', $name . '을(를) 만들었습니다.<br><a href="' . $url . '">열기</a>');

// v7.3부터
admin_info('완료', admin_html_message(e($name) . '을(를) 만들었습니다.<br><a href="' . e($url) . '">열기</a>'));
~~~

감싸지 않으면 `<br>` 등이 그대로 문자로 나옵니다(동작은 멈추지 않습니다).

### 기능 관리
v7.3에서 추가된 기능의 대부분은 "시스템 설정" → "[기능 관리](/ko/feature)"에서 사용 여부를 정합니다. 새 기능 중에는 처음에 사용하지 않음으로 되어 있는 것이 있습니다.

### 화면
왼쪽 메뉴에서 하위 메뉴가 있는 항목은 옆으로 열립니다("시스템 설정"에서 이전 방식으로 되돌릴 수 있습니다). 자세한 내용은 [릴리스 노트](/release_note)를 보십시오.

## 5. Exment SaaS를 사용하는 분
Exment SaaS는 제공하는 쪽에서 올립니다. 이 절차는 필요 없습니다.

## 6. 원래대로 되돌릴 때
올리기 전에 만든 백업으로 되돌립니다.

1. 데이터베이스를 올리기 전의 백업으로 복원합니다.
2. `composer.json`, `composer.lock`, `vendor`, `public/vendor`를 올리기 전의 것으로 되돌립니다(zip 사이트는 이름을 바꿔 남겨 둔 이전 폴더로 되돌립니다).
3. `bootstrap/cache`의 내용을 지우고 `php artisan optimize:clear`를 실행합니다.

<span class="red bold">`php artisan migrate:rollback`은 사용하지 마십시오.</span> v7.3에서 추가한 데이터베이스 변경 중에는 되돌리는 처리가 없는 것이 있어, 메뉴나 열이 남습니다.
