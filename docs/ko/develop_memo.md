# 개발 메모
개발자를 위한 메모입니다.  
각 화면의 매뉴얼에 쓰기에는 너무 자세하지만, 개발자끼리 공유해 두고 싶은 사양 등을 정리했습니다.

## 권한 "전체 데이터 참조"와 "담당 데이터 편집" 등을 함께 쓸 수 없는 이유
현재, 특정 테이블에 대해 권한 "전체 데이터 참조"와 "담당 데이터 편집" "담당 데이터 열람"을 함께 쓸 수 없습니다.  
그 이유는 아래의 사양 때문입니다.

#### 전제
권한은 병합되며, 강한 권한 쪽("가능하게 한다" 계열의 권한)을 우선합니다.  
예를 들어, "모든 데이터를 가져올 수 있게 한다"와 "자신에게 공유된 데이터만 가져올 수 있다"가 함께 있는 경우, "모든 데이터를 가져올 수 있게 한다"가 우선됩니다.

#### 권한 "전체 데이터 참조"의 상세

- SQL을 실행할 때, 데이터 공유에 따른 where 절을 추가하지 않고, 모든 데이터를 가져올 수 있게 합니다.
- 목록 화면을 표시할 수 없습니다. 또한 메뉴에 항목을 표시할 수 없습니다.
- 데이터를 새로 만들거나 편집할 수 없습니다.

#### 권한 "담당 데이터 편집"의 상세

- SQL을 실행할 때, 데이터에 따른 where 절이 실행되어, 자신에게 공유된 데이터만 가져올 수 있습니다.
- 목록 화면을 표시할 수 있습니다. 또한 메뉴에 항목을 표시할 수 있습니다.
- 데이터를 새로 만들고, 자신에게 공유된 데이터를 편집할 수 있습니다.


#### 결과
이 두 권한을 함께 쓰면 다음과 같은 상세가 됩니다.

- SQL을 실행할 때, 데이터 공유에 따른 where 절을 추가하지 않고, 모든 데이터를 가져올 수 있게 합니다.
- 목록 화면을 표시할 수 있습니다. 또한 메뉴에 항목을 표시할 수 있습니다.
- 데이터를 새로 만들고, 자신에게 공유된 데이터를 편집할 수 있습니다.

즉, 모든 데이터가 목록 화면에 표시되고, 데이터를 새로 만들고 자신에게 공유된 데이터를 편집할 수 있는 상황이 됩니다.  
  
"목록 화면에서는 모든 데이터를 가져올 수 있게 하지 않고, 자신에게 공유된 데이터만 가져올 수 있게 한다"는 처리를 각 화면에 넣을 수도 있습니다. 하지만 독자 플러그인이나 그 밖의 화면에 모두 그 처리를 추가해야 하고, 취약점이 될 수 있습니다.  
또한 이 상황은 "전체 데이터 열람"과 "담당 데이터 편집"을 함께 쓰는 것과 완전히 같습니다.  
그래서 현재 설정에서는 "전체 데이터 참조"와 "담당 데이터 편집" 등을 함께 쓸 수 없습니다.  

#### "전체 데이터 참조"의 용도
용도로는 주로 다음과 같은 것이 해당합니다.  

- 세율  
    →책임자 등에게 "전체 데이터 참조"와 "전체 데이터 편집" 권한을 주어, 마스터로서 유지 관리해 나갑니다.  
    →일반 사용자에게는 "전체 데이터 참조"만 주어, 선택지로는 가져올 수 있게 합니다.

## 함수 getOrganizationIdsForQuery의 결과가 실제 조직과 뒤바뀌어 나오는 이유
함수 \Exment::user()->getOrganizationIdsForQuery 에서는 실제로 소속된 조직과 뒤바뀐 결과가 나옵니다.  
예를 들어, 다음과 같은 조직 구성이 있다고 합시다.

```
 Ex. (O):Ogganization, (U):User
 
     (O)Company
         (O)develop-team
             (U) Manager
 
             (O) develop-team1
                  (U) User1
                  (U) User2
             (O) develop-team2
                  (U) User3
```

여기서 로그인 사용자가 Manager이고 $filterType이 JoinedOrgFilterType::ONLY_UPPER인 경우, 느낌으로는 (O)develop-team, (O)Company를 가져올 것 같지만,  
**실제로는 (O)develop-team, (O) develop-team1, (O) develop-team2를 가져옵니다.**
  
이것은 이 함수가 어디까지나 공유된 데이터나 권한이 있는 데이터를 가져오는 것을 목적으로 하고, 실제 조직을 가져오는 것을 목적으로 하지 않기 때문입니다.  
예를 들어, "데이터 A는 (O)develop-team1에 공유되어 있다" "데이터 공유는 상위 계층의 조직을 포함한다(JoinedOrgFilterType::ONLY_UPPER)"라는 설정인 경우, Manager는 (O)develop-team, (O) develop-team1, (O) develop-team2에 공유된 데이터를 가져오게 됩니다.  
이 경우 쿼리 처리에서는, Manager가 (O)develop-team, (O) develop-team1, (O) develop-team2에 소속되어 있는 것으로 보고 SQL을 실행합니다.  

그래서 Enum 값의 느낌과 달리, 실제 결과는 뒤바뀌어 나옵니다.


## 플러그인의 로드 처리
보통 PHP 파일을 로드할 때는 autoload를 사용합니다.  
이것은 composer가 만들며, 프로그램 개발자와 이용자가 의식할 일은 거의 없습니다.  
  
그러나 플러그인으로 설치하는 PHP 파일은 autoload를 사용할 수 없습니다.  
Exment의 플러그인 파일은 AWS S3나 FTP 등 외부 서비스에 둘 수 있어서, 플러그인 파일의 실체가 서버에 없는 경우가 있기 때문입니다.  
※이 기능의 자세한 내용은 [여기](/ko/additional_file_saveplace)를 확인해 주십시오  
  
그래서 플러그인의 로드 처리는 특별한 방법으로 하고 있습니다.  
아래는 그 상세입니다.  

### 플러그인 파일 다운로드(플러그인 파일을 외부 서비스에 둔 경우)
플러그인 파일을 외부 서비스에 둔 경우, 다운로드를 합니다.  
다음 판정을 하여, 필요한 경우에만 다운로드합니다.

- 서버의 대상 플러그인 폴더 "/storage/app/plugins/(플러그인 이름)"에 "updated_at.txt" 파일이 있는지 확인합니다  
→없는 경우, 다운로드 필요

- "updated_at.txt" 파일을 열어, 안에 적힌 타임스탬프를 확인합니다

- 데이터베이스의 테이블 "플러그인"의 수정 일시와 비교하여, 일시가 다른지 확인합니다  
→다른 경우, 다운로드 필요

다운로드가 필요한 경우, 외부 서비스에서 플러그인 파일을 다운로드합니다.  
그 뒤, 대상 플러그인 폴더에 "updated_at.txt" 파일을 만들고 타임스탬프를 적습니다.

### 독자 ClassLoader에 디렉터리 추가하기
각 플러그인 파일을 반복하여, 대상 플러그인 폴더와 그 플러그인에 맞는 네임스페이스를 독자 \Exceedone\Exment\Services\ClassLoader에 추가합니다.

### 로드 처리 실행
플러그인의 클래스가 호출되면, spl_autoload_register에 의해 독자 ClassLoader가 호출됩니다.  
이로써, 호출된 클래스의 namespace와 대상 플러그인 폴더를 키로 하여, 맞는 PHP 파일을 require_once합니다.  
이 처리로, 아직 로드되지 않은 클래스라도 동적으로 클래스를 읽어 들여 require_once를 합니다.




## 열 종류 "선택 (테이블에서)" "사용자" "조직"의 필터 설정
사용자 정의 데이터의 입력 화면에서, 열 종류 "선택 (테이블에서)" "사용자" "조직"에 표시되는 선택지는 항상 전부 표시되는 것은 아닙니다.  
아래에 선택지가 좁혀지는 패턴을 적습니다.  
  
※설명을 위한 예로, 다음과 같은 테이블을 가정합니다.  

- 표시하고 있는 테이블: 계약
- 열 종류 "선택 (테이블에서)"로 참조하는 테이블 1: 고객
- 열 종류 "선택 (테이블에서)"로 참조하는 테이블 2: 담당자  
※고객과 담당자 테이블은 1:n 부모-자식 관계의 릴레이션 설정


### 열 종류 "선택 (테이블에서)"의 필터 사례

#### 로그인 사용자의 권한
참조 대상 테이블(고객)에서, 로그인 사용자가 접근할 권한을 가진 데이터만 표시됩니다.  
권한이 없는 데이터는 선택지에 표시되지 않습니다.  

##### 이 설정의 대응 방법
예상한 선택지가 표시되지 않는 경우, 다음 중 하나를 하여 권한을 추가해 주십시오.  

- 선택지에 표시하고 싶은, 참조 대상 테이블(고객)의 데이터를 로그인 사용자에게 공유해 주십시오.  
자세히: [데이터 공유](/ko/data_details)

- 로그인 사용자가 소속된 역할 그룹에, "참조 대상 테이블(고객)"의 "전체 데이터 편집/열람" 권한을 추가해 주십시오.  
자세히: [역할 그룹](/ko/role_group)


#### 열 설정 "조건 뷰"
열 설정 "조건 뷰"가 설정되어 있는 경우, 그 조건 뷰의 필터 조건에 따라 표시되는 선택지가 좁혀집니다.  
※조건 뷰는 참조 대상 테이블(고객)의 데이터를 좁히기 위한 뷰입니다.

##### 이 설정의 대응 방법
예상한 선택지가 표시되지 않는 경우, 다음 중 하나를 해 주십시오.  

- 선택지에 표시하고 싶은, 참조 대상 테이블(고객)의 조건 뷰의 조건을 다시 확인해 주십시오.  
자세히: [조건 뷰](/ko/view)

- 열 설정 "조건 뷰"의 설정을 삭제해 주십시오.


#### 데이터가 100건 이상 있는 경우
참조 대상 테이블(고객)의 데이터가 100건 이상 있는 경우, 처음 표시할 때는 선택지가 표시되지 않습니다.  
검색어를 입력하면, 그 검색어에 맞는 데이터만 선택지로 표시합니다.   
또한 사용자 정의 열 설정 "선택지를 매번 검색"을 YES로 한 경우에는, 데이터 건수와 관계없이 이 방식으로 선택지가 표시됩니다.  


#### 관계 필터 설정
사용자 정의 폼의 설정 화면에 "관계 필터" 설정이 있습니다.  
이것은 부모-자식 관계가 있는 선택지가 같은 폼 안에 있는 경우, 부모 선택지(고객)를 선택하면 자식 선택지(담당자)가 자동으로 좁혀지는 기능입니다.  
자세히: [폼 설정](/ko/form)  
 
이 설정에 따라 다음과 같이 동작합니다.

- 부모(고객)를 선택하지 않은 경우의, 자식(담당자)의 선택지  
→선택지가 1건도 표시되지 않는 상태가 됩니다.

- 부모(고객)를 선택한 경우의, 자식(담당자)의 선택지  
→자식(담당자)의 데이터 가운데, 부모(고객)의 값이 부모 선택지에서 선택한 값으로 되어 있는 데이터를 목록으로 표시합니다.  




### 열 종류 "사용자" "조직"의 필터 사례

#### 현재 표시하고 있는 테이블의, 사용자·조직의 권한
현재 표시하고 있는 테이블(계약)에 접근할 수 있는 사용자·조직만 선택지에 표시됩니다.  
<span class="red">※로그인한 사용자의 권한은 영향을 주지 않습니다.</span>"선택지에 표시할 사용자·조직이, 현재 표시하고 있는 테이블에 권한을 가지고 있는가"가 판정 기준이 됩니다.  

##### 이 설정의 대응 방법
예상한 선택지가 표시되지 않는 경우, 다음 중 하나를 해 주십시오.  

- 역할 그룹 설정에서, "표시하고 있는 테이블(계약)"에 권한이 있는 역할 그룹에 "선택지에 표시하고 싶은 사용자·조직"을 추가해 주십시오.  
자세히: [역할 그룹](/ko/role_group)

- 사용자 정의 열 설정에서, "권한이 없는 사용자·조직도 표시"를 YES로 해 주십시오.  
이 설정을 YES로 하면, "표시하고 있는 테이블(계약)에서 사용자·조직이 권한을 가지고 있는지"의 확인을 하지 않게 됩니다.


#### 외부 포털 사이트용 설정(여러 조직의 사용자가 로그인하는 시스템을 만드는 경우)
데이터 목록 화면이나 편집 화면에서 사용자·조직을 표시할 때, "**로그인 사용자가 소속된 조직과 그 소속 사용자만 표시한다**"는 설정을 하는 경우가 있습니다.  
이 설정이 되어 있을 때 로그인 사용자가 조직·사용자의 선택지를 표시하면, 로그인하는 사용자와 부모-자식 관계에 있는 사용자·조직만 표시합니다.  
자세히: [외부 포털 사이트용 설정](/ko/multiuser)


#### 열 설정 "조건 뷰"
열 설정 "조건 뷰"가 설정되어 있는 경우, 그 조건 뷰의 필터 조건에 따라 표시되는 선택지가 좁혀집니다.  
※조건 뷰는 참조 대상 테이블(사용자)의 데이터를 좁히기 위한 뷰입니다.

##### 이 설정의 대응 방법
예상한 선택지가 표시되지 않는 경우, 다음 중 하나를 해 주십시오.  

- 선택지에 표시하고 싶은, 참조 대상 테이블(사용자)의 조건 뷰의 조건을 다시 확인해 주십시오.  
자세히: [조건 뷰](/ko/view)

- 열 설정 "조건 뷰"의 설정을 삭제해 주십시오.


#### 데이터가 100건 이상 있는 경우
참조 대상 테이블(사용자)의 데이터가 100건 이상 있는 경우, 처음 표시할 때는 선택지가 표시되지 않습니다.  
검색어를 입력하면, 그 검색어에 맞는 데이터만 선택지로 표시합니다.   
또한 사용자 정의 열 설정 "선택지를 매번 검색"을 YES로 한 경우에는, 데이터 건수와 관계없이 이 방식으로 선택지가 표시됩니다.  


#### 관계 필터 설정
사용자 정의 폼의 설정 화면에 "관계 필터" 설정이 있습니다.  
이것은 부모-자식 관계가 있는 선택지가 같은 폼 안에 있는 경우, 부모 선택지(조직)를 선택하면 자식 선택지(사용자)가 자동으로 좁혀지는 기능입니다.  
자세히: [폼 설정](/ko/form)  
 
이 설정에 따라 다음과 같이 동작합니다.

- 부모(조직)를 선택하지 않은 경우의, 자식(사용자)의 선택지  
→선택지가 1건도 표시되지 않는 상태가 됩니다.

- 부모(조직)를 선택한 경우의, 자식(사용자)의 선택지  
→자식(사용자)의 데이터 가운데, 부모(조직)에 소속된 데이터를 목록으로 표시합니다.
