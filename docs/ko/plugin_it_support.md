# IT 지원(공식 플러그인)
"IT 지원"(「ITサポート」)은 IT 지원·헬프데스크를 위한 Exment의 **공식 플러그인**입니다. 고객의 의뢰(메일·접수 폼·전화)와, 모니터링이나 오류 로그에서 찾은 문제를 "티켓"으로 관리하고, **진행 상황을 고객과 로그인 없이 공유**합니다. 무료로 사용할 수 있습니다.

- 소스 코드·설명: [exceedone/exment-plugins(it-support)](https://github.com/exceedone/exment-plugins/tree/main/it-support)
- 라이선스: GPL-3.0(Exment와 같음)
- 플러그인 목록에 나오는 이름: Exment Plugin IT Support（ITサポート）. 내부 이름은 `ExmentITSupport`, URL은 `/plugins/exment_it_support` 입니다.

## 할 수 있는 것
| 분야 | 할 수 있는 것 |
| --- | --- |
| 담당자의 화면 | 전용 **접수함**(접수함의 종류와 건수·티켓 목록·대화와 항목의 3열). 티켓을 바꿔도 페이지를 다시 읽지 않습니다. 키보드 조작(`J`/`K` 위아래·`R` 답장·`N` 사내 메모·`Ctrl+Enter` 보내기·`A` 내가 담당·`E` 해결·`?` 목록), 초안의 자동 저장, 다크 모드, 스마트폰 표시 |
| 접수 | **메일**(IMAP으로 5분마다 수신. ISO-2022-JP·Shift_JIS·첨부 파일 지원), **접수 폼**(로그인 없음·먼저 FAQ를 안내), **전화·방문**(담당자가 등록), **모니터링·오류 로그**(API. 같은 오류는 1건으로 모아 횟수를 셈), **IT 자산의 기한**(유지 보수·라이선스·도메인·인증서의 기한이 가까워지면 자동으로 티켓 등록) |
| 주고받기 | 고객에 대한 답장은 메일로 도착하고, 고객이 그대로 답장하면 같은 티켓에 들어갑니다. 인용 부분은 자동으로 없앱니다. **사내 메모**는 고객에게 보이지 않습니다. **상용구**와 **지식의 후보**를 답장 칸 옆에 냅니다 |
| 이중 대응 방지 | 다른 담당자가 같은 티켓에 답장을 쓰고 있으면 화면에 나옵니다 |
| 고객과의 공유 | **로그인 없는 링크**(그 티켓 1건만 보임·기한과 취소·연 기록). 중요한 티켓은 **확인 코드**(메일로 6자리). 로그인하는 고객은 **고객 포털**(회사의 관리자는 회사의 모든 티켓) |
| SLA | 고객별·우선순위별의, 첫 답장과 해결의 기준. **영업 시간과 공휴일로 세고**, **고객의 답장을 기다리는 동안은 멈춥니다**. 기한이 가깝거나 넘으면 담당자에게 알립니다 |
| 자동화 | 종류별 담당자나 대응 중인 건이 적은 사람에게 자동으로 배정. 답장 대기의 요청 → 자동으로 해결 → 자동으로 완료. 해결하면 만족도(5단계)를 묻습니다 |
| 지식(FAQ) | 공개한 글은 고객의 FAQ 페이지와 접수 폼에 나옵니다. 티켓에서 한 번의 클릭으로 초안을 만들 수 있습니다 |
| IT 자산 | 고객의 PC·서버·라이선스 등을 등록하고 티켓과 연결합니다 |
| 리포트 | 접수·해결·SLA의 달성률·첫 답장까지의 시간·만족도 등. **고객별 작업 시간과 계약 시간의 비교**(월 보고에), CSV |
| 검색 | 제목·본문·주고받은 내용·메일·번호의 부분 일치. 공백으로 AND, 태그는 AND/OR를 고를 수 있습니다 |
| 사용자 정의 | 모두 Exment의 테이블이므로 항목·화면·목록·워크플로·API를 Exment의 화면에서 바꿀 수 있습니다. 티켓의 보드(칸반)도 붙어 있습니다 |

## 동작 요건
- Exment 7.0 이상(PHP 8.2 이상). 추가 PHP 확장은 필요 없습니다.
- 메일 수신에는 접수용 메일함(IMAP)이 필요합니다. 전송은 Exment의 [메일 전송 설정](/ko/mailsend_setting)을 사용합니다.
- 자동 처리(메일 수신·SLA·답장 대기·완료·자산의 기한)는 5분마다 동작합니다. [작업 스케줄](/ko/additional_task_schedule)을 설정해 주십시오.
- 화면은 일본어뿐입니다.

## 설치
1. 플러그인을 설치합니다. Exment v7.2.1 이상은 "기능 관리"에서, 그보다 이전은 zip 업로드입니다. [공식 플러그인](/ko/plugin_official)을 참조하십시오.
2. Exment v7.2.1 이상에서는 "관리자 설정" → "[기능 관리](/ko/feature)"에서 「ITサポート：受付箱」(IT 지원: 접수함)을 켭니다(꺼져 있는 동안은 설정 화면도 열 수 없습니다). 접수함은 사용할 수 있는 역할 그룹을 고를 수 있습니다. 고객 창구(`/support`)·메일 수신·모니터링에서의 티켓 등록을 사용한다면 「ITサポート：お客様の窓口」(IT 지원: 고객 창구)도 켭니다(접수함이 켜져 있을 때만 동작합니다).
   - 새로 설치한 사이트에서는 둘 다 처음에는 꺼져 있습니다. 기능 관리 이전부터 IT 지원을 사용하던 사이트에서는 둘 다 켜진 채로 남습니다.
   - 접수함을 "사용 안 함"으로 하면 메뉴의 「ITサポート」도 사라집니다. 티켓 등의 테이블은 데이터로 남고, Exment의 보통 테이블로서 URL(`/data/its_ticket` 등)이나 "관리자 설정" → "사용자 정의 테이블"에서 열 수 있습니다. 메뉴에 내고 싶을 때는 "관리자 설정" → "메뉴"에서 테이블을 추가해 주십시오. 보이고 싶지 않을 때는 역할 그룹에서 테이블의 권한을 빼 주십시오.
3. 메뉴의 「ITサポート」(또는 `/plugins/exment_it_support`)를 열고 「セットアップする」(설정하기)를 누릅니다. 테이블·메뉴·권한·SLA·종류·상용구·FAQ의 예까지 들어갑니다.
   - 왼쪽 메뉴는 「ITサポート」 하나뿐입니다(열면 접수함). 티켓 표·지식·고객·연락처·IT 자산·상용구는 접수함 위의 메뉴에서, 모든 테이블(티켓의 종류·SLA도)은 「設定」(설정)의 「テーブル・権限」(테이블·권한)에서 엽니다.
   - 1.0.6까지의 「ITサポート」 폴더(접수함과 테이블 8개)는 1.0.7로 올린 뒤 처음 접수함을 열었을 때 하나로 합쳐집니다. 관리자가 직접 추가한 메뉴는 남습니다.
4. 「設定」(설정)에서 접수용 메일함(IMAP)과 창구의 주소를 넣어 저장하고, 「IMAP につながるか試す」(IMAP에 연결되는지 시험)을 누릅니다. 메일 수신을 사용한다면 「差出人の確認」(보낸 사람 확인)과 「受信サーバーの名前」(수신 서버의 이름. 받은 메일의 Authentication-Results의 맨 앞 이름)도 넣습니다. 넣을 때까지는 메일로 온 티켓이 "사칭 의심"이 됩니다.
5. 담당자를 역할 그룹 「ITサポート 担当者」(IT 지원 담당자)에 넣습니다. 로그인하는 고객은 「ITサポート お客様」(IT 지원 고객)에 넣고, 「お客様の担当者」(고객의 담당자)의 「Exment のユーザー」(Exment의 사용자)로 연결합니다.
6. 고객에게는 창구의 URL(`https://당신의 Exment/support`)을 안내합니다.

## 모니터링·오류 로그에서 티켓 등록하기
모니터링 시스템에서 API로 티켓을 만들 수 있습니다. 키는 설정 화면에 있습니다.

~~~sh
curl -X POST https://당신의 Exment/support/intake/alert \
  -H "X-ITS-Key: (설정 화면의 키)" \
  -H "Content-Type: application/json" \
  -d '{"title":"Disk full on web01","source":"web01.example.co.jp","severity":"error","detail":"/var 98%"}'
~~~

| 항목 | 의미 |
| --- | --- |
| `title`(필수) | 제목(`message` 로도 받습니다) |
| `source` | 발생한 곳(`host` 로도 받습니다). 도메인이 고객의 "메일의 도메인"과 맞으면 그 고객의 티켓이 됩니다 |
| `severity` | 우선순위가 됩니다(`level` 로도 받습니다). critical·emergency·alert·fatal은 "긴급", error·high는 "높음", 그 밖은 "보통" |
| `fingerprint` | 같은 오류를 모으는 표시(없으면 발생한 곳과 제목으로 만듭니다) |
| `detail` | 본문 |
| `customer` | 고객 코드 |

원래의 메일을 그대로 보낼 수 있는 구조(Postfix의 파이프 등)에서는 `/support/intake/mail` 에 POST할 수 있습니다(같은 키).

- 모니터링에서 만든 티켓은 처음에는 고객에게 보이지 않습니다.
- 기능 관리에서 「ITサポート：お客様の窓口」(IT 지원: 고객 창구)가 꺼져 있을 때는 `/support/intake/alert` 와 `/support/intake/mail` 은 404가 됩니다.

## 안전을 위한 규칙
- 고객의 링크는 추측할 수 없는 긴 번호이며, 데이터베이스에는 해시만 저장합니다. 링크로 보이는 것은 그 티켓 1건뿐입니다(사내 메모·다른 고객·담당자의 메일 주소는 나오지 않습니다).
- 확인 코드는 10분·5회까지·한 번뿐입니다. 링크마다 코드를 보내는 것은 1시간에 5회까지, 틀리는 것은 하루 10회까지입니다(넘으면 그 링크의 코드는 다음 날까지 사용할 수 없습니다).
- 제목에 티켓 번호를 써도, 의뢰한 사람·CC·같은 회사의 사람이 아니면 그 티켓에는 들어가지 않습니다.
- 보낸 사람 확인은 초깃값(권장)에서는 "수신 서버의 확인(DMARC 또는 From의 도메인에 맞춘 DKIM·SPF)에 합격한 메일만 믿는다"입니다. 확인할 수 없는 메일은 "사칭 의심"으로 받고, Cc를 넣지 않으며, 연락처도 만들지 않습니다. 지금 있는 티켓에 대한 답장이면 고객에게 보이지 않는 사내 메모(태그 「要確認」(확인 필요))가 됩니다. 설정에서 "확인에 떨어진 메일만 의심한다"로도 할 수 있습니다.
- 접수 폼은 접수한 화면에 링크를 내지 않고, 입력된 주소로 메일로 보냅니다. 그 링크를 열 때까지 티켓에 태그 「メール未確認」(메일 미확인)이 붙고, 연락처는 만들지 않습니다.
- 자동 답장·반송 메일·자신의 주소에서 온 메일은 가져오지 않습니다.
- 만족도의 링크는 열기만 해서는 저장하지 않습니다.
- 담당자의 화면을 사용할 수 있는 것은 티켓 테이블을 "모두 편집"할 수 있는 사람(역할 그룹 「ITサポート 担当者」 등)뿐입니다. "자신의 데이터만 편집"으로는 사용할 수 없습니다.

### 로그인 없는 페이지에 대하여
Exment는 안전을 위해 플러그인의 `config.json` 에서는 로그인 없는 페이지를 만들 수 없게 하고 있습니다. 헬프데스크에는 계정이 없는 고객의 입구가 필요하므로, 이 플러그인은 Exment가 시작될 때 `/support/...` 페이지를 직접 등록합니다. Exment의 공개 폼과 같은 생각으로, URL의 비밀이 열 수 있는 것만 보여 줍니다.
