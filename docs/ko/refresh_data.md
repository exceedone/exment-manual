# 사용자 정의 데이터의 리프레시
등록한 사용자 정의 데이터를 명령으로 한꺼번에 삭제하기(리프레시하기) 위한 절차입니다.  
설정(테이블의 정의나 시스템 설정 등)은 남긴 채 데이터만 지웁니다. 다음과 같은 때에 씁니다.

- 환경을 검증한 뒤, 등록한 데이터를 모두 삭제하고 다시 검증하고 싶다.
- 테스트 환경에서 운영 환경으로 옮긴 뒤, 운영 환경의 데이터를 모두 삭제하고 운용을 시작하고 싶다.

명령은 2가지가 있습니다.

| 하고 싶은 일 | 명령 | 볼 곳 |
|---|---|---|
| 모든 사용자 정의 테이블의 데이터를 한꺼번에 삭제한다 | `php artisan exment:refreshdata` | "모든 테이블의 데이터" |
| 지정한 테이블의 데이터만 삭제한다 | `php artisan exment:refreshtable` | "지정한 사용자 정의 테이블의 데이터" |

어느 명령이든 실행하기 전에 데이터를 백업해 두기를 권장합니다.

## 모든 테이블의 데이터
모든 테이블이 대상입니다.  
명령을 실행하면 아래의 "삭제되는 데이터"를 모두 삭제합니다. id의 일련번호도 1부터가 됩니다.


### 삭제되는 데이터(내부 테이블도 포함)
- 액세스 로그
- 이메일 주소의 인증 테이블
- 알림 바의 데이터
- 변경 이력
- 워크플로의 작업 사용자 대상
- 워크플로의 실행 상태
- 사용자 정의 데이터의 공유
- n:n의 관계 데이터(조직-사용자는 제외)
- 사용자 정의 데이터(사용자, 조직, 알림 템플릿은 제외)
- 사용자 정의 데이터의 첨부 파일(사용자, 조직, 알림 템플릿은 제외)

### 삭제되지 않는 데이터
- 시스템 설정
- 사용자 정의 테이블의 설정값
- 워크플로 설정
- 그 밖의 시스템 관련 설정값
- 로그인 정보
- 사용자 정보, 조직 정보, 알림 템플릿의 데이터
- 조직-사용자의 소속 정보

### 실행 방법
- <span class="red bold">※이 명령을 실행하기 전에 데이터의 백업을 실행하기를 권장합니다.</span>
- 다음 명령을 실행하십시오.

~~~
php artisan exment:refreshdata
~~~


## 지정한 사용자 정의 테이블의 데이터
지정한 사용자 정의 테이블이 대상입니다.  
모두를 한꺼번에 삭제하는 것이 아니라, 데이터의 종류에 따라 삭제하는 방법이 달라집니다(아래의 3가지).  
※사용자, 조직, 알림 템플릿의 데이터는 리프레시할 수 없습니다.

### 모두 삭제하고 id 일련번호가 1이 되는 데이터
- 지정한 사용자 정의 테이블 안의 데이터
- 지정한 사용자 정의 테이블이 1:n 관계의 부모 쪽인 경우, 자식 쪽 사용자 정의 테이블 안의 데이터
- 지정한 사용자 정의 테이블이 n:n 관계의 부모 쪽·자식 쪽인 경우, n:n의 관계 데이터 정보. ※관계 대상인 사용자 정의 테이블 안의 데이터 자체는 삭제하지 않습니다.

### 삭제 대상 테이블에 관련된 데이터만 삭제(내부 테이블도 포함)
- 알림 바의 데이터
- 변경 이력
- 워크플로의 작업 사용자 대상
- 워크플로의 실행 상태
- 사용자 정의 데이터의 공유
- 사용자 정의 데이터의 첨부 파일, 댓글

### 값을 비우도록 업데이트
- 삭제 대상 테이블이 다른 사용자 정의 테이블의 사용자 정의 열 "선택 (테이블에서)"에서 쓰이고 있는 경우, 그 사용자 정의 테이블 안의 데이터는 참조 대상의 값이 비도록 한꺼번에 업데이트합니다.


### 실행 방법

- <span class="red bold">※이 명령을 실행하기 전에 데이터의 백업을 실행하기를 권장합니다.</span>
- 다음 명령을 실행하십시오.

~~~
php artisan exment:refreshtable {테이블 이름. 여러 개일 때는 ""로 감싸고 쉼표로 구분}

# 예: 1개의 테이블을 대상으로 실행
php artisan exment:refreshtable information

# 예: 여러 테이블을 대상으로 실행
php artisan exment:refreshtable "table1,table2,table3"
~~~
