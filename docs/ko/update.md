# 업데이트
Exment를 새 버전으로 하는 절차입니다.  
어느 버전에서 무엇이 바뀌었는지는 [릴리스 노트](/release_note)(영어)를 보십시오.

## 업데이트의 흐름
1. **지금의 버전을 확인한다**
2. **백업을 받는다**
3. **업데이트한다**(지금의 버전에 따라 절차가 달라집니다)
4. **업데이트한 뒤에 확인한다**(포함된 공식 플러그인의 새 버전도 확인합니다)

## 1. 지금의 버전을 확인한다
- 화면에서 본다: "시스템 설정" → "시스템 버전 정보" → "현재 버전"
- 파일에서 본다: `composer.lock`의 `exceedone/exment`의 `version`

## 2. 백업을 받는다
업데이트하기 전에 데이터의 백업을 받으십시오. 자세한 내용은 [백업](/ko/backup)을 보십시오.

- 관리자로 Exment에 로그인하고 왼쪽 메뉴의 "관리자 설정" → "백업"을 엽니다.
- 오른쪽 위의 [백업] 버튼을 누릅니다. 데이터와 첨부 파일의 백업이 만들어집니다.
- 만들어진 백업 파일을 눌러 다운로드해 둡니다.

※ 아래의 "업데이트 배치"를 쓸 때는 배치가 자동으로 백업을 받습니다.

## 3. 업데이트한다
### 어느 절차를 쓸지
지금의 버전과 올리고 싶은 버전으로 정해집니다.

| 지금의 버전 | 할 일 |
|---|---|
| **v7.x**(v7 안에서 새롭게 한다) | 아래의 "[일반 업데이트](/ko/update?id=일반-업데이트)"로 올라갑니다 |
| **v6.x 이하** | 먼저 아래의 "[오래된 버전에서 올릴 때](/ko/update?id=오래된-버전에서-올릴-때)"의 절차가 필요합니다 |

- v7.0.x에서 v7.1.0 이상으로 올리면 <span class="red bold">화면 디자인이 "모던"으로 바뀝니다.</span> 이전의 겉모습으로 되돌리려면 [시스템 설정](/ko/system_setting)의 "화면 디자인"에서 "클래식"을 고르십시오.

### 일반 업데이트
방법은 3가지 있습니다. 어느 것이든 하는 일은 같습니다(백업 → 새 프로그램을 받는다 → 데이터베이스를 새롭게 한다).

| 방법 | 맞는 사람 |
|---|---|
| **A. 업데이트 배치(권장)** | 서버에서 파일 하나를 실행하기만 하고 싶다 |
| **B. 명령으로 한다** | 하나씩 직접 실행하고 싶다 |
| **C. 자동 업데이트** | 매일 자동으로 새 버전으로 하고 싶다([자동 업데이트](/ko/update_auto)) |

#### A. 업데이트 배치(권장)
**(1) 배치를 다운로드한다(처음 한 번만)**

Exment를 설치한 폴더(프로젝트의 루트 디렉터리)에 둡니다.

| 서버 | 할 일 |
|---|---|
| Windows | [ExmentUpdateWindows.bat](https://exment.net/downloads/cmd/ExmentUpdateWindows.bat)을 다운로드하여 폴더에 둔다 |
| Linux | 아래의 명령(`ExmentUpdateLinux.sh`) |
| Xserver | 아래의 명령(`ExmentUpdateLinuxXserver.sh`) |
| 사쿠라 인터넷 | 아래의 명령(`ExmentUpdateLinuxSakura.sh`) |
| Mac | [ExmentUpdateLinux.sh](https://exment.net/downloads/cmd/ExmentUpdateLinux.sh)를 다운로드하여 폴더에 두고 `chmod 775 ExmentUpdateLinux.sh`를 실행한다 |

Linux·Xserver·사쿠라 인터넷은 폴더 안에서 다음 명령을 실행합니다(쓰시는 서버의 2행만).

~~~
# Linux
wget https://exment.net/downloads/cmd/ExmentUpdateLinux.sh
chmod 775 ExmentUpdateLinux.sh

# Xserver
wget https://exment.net/downloads/cmd/ExmentUpdateLinuxXserver.sh
chmod 775 ExmentUpdateLinuxXserver.sh

# 사쿠라 인터넷
wget https://exment.net/downloads/cmd/ExmentUpdateLinuxSakura.sh
chmod 775 ExmentUpdateLinuxSakura.sh
~~~

※ 2021년 4월 13일보다 전에 다운로드한 배치를 쓰시는 경우는 새것으로 바꾸십시오.

**(2) 배치를 실행한다**

폴더 안에서 실행합니다.

~~~
# Linux·Mac
sh ExmentUpdateLinux.sh

# Xserver
sh ExmentUpdateLinuxXserver.sh

# 사쿠라 인터넷
sh ExmentUpdateLinuxSakura.sh

# Windows
ExmentUpdateWindows.bat
~~~

배치는 다음 일을 차례로 합니다.

- 데이터의 백업
- 새 프로그램을 받아서 바꿔 넣는다
- 데이터베이스를 새롭게 한다

#### B. 명령으로 한다
먼저 위의 "2. 백업을 받는다"를 하십시오.  
그런 뒤에 폴더 안에서 다음 명령을 실행합니다.

~~~
cd (프로젝트의 루트 디렉터리)
composer update
php artisan exment:update
~~~

- 새 버전이 나온 직후에는 아직 찾지 못할 수 있습니다. 그때는 10~20분 기다린 뒤에 다시 실행하십시오.
- 운영 사이트(`APP_ENV=production`)에서는 데이터베이스를 바꾸기 전에 확인하는 질문이 나옵니다. 화면이 없는 곳(스크립트·cron·CI)에서 실행할 때는 `php artisan exment:update --force`를 쓰십시오.

**임대 서버(Xserver 등)일 때**

- Xserver에서는 `composer update` 대신 `composer update --ignore-platform-reqs`를 실행하십시오. Xserver는 PHP의 Sodium 확장이 처음부터 들어 있지 않기 때문입니다(꼭 넣고 싶을 때는 Xserver의 지원 창구에 문의하십시오).
- SSH에서 쓰는 `php`가 서버의 관리 화면에서 고른 PHP와 다른 버전일 수 있습니다. `php --version`으로 같은 버전인지 확인하십시오. 다를 때는 `~/bin/php`를 그 버전에 링크하거나, `/usr/bin/php8.3 artisan exment:update`처럼 위치를 전부 써서 실행합니다([임대 서버](/ko/install_rental)).

#### C. 자동 업데이트
매일 새 버전이 있는지를 조사하여, 있으면 업데이트 배치를 실행합니다. 설정 방법은 [자동 업데이트](/ko/update_auto)를 보십시오.

- 자동 업데이트로 올라가는 것은 "일반 업데이트"로 올라가는 범위뿐입니다. **v6에서 v7과 같은 큰 버전의 경계는 올라가지 않습니다**. 자세한 내용은 아래의 "[버전 번호와 올라가는 범위](/ko/update?id=버전-번호와-올라가는-범위)"를 보십시오.

### 오래된 버전에서 올릴 때
다음 버전의 경계에는 손으로 하는 절차가 있습니다. 업데이트 배치나 자동 업데이트로는 올라가지 않습니다.  
지금의 버전에서 최신 버전까지 사이에 있는 경계의 페이지를 모두 확인하십시오.

| 버전의 경계 | 절차 페이지 |
|---|---|
| v3.x 이하 → v4.0.x | [v4.0으로 업데이트](/update/v4_0)(영어) |
| v4.3.x 이하 → v4.4.x 이상 | [v4.4로 업데이트](/update/v4_4)(영어) |
| v4.4.x 이하 → v5.0.0 이상 | [v5.0으로 업데이트](/update/v5_0_php8)(영어) |
| v5.0.x 이하 → v6.0.0 이상 | [v6.0으로 업데이트](/update/v6_0_php8)(영어) |
| <span class="red bold">v6.x 이하 → v7.0.0 이상</span> | <span class="red bold">[v7.0으로 업데이트](/update/v7_0_0)(영어)</span>(Laravel의 버전과 관리 화면 라이브러리의 네임스페이스가 바뀝니다) |

- 어느 버전이 언제까지 수정되는지는 [지원 기간](/ko/support_policy)을 보십시오.

## 4. 업데이트한 뒤에 확인한다
- 브라우저에서 **Ctrl+F5**(강력 새로 고침)를 눌러 화면을 다시 읽어 들이십시오.
- "시스템 설정" → "시스템 버전 정보"에서 새 버전이 되어 있는지를 확인합니다.
- 오류가 나왔을 때는 [문제 해결](/ko/troubleshooting)을 보십시오.
- 업데이트한 뒤에 "기능 관리"에서 포함된 공식 플러그인의 새 버전을 확인합니다(아래의 "[업데이트와 포함된 공식 플러그인](/ko/update?id=업데이트와-포함된-공식-플러그인)").

## 업데이트와 포함된 공식 플러그인
Exment v7.2.1부터 무료 공식 플러그인(프로젝트 관리·서포트 데스크·Groupware)이 Exment에 포함되어 있습니다(패키지 exceedone/exment-plugins-release).

`composer update`와 `php artisan exment:update`(업데이트 배치·자동 업데이트도 같음)로 새 Exment와 함께 새 포함 플러그인도 옵니다. **다만 사이트에서 쓰고 있는 플러그인은 자동으로 바뀌지 않습니다.** 플러그인에는 데이터와 설정이 있으므로, 언제 바꿀지는 시스템 관리자가 정합니다.

그래서 업데이트한 뒤의 사이트에는 다음 두 가지가 있습니다.

| | 어디에 있는가 | 바뀌는 때 |
| --- | --- | --- |
| 쓰고 있는 플러그인 | 사이트의 플러그인 폴더와 데이터베이스 | 시스템 관리자가 "기능 관리"에서 바꿨을 때 |
| 포함된 플러그인 | Exment 패키지 안(exceedone/exment-plugins-release) | Exment를 업데이트했을 때 |

### 바꾸는 방법
1. "[기능 관리](/ko/feature?id=무료-공식-플러그인exment에-포함)"를 엽니다. "무료 공식 플러그인(Exment에 포함)" 칸에 포함된 플러그인이 나옵니다.
2. 새 버전이 있을 때는 "새 버전 ○○을(를) 사용할 수 있습니다."라고 나옵니다. "이 버전으로 업데이트"를 누르면 바뀝니다. 설정·메뉴·권한은 남습니다.
3. 바꾸기 전의 버전은 남아 있습니다. 잘 동작하지 않을 때는 "이전 버전(○○)으로 되돌리기"로 되돌릴 수 있습니다.

- 나오는 것은 엑시드원(Exceed One)의 서명을 확인할 수 있었던 공식 플러그인뿐입니다.
- 새 버전에 보안 수정이 들어 있을 때는, 시스템 관리자의 홈 알림과 종 모양의 알림(메일을 보낼 수 있는 사이트에서는 메일도)으로 한 번만 알립니다([보안 수정 알림](/ko/feature?id=보안-수정-알림)).
- 아직 "사용"을 누르지 않은 플러그인은 업데이트해도 설치되지 않습니다.
- 운영자가 버전을 바꾸는 사이트(Exment SaaS 등)에서는 버튼이 나오지 않습니다. 운영자가 바꿉니다.

### 포함된 플러그인의 새 버전이 올 때
- Exment 7.2.x는 패키지 exceedone/exment-plugins-release를 `~7.2.0` 범위에서 씁니다. 그래서 `composer update`를 하면 **Exment에 새 버전이 없을 때도** 7.2.x의 최신 포함 플러그인이 옵니다(예: ExmentPM 1.7.24는 패키지 7.2.22로 옵니다).
- 와도 쓰고 있는 플러그인은 바뀌지 않습니다. 바뀌는 것은 시스템 관리자가 "기능 관리"에서 "이 버전으로 업데이트"를 눌렀을 때뿐입니다.
- exment.net에서 내려받는 zip에는 그 zip을 만든 날의 포함 플러그인이 들어 있습니다. zip은 Exment의 새 버전이 나왔을 때만 다시 만듭니다. zip으로 설치한 사이트에도 다음에 `composer update`를 했을 때 새 포함 플러그인이 옵니다.
- Exment 7.3에도 7.2와 같은 포함 플러그인이 옵니다(공식 플러그인은 7.2와 7.3 모두에서 동작합니다. Exment 7.3은 이 패키지를 `^7.2` 범위에서 씁니다).

## 버전 번호와 올라가는 범위
Exment의 버전 번호는 "메이저 . 마이너 . 패치"(예: v7.1.0)입니다. 어느 숫자가 올라가는지에 따라 업데이트 방법이 달라집니다.

| 종류 | 예 | 내용 | 업데이트 방법 |
|---|---|---|---|
| 패치 | v7.0.2 → v7.0.3 | 결함·취약점의 수정뿐 | 일반 업데이트로 올라갑니다 |
| 마이너 | v7.0.x → v7.1.0 | 새 기능이 들어갑니다. 화면이 조금 바뀔 수 있습니다 | 일반 업데이트로 올라갑니다. 올리기 전에 [릴리스 노트](/release_note)(영어)를 확인하십시오 |
| 메이저 | v6.x → v7.0 | Laravel·PHP의 요건이나 프로그램의 구조가 크게 바뀝니다 | **일반 업데이트로는 올라가지 않습니다**. "오래된 버전에서 올릴 때"의 절차로 올리십시오 |

### 왜 메이저 버전은 자동으로 올라가지 않는가
- 업데이트 배치와 자동 업데이트는 `composer update`를 씁니다. `composer update`는 `composer.json`에 적혀 있는 범위 안에서 가장 새로운 버전으로 합니다.
- 예를 들어 `"exceedone/exment": "^7.0"`이라고 적혀 있으면 v7.x의 최신까지입니다. v8은 되지 않습니다. `"^6.2"`라면 v7이 나와 있어도 v6.x의 최신까지입니다.
- v6을 쓰시는 채로 자동 업데이트를 실행하고 있으면, 자동 업데이트는 "더 새로운 버전(v7)이 있다"고 판단하여 매일 업데이트 배치를 실행합니다(버전은 v6.x의 최신 그대로입니다). v7로 올릴지, 올리지 않는 동안은 자동 업데이트를 멈출지를 검토하십시오.

## 그 밖에
- 개발 중인 버전을 설치한다, 이전 버전으로 되돌린다, 프로그램을 일시적으로 바꿔 넣는다: [개발 버전·과거 버전의 도입](/ko/update_tmp)
