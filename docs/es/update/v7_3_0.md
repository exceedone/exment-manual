# Actualización a v7.3.0
Cómo actualizar de v7.2.x a v7.3.0. Es una actualización dentro de v7, pero <span class="red bold">v7.3 es la única versión a la que no se llega solo con `composer update`.</span>

v7.3 cambia la biblioteca de las pantallas de administración, «exceedone/exment-admin-core», de 1.x a **2.x**. El `composer.json` de los sitios fija admin-core en `^1.0`, así que un simple `composer update` dice «Nothing to install, update or remove» y el sitio sigue en v7.2.x.

| | v7.2.x | v7.3.0 |
| ---- | ---- | ---- |
| PHP | 8.2 o posterior | 8.2 o posterior (sin cambio) |
| exceedone/exment-admin-core | 1.x (`^1.0`) | **2.x (`^2.1.1`)** |
| Biblioteca de códigos QR | simplesoftwareio/simple-qrcode | bacon/bacon-qr-code 3.x |
| Laravel | 12 | 12 (sin cambio) |
| MySQL / MariaDB | 8.0 o posterior / 10.11 o posterior | sin cambio |

Si aparece un error, consulte [Solución de problemas](/es/troubleshooting).

## 1. Hacer una copia de seguridad
<span class="red bold">Haga siempre una copia de seguridad antes de actualizar.</span>

- Copie la base de datos y toda la carpeta de Exment (con `composer.json`, `composer.lock`, `vendor`, `public/vendor`, `.env` y `storage`).
- <span class="red bold">Compruebe con sus propios ojos que el archivo de la copia existe.</span> `php artisan exment:backup` puede terminar sin error aunque mysqldump haya fallado (por ejemplo, con un certificado TLS autofirmado de la base de datos).

## 2. Sitio instalado con composer
En la carpeta donde está instalado Exment (la raíz del proyecto), ejecute en orden:

~~~
# 1. solo si composer.json tiene una línea de simplesoftwareio/simple-qrcode
composer remove simplesoftwareio/simple-qrcode --no-update

# 2. exment y exment-admin-core de 7.3 (se necesita -W)
composer require "exceedone/exment:^7.3" "exceedone/exment-admin-core:^2.1.1" -W

# 3. actualizar la base de datos y lo demás
php artisan exment:update --force
~~~

- **1.** Un sitio instalado desde el zip o el boilerplate de v7.2 tiene `simplesoftwareio/simple-qrcode` en su `composer.json` (v7.3 no lo usa). La actualización funciona aunque quede, pero se recomienda quitar la línea que no se usa.
- **2.** Añada `-W` (`--with-all-dependencies`). Sin él, se detiene con un mensaje como «bacon … fixed to 1.0.2 by a partial update». Instala exment 7.3, exment-admin-core 2.1.1 o posterior y bacon/bacon-qr-code 3.x (y añade dasprid/enum).
    - Si el sitio exige por su cuenta `bacon/bacon-qr-code` 1.x, añada `"bacon/bacon-qr-code:^3"` en la misma línea.
- **3.** `--force` omite la confirmación en un sitio de producción (`APP_ENV=production`).
- Un sitio cuyo `composer.json` no menciona exment-admin-core ni simple-qrcode (solo `exceedone/exment`) se actualiza con un simple `composer update` y `php artisan exment:update`.
- Al final, pulse **Ctrl+F5** (recarga completa) en el navegador.

## 3. Sitio instalado desde el zip, servidor de alquiler
Sustitúyalo por el zip de v7.3.

1. `php artisan down` (modo de mantenimiento).
2. Haga la copia de seguridad de arriba.
3. Cambie el nombre de la carpeta (por ejemplo `exment` → `exment_old`).
4. [Descargue](https://exment.net/download/) el zip de v7.3 y descomprímalo como una carpeta con el nombre anterior.
5. Elimine `storage` de la carpeta nueva y copie **todo `storage`** y **`.env`** de la carpeta anterior.
6. Elimine `bootstrap/cache/*.php` de la carpeta nueva.
7. Ejecute `php artisan exment:update --force`.
8. `php artisan up` (fin del modo de mantenimiento).

| | Qué hacer |
|---|---|
| `.env`, todo `storage` (`app/admin`, `app/plugins`, `app/backup`, `app/templates`, `oauth-*.key`, etc.) | Usar los anteriores tal cual |
| Archivos que puso o cambió en `public`, cambios a mano en `config/*.php`, paquetes que exigió usted con composer (ldaprecord, etc.) | Recuperarlos a mano, mirando la carpeta anterior |
| Su propio código en `app/Exment/bootstrap.php` | Recuperarlo a mano (`exment:update` vuelve a crear el archivo) |
| `vendor`, `composer.json`, `composer.lock`, `public/vendor`, `bootstrap/cache` | Los nuevos (no use los anteriores; `exment:update` vuelve a crear `public/vendor`) |

## 4. Qué cambia en v7.3
### Plugins y código propio: los mensajes se muestran como texto
Con admin-core 2.x, los mensajes de `admin_info()`, `admin_success()`, `admin_warning()`, `admin_error()` (y `*_once()`) y `admin_toastr()` se muestran **como texto, no como HTML**. Un `<` en un nombre o en un texto de error se muestra tal cual, lo que es seguro.

Si un mensaje usa HTML (`<br>`, un enlace, etc.), envuélvalo con `admin_html_message()` y los valores de dentro con `e()` (o `esc_html()`).

~~~php
// hasta v7.2
admin_info('Hecho', $name . ' se creó.<br><a href="' . $url . '">Abrir</a>');

// desde v7.3
admin_info('Hecho', admin_html_message(e($name) . ' se creó.<br><a href="' . e($url) . '">Abrir</a>'));
~~~

Sin ello, `<br>` y similares se muestran como texto (nada deja de funcionar).

### Gestión de funciones
Muchas de las funciones añadidas en v7.3 se activan o desactivan en «Configuración del sistema» → «[Gestión de funciones](/es/feature)». Algunas funciones nuevas empiezan desactivadas.

### Pantallas
En el menú de la izquierda, un elemento con subelementos se abre hacia el lado (la forma anterior se puede elegir en la configuración del sistema). Consulte las [notas de la versión](/release_note).

## 5. Exment SaaS
Exment SaaS lo actualiza su proveedor. No necesita estos pasos.

## 6. Para volver atrás
Vuelva a la copia de seguridad hecha antes de actualizar.

1. Restaure la base de datos desde la copia hecha antes.
2. Recupere `composer.json`, `composer.lock`, `vendor` y `public/vendor` de antes (sitio zip: vuelva a la carpeta anterior renombrada).
3. Elimine el contenido de `bootstrap/cache` y ejecute `php artisan optimize:clear`.

<span class="red bold">No use `php artisan migrate:rollback`.</span> Algunos cambios de la base de datos de v7.3 no tienen vuelta atrás, y quedarían menús y columnas.
