# チューニング
このサイトを速くするための設定を確認します。「設定：システム」→「チューニング」（URL は `/tuning`）で、設定すると Exment が速くなる項目と、今の状態が一覧で出ます。

※この画面は、Exment v7.2.1 以降で使えます。  
※この画面を見られるのは、システム管理者だけです。

![チューニング](img/tuning/tuning1.png)

## 画面の見方
- 項目ごとに、「設定ずみ」か「未設定（設定をおすすめ）」が出ます。「未設定」の項目は、下に出る内容を設定してください。
- ボタンがある項目は、この画面から変えられます。
- データの項目（7.3.0）は、毎晩数えたものを出します。まだ数えていないときや、確かめられないときは「確かめられませんでした」の印（？）が出ます。
- サーバーの設定（php.ini・.env）は、サーバーの管理者に依頼してください。
- 同じ内容は、インストールの画面の「もっと速くするには（任意）」と、`php artisan exment:checkrequire` の「== チューニング（任意） ==」にも出ます。結果は「設定ずみ」か「未設定」だけで、インストールは止めません。

## Exment が自分で入れられる設定（おすすめの設定）
Exment が安全に変えられる設定は、チェックを付けて、この画面から入れられます。このサーバーで要るものだけが出ます。

| 設定 | 内容 |
|---|---|
| Exment のキャッシュ | `.env` に `EXMENT_USE_CACHE=true` |
| 画面の部品 | JS・CSS がそろっていないとき、`exment:publish` で置き直す |
| キャッシュの置き場所 | Redis が使えるとき（PHP から Redis に届くとき）だけ、キャッシュを Redis に |
| セッションの置き場所 | 同じく Redis に（この画面だけ。セットアップでは出しません） |
| ルートのキャッシュを消す | ルートのキャッシュがあれば消す（プラグインの画面が開けなくなるため） |
| 設定のキャッシュを作る | `config:cache`（権限 640）。`.env` を書く設定のあとに作ります |
| 秘密のファイルの権限 | `.env` と設定のキャッシュを 640 に（PHP の利用者が持ち主のときだけ） |

- 「チェックした設定を入れる」を押すと、入れる設定の一覧を確かめてから入れます。入れたことは操作ログに残り、前回の結果（入れた・もう入っていた・失敗とその理由）が下に出ます。
- **セットアップでも選べます**：インストールのあとの初期設定の画面に、同じ設定がチェックの付いた状態で出ます。外したものは入れません。

  ![セットアップのおすすめの設定](img/tuning/tuning_setup.png)

- php.ini・PHP-FPM・OPcache・cron・キューは変えません。下の項目を見て、サーバーの管理者が設定してください。
- `.env` に `EXMENT_TUNING_SERVER_ACTIONS=false` があると、この欄もセットアップでの設定も出ません。

## 項目
### OPcache
PHP のプログラムをコンパイルした結果をメモリにとっておきます。Exment はファイルが多いので、メモリとファイル数の上限も大きくします（メモリ 128MB 以上、ファイル数 20,000 以上で「設定ずみ」）。

php.ini を次のように設定し、PHP（PHP-FPM・Web サーバー）を再起動してください。

~~~ini
opcache.enable=1
opcache.memory_consumption=256
opcache.interned_strings_buffer=16
opcache.max_accelerated_files=20000
opcache.revalidate_freq=60
~~~

### PHP のバージョン
新しい PHP ほど速く動きます。PHP 8.2 のセキュリティのサポートは 2026-12-31 までです。PHP 8.3 以上へのバージョンアップをおすすめします。

### デバッグモード（APP_DEBUG）
デバッグモードでは、リクエストごとに詳しい情報を集め、エラーの詳細を画面に出します。本番では OFF にします。

~~~
# .env
APP_DEBUG=false
~~~

### 設定のキャッシュ（config:cache）
設定ファイルを 1 つにまとめ、リクエストごとの読み込みを減らします。画面の「設定のキャッシュを作る」「設定のキャッシュを消す」のボタンか、次のコマンドで作れます。

~~~
php artisan config:cache
~~~

- `.env` を手で書きかえたときは、もう一度作ってください（作り直すまで、書きかえが効きません）。
- Exment が `.env` を書きかえたとき（インストール・リストアなど）は、キャッシュを自動で消します。
- `bootstrap/cache/config.php` には、`.env` の秘密（データベースのパスワード・`APP_KEY` など）が入ります。1 つのサーバーで、サイトごとに別の OS のユーザーで動かしているとき（マルチテナント）は、ほかのサイトから読めないように、作ったあと権限を 640 にしてください（umask 027 で動かす）。
- ルートのキャッシュ（`route:cache`）は使いません。プラグインのルートをデータベースから作っているため、プラグインの画面が開けなくなります。

### クラスの読み込みの最適化（composer）
composer でクラスの一覧を作っておくと、PHP がクラスのファイルを探す時間が減ります。

~~~
composer install --optimize-autoloader --no-dev
~~~

### Exment のキャッシュ（EXMENT_USE_CACHE）
テーブル・列・設定などの定義をキャッシュに入れ、リクエストごとにデータベースから読まないようにします。

~~~
# .env
EXMENT_USE_CACHE=true
~~~

### キャッシュ・セッションの置き場所
キャッシュとセッションを Redis などに置くと、ファイルより速くなります。Web サーバーが複数台のときは必要です。Redis が使えるときは、次のように設定します（任意）。

~~~
# .env (Redis)
CACHE_STORE=redis
SESSION_DRIVER=redis
~~~

### キュー（メールなどの裏の処理）
キューが `sync` のときは、メールの送信などを画面の処理の中で行うため、終わるまで画面が待たされます。次のように設定し、キューのワーカーを動かしてください（supervisor・systemd など）。

~~~
# .env
QUEUE_CONNECTION=database
# ワーカーを動かし続ける
php artisan queue:work --tries=3
~~~

### ダッシュボードの集計のキャッシュ（EXMENT_DASHBOARD_CACHE_SECONDS）
集計ビューのグラフは、ダッシュボードを開くたびにテーブルを集計します。結果を決めた秒数だけ、見る人ごとに残し、そのあいだは集計しなおしません。初期値は `0`（使わない）です。

~~~
# .env（秒）
EXMENT_DASHBOARD_CACHE_SECONDS=60
~~~

- データを保存・削除したときは、集計しなおします。
- 共有や所属の変更などは、残す時間が過ぎてから表に出ます。

### 調査用のログ
システムパフォーマンスログと、`.env` のデバッグモード（`EXMENT_DEBUG_MODE_REQUEST`・`EXMENT_DEBUG_MODE_SQL`・`EXMENT_DEBUG_MODE_SQLFUNCTION`・`EXMENT_DEBUG_MODE_SQLFUNCTION1`・`EXMENT_DEBUG_MODE_SCHEDULE`）は、リクエストごとにログを書きます。調査が終わったら OFF にします。システムパフォーマンスログは、「システムパフォーマンスログを OFF にする」のボタンで止められます。

### 検索インデックス
1 万件より多いテーブルで、よく絞り込み・並べ替えに使う列に「検索インデックス」を付けると、一覧・検索・集計が速くなります。[カスタム列](/ja/column)の設定で、よく使う列に「検索インデックス」を付けてください。

### 決まった時間の処理（schedule:run・cron）
通知・スケジュール・バッチなどは、cron が毎分動かす `schedule:run` で行います。毎分 PHP と Exment を起動するので、重い処理があると画面の処理の CPU が減ります。最後に動いた時刻と、1 分あたりの最長の時間が出ます。cron が動いていないときや、重いタスクがあるときに知らせます。

### PHP-FPM のプロセス
`pm = ondemand` で待ち時間（`pm.process_idle_timeout`）が短いと、しばらく使われなかったあとの 1 回目が、プロセスを起こす分だけ遅くなります。`pm.max_children` は、サーバーのメモリに合わせます。

### ルートのキャッシュ（route:cache）
Exment は、プラグインの画面のルートをリクエストごとにデータベースから足します。ルートのキャッシュがあると、あとから入れたプラグインの画面が開けません。**ないのが正しい状態**です。

### 秘密のファイルの権限（.env・設定のキャッシュ）
`.env` と設定のキャッシュ（`bootstrap/cache/config.php`）には、パスワードや APP_KEY が入っています。サーバーのほかの利用者が読めないよう、640 などにします（上の「Exment が自分で入れられる設定」でも直せます）。

### 画面の部品（JS・CSS）
ログイン画面などが読み込む JS・CSS がそろっているか、ブラウザーが覚えておける設定（Cache-Control・Expires）かを確かめます。URL には版（`?v=`）が付くので、長く覚えさせても大丈夫です。

### 遅いクエリーのログ（DB）
MySQL・MariaDB の slow query log を ON にすると、時間がかかったクエリーが記録され、遅い原因を探せます。

### 検索インデックスの索引（DB）
「検索インデックス」を付けた列には、データの表に専用の列と索引があります。リストアや変更の失敗で索引がないと、絞り込み・並べ替えのたびに全件を読みます。索引がそろっているかを確かめます。

## データの項目（7.3.0）
Exment 7.3.0 から、サーバーの設定のほかに、データの側の問題も出ます。

- データの数は、**毎晩 4:30 にまとめて数えて**覚えておきます（`php artisan exment:tuning-data`）。画面を開くたびには数えません。「決まった時間の処理」の画面の「今すぐ実行」でも数えられます。
- 結果には、数えた時刻が出ます。まだ一度も数えていないときは「まだ数えていません」と出ます。
- **見るだけです。** Exment が自分でデータや設定を変えることはありません。検索インデックスをつけるのは、管理者がボタンを押したときだけです。

| 項目 | 出すもの | おすすめが出るとき | 直し方 |
| ---- | ---- | ---- | ---- |
| データの量（テーブル） | 件数の多いテーブルの上位 5 つ。MySQL・MariaDB では、データと索引の大きさも | 前に数えたときから 2 倍以上・5 万件以上ふえたテーブルがある | 取り込みや自動の処理がくり返し動いていないか確かめる |
| 変更の履歴 | 変更の履歴が 100 万件を超えたテーブル | そのようなテーブルがある | [テーブル](/ja/table)の設定の「変更履歴バージョン数」を小さくする（データを保存したときに、そのデータの古い履歴から消えます） |
| 削除したデータ | 削除したデータ（ゴミ箱）が 1 万件以上で、テーブルの 2 割以上のテーブル | 「削除してから完全に削除するまでの日数」を決めていない | テーブルの設定で日数を決めると、毎晩、古いものから完全に削除します（アーカイブに残します） |
| 添付ファイル | 添付ファイルの数と合計の大きさ（新しい 5,000 件まで）。どのデータにもつながっていないファイルの数 | データを完全に削除したあとに残った、つながっていないファイルがある | 画面からは見えず、ディスクだけを使っています |
| データベースの設定（MySQL・MariaDB） | `innodb_buffer_pool_size` と、データと索引の合計 | `innodb_buffer_pool_size` が、データと索引の合計より小さい | MySQL の設定ファイルに、出てくる値を書いて再起動する（サーバーのメモリーの 50〜70% まで）。ほかのデータベースや、設定を読めないときは「確かめられませんでした」 |
| 検索インデックスのない列 | 1 万件以上のテーブルで、ビューの絞り込み・並べ替え・集計のグループに使っている列と、参照の列（選択・ユーザー・組織）のうち、検索インデックスがないもの | そのような列がある | 列を選んで「選んだ列に検索インデックスをつける（裏の処理）」を押すか、[カスタム列](/ja/column)の設定でつける |
| 重いビュー | 1 万件以上のテーブルのビューで、検索インデックスのない列で絞り込み・並べ替え・グループ分けをするものと、子のテーブルを集計するもの | そのようなビューがある | 使っている列に検索インデックスをつけるか、[ビュー](/ja/view)の条件を見直す |

### 検索インデックスを画面からつける
- 「検索インデックスのない列」で列を選んでボタンを押すと、**裏の処理で**つけます。件数が多いテーブルでは、時間がかかります。
- キューのワーカーがあるときはワーカーで、ないときは画面の応答を返したあとに動きます。つけているあいだは「つけているところ」と出ます。
- 1 つのテーブルにつけられる検索インデックスの数（標準は 20）を超えるときは、選べません。
- ボタンを押したことは操作ログに、つけたことはアプリのログに残ります。

### ログの大きさ（7.3.0）
データベースのログが大きいとき、ログ用のデータベースをまだ決めていなければ、`EXMENT_LOG_DB_CONNECTION` と `php artisan exment:log-db --copy` で、ログを別のデータベースに置くこともすすめます。

## そのほかの速さに関わる設定
### 一覧ビューのグラフ（EXMENT_CHART_LIST_MAX_ROWS）
一覧ビューのグラフは、1 行に 1 つの点を描きます。初期値（`0`）では、すべての行を読みます。大きなテーブルでメモリや時間が足りないときは、`.env` で上限を決められます（例: 1000）。上限を超えたときは「集計ビューのチャートにしてください」と出ます。大きなテーブルのグラフは、集計ビューで作ってください。

~~~
# .env（上限を決めるとき）
EXMENT_CHART_LIST_MAX_ROWS=1000
~~~

## 画面のボタンを出さない（EXMENT_TUNING_SERVER_ACTIONS）
1 つのサーバーで複数のサイトがコードを共有しているとき（マルチテナントなど）は、`.env` に次のように書くと、サーバー全体を変えるボタン（設定のキャッシュを作る・消す）を出しません。画面には「このサーバーでは、画面から変えられません（サーバーの管理者が設定します）。」と出ます。

~~~
# .env
EXMENT_TUNING_SERVER_ACTIONS=false
~~~

## 画面を隠す
- チューニングは「[機能の管理](/ja/feature)」の機能の 1 つで、はじめから「使う」です。サイトのシステム管理者は、機能の管理で「使わない」にできます。
- サーバーの側（SaaS など）で隠すときは、`.env` に `EXMENT_FEATURES_LOCKED=tuning` を書きます（ほかの機能と一緒に止めるときは、カンマで区切ります）。画面は 404 になり、メニューにも出ません。
