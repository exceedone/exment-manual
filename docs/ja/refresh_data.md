# カスタムデータのリフレッシュ
登録したカスタムデータを、コマンドでまとめて削除する（リフレッシュする）ための手順です。  
設定（テーブルの定義やシステム設定など）は残したまま、データだけを消します。次のようなときに使います。

- 環境の検証のあと、登録したデータをすべて削除して、もう一度検証したい。
- テスト環境から本番環境へ移したあと、本番環境のデータをすべて削除して、運用を始めたい。

コマンドは 2 つあります。

| したいこと | コマンド | 見るところ |
|---|---|---|
| すべてのカスタムテーブルのデータを、一括で削除する | `php artisan exment:refreshdata` | 「全テーブルのデータ」 |
| 指定したテーブルのデータだけを削除する | `php artisan exment:refreshtable` | 「指定のカスタムテーブルのデータ」 |

どちらのコマンドも、実行する前に、データのバックアップを取ることをおすすめします。

## 全テーブルのデータ
すべてのテーブルが対象です。  
コマンドを実行すると、下の「削除されるデータ」をすべて削除します。id の連番も 1 からになります。


### 削除されるデータ(内部テーブルも含む)
- アクセスログ
- Eメールアドレスの認証テーブル
- 通知バーのデータ
- 更新履歴
- ワークフローの作業ユーザー対象
- ワークフローの実行ステータス
- カスタムデータの共有
- n:nのリレーションデータ(組織-ユーザーを除く)
- カスタムデータ（ユーザー、組織、通知テンプレートを除く）
- カスタムデータの添付ファイル（ユーザー、組織、通知テンプレートを除く）

### 削除されないデータ
- システム設定
- カスタムテーブルの設定値
- ワークフロー設定
- その他のシステム関連設定値
- ログイン情報
- ユーザー情報、組織情報、通知テンプレートのデータ
- 組織-ユーザーの所属情報

### 実行方法
- <span class="red bold">※このコマンドを実行する前に、データのバックアップを実行することをおすすめします。</span>
- 次のコマンドを実行してください。

~~~
php artisan exment:refreshdata
~~~


## 指定のカスタムテーブルのデータ
指定したカスタムテーブルが対象です。  
すべてを一括で削除するのではなく、データの種類によって、削除のしかたが変わります（下の 3 つ）。  
※ユーザー、組織、通知テンプレートのデータは、リフレッシュできません。

### すべて削除し、id連番が1になるデータ
- 指定したカスタムテーブル内のデータ
- 指定したカスタムテーブルが、1:n のリレーションの親側になっている場合、子側のカスタムテーブル内のデータ
- 指定したカスタムテーブルが、n:n のリレーションの親側・子側になっている場合、n:n のリレーションデータ情報。※リレーション先のカスタムテーブル内のデータそのものは、削除しません。

### 削除対象のテーブルに関連するデータのみ削除(内部テーブルも含む)
- 通知バーのデータ
- 更新履歴
- ワークフローの作業ユーザー対象
- ワークフローの実行ステータス
- カスタムデータの共有
- カスタムデータの添付ファイル、コメント

### 値を空にするように更新
- 削除対象のテーブルが、ほかのカスタムテーブルのカスタム列「選択肢 (他のテーブルの値一覧から選択)」で使われている場合、そのカスタムテーブル内のデータは、参照先の値が空になるように、一括で更新します。


### 実行方法

- <span class="red bold">※このコマンドを実行する前に、データのバックアップを実行することをおすすめします。</span>
- 次のコマンドを実行してください。

~~~
php artisan exment:refreshtable {テーブル名。複数の場合は""で囲んでカンマ区切り}

# 例：1つのテーブルを対象に実行
php artisan exment:refreshtable information

# 例：複数のテーブルを対象に実行
php artisan exment:refreshtable "table1,table2,table3"
~~~
