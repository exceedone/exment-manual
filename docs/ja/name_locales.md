# 名前を言語ごとに持つ（v7.3.0 以降）
v7.3.0 から、テーブル・列・ビュー・メニューの名前を、言語ごとに持てます。  
サイトの言語の名前が、いままでどおりの名前です。ほかの言語の名前は、入力しなくてもかまいません。

## 入力する場所
次の設定画面に「ほかの言語の名前」の欄があります。

- テーブル設定（カスタムテーブル）
- 列設定（カスタム列）
- ビュー設定（カスタムビュー）
- メニューの編集画面（メニュー →［編集］）

ユーザーが選べる言語ごとに 1 つずつ入力欄が出ます。サイトの言語の欄はありません。  
空のときは、いままでの名前が表示されます。  
※メニュー一覧の追加フォームには、この欄はありません。名前は、メニューの編集画面で入力してください。

## だれに、どの名前が見えるか
ユーザー設定の「言語」（v7.2.4 以降）を選んでいる人には、その言語の名前が表示されます。  
表示されるのは、データの画面・メニュー・一覧・フォーム・ダッシュボードです。  
その言語の名前がないときは、いままでの名前が表示されます。

## いままでの名前が使われる場所
次の場所では、言語に関係なく、いままでの名前を使います。

- 設定の画面（テーブル設定・列設定・ビュー設定など）
- テンプレートの書き出しと取り込み
- API と MCP
- データのインポート・エクスポート（CSV・Excel）

そのため、ほかの言語のユーザーが設定を保存しても、いままでの名前は変わりません。  
API と MCP では、ほかの言語の名前を読み取り専用の `name_locales` でも返します。例：`{"en":"..."}`

## メニューの名前
- そのメニュー自身に言語ごとの名前があれば、それが表示されます。
- テーブルのメニューで、名前がまだテーブルの名前のままのときは、そのテーブルの言語ごとの名前に合わせて表示されます。
- インストール用テンプレートのメニューは、テンプレートの翻訳（v7.2.6）に合わせて表示されます。
- 手で変えた名前は、そのまま表示されます。

## テンプレート
`lang/<ロケール>/lang.json` を持つテンプレートを取り込むと、テーブル・列・ビューについて、そのテンプレートにあるすべての言語の名前が入ります。取り込みをした人の言語だけではありません。

## まだ対応していないもの
次は、あとのバージョンで対応する予定です。

- フォーム、フォームのブロック
- ダッシュボード、ダッシュボードのボックス

通知やメールのテンプレートは、対象外です。
