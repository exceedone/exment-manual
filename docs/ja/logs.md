# ログ
Exmentの各種ログについて記載します。


## ログ種類
現在Exmentでは、以下のログ種類があります。

- **操作ログ**  
各ユーザーが画面で操作した内容を、Web画面で一覧表示します。  

- **ログファイル出力**  
主にエラーが発生した場合に、サーバー上にログファイルを出力します。  


## 操作ログ  
各ユーザーが画面で操作した内容を、Web画面で一覧表示します。  
操作した内容とは、主に以下があります。  

- ユーザーが画面を表示、データを新規追加、更新、削除など
- APIの認証、実行


### 確認方法
- システム管理者が、以下のURLを入力します。  
http(s)://(ExmentのURL)/admin/auth/logs  

- もしくは、メニューに「APIアプリ設定」を追加します。  
「管理者設定」 > 「メニュー」ページを開き、メニュー種類「システムメニュー」を選択すると、対象の「操作ログ」が表示されますので、選択し、保存を行ってください。  
※「操作ログ」は、デフォルトの設定ではメニューに表示されていません。

- 操作ログの一覧画面が表示されます。

![データ画面](img/logs/auth_logs1.png)  

- データの詳細を表示したい場合は、該当行をクリックしてください。  

![データ画面](img/logs/auth_logs2.png)  

### 各項目について

- ##### ユーザー名  
操作した該当のユーザーです。※未ログイン状態での操作の場合、未記入になります。

- ##### メソッド
HTTPリクエストのメソッドの種類です。

- ##### パス
HTTPリクエストの対象URIです。  
※GETメソッドで、クエリ文字列が含まれていた場合でも、この項目には出力されず、代わりに「入力・クエリ」が表示されます。

- ##### IPアドレス
操作を実施した端末のIPアドレスです。

- ##### 入力・クエリ
HTTPリクエストのクエリ文字列、もしくはPOST値です。  

- ##### 作成日時
操作を実施した日時です。


### その他
- 項目「入力・クエリ」について、以下の値は、機密情報につき、文字列"***"に置き換えて保存しています。
    - password
    - password_confirmation
    - current_password
    - _token
    - verify_code
    - access_token
    - refresh_token


### 機密情報のマスキング

操作ログには、ユーザーが入力したリクエスト値や、APIから送信されたリクエスト値、およびURLパスパラメータが記録される場合があります。

認証情報などの機密情報が平文で保存されることを防ぐため、Exmentは操作ログの記録時に、設定されたリクエスト項目およびURLパス値をマスクします。

マスキングの設定は、以下のファイルの`operation_log`セクションで変更できます。

`config/exment.php`

以下はマスキング設定の構成例です。

```php
'operation_log' => [
    'mask_columns' => [
        'client_secret',
    ],

    'mask_columns_by_uri' => [
        'oauth/*' => ['client_id'],
    ],

    'mask_path_prefixes' => [
        'auth/reset' => false,
    ],
],
```

#### mask_columns

- リクエストURIに関係なく、常にマスクするリクエスト項目名を指定します。
- APIキーやクライアントシークレットなど、常に機密情報として扱う値に使用してください。
- ここで指定した項目名がユーザー定義テーブルの通常の業務データ項目として使用されている場合でも、その値はマスクされます。

#### mask_columns_by_uri

- 特定の画面またはAPIのみでマスクするリクエスト項目名を指定します。
- 配列のキーには、`admin`プレフィックスからの相対URIパターンを指定します。ワイルドカード`*`が使用できます。
- `id`、`secret`、`client_id`、`api_key`、`token`のように、他の画面では通常の業務データとして使用される可能性がある項目名に使用してください。
- 一致した項目は、ネストされたリクエスト構造内の値も含めて再帰的にマスクされます。

#### mask_path_prefixes

- `admin`プレフィックスからの相対URIプレフィックスを指定し、その直後のパスセグメントに機密情報が含まれる場合にマスクします。
- 配列の値によってマスク方法を指定します。
    - `true`: 先頭8文字（十分な長さがある場合）のみを保持し、残りを`***`に置き換えます。追跡が必要なレコードIDなどに使用します。
    - `false`: 値全体を`***`に置き換えます。パスワードリセットトークンなど、完全に秘匿すべき値に使用します。
- 例えば、`auth/reset`を`false`に設定した場合、URLに含まれるパスワードリセットトークン全体が`***`に置き換えられます。

#### 注意事項

- マスキングは、新しく作成される操作ログに適用されます。
- アップグレード時に操作ログのパッチ処理を実行した場合、既存の操作ログも設定内容に従ってマスクされます。
- Exmentのアップグレード時には、`operation_log`の設定を確認し、必要に応じて新しいマスク対象を追加してください。
- 常に機密情報となる値には`mask_columns`を使用してください。特定の画面やAPIのみで機密情報となる値には、通常の業務データを誤ってマスクしないよう、`mask_columns_by_uri`または`mask_path_prefixes`を使用してください。


### 操作ログ自動削除
操作ログ画面の下部で、操作ログを自動削除する設定を行うことができます。
![操作ログ自動削除設定](img/logs/auth_logs3.png)  

#### 自動削除を有効にする
- 操作ログの自動削除を有効または無効にします。
- 有効にすると、設定された保存期間より古いログは自動的に削除されます。
- 無効にすると、ログは自動削除されません。
- デフォルト値は「Yes」です。


#### ログ保存期間（日数）
- 操作ログを保存する日数を指定します。
- 指定した日数より古いログは自動的に削除されます。
- 1以上の値を入力してください。
- この設定は「自動削除を有効にする」が有効な場合にのみ表示されます。
- デフォルト値は「180」です。


#### 実行曜日
- 自動削除を実行する曜日を指定します。
- 未選択の場合、曜日を問わず実行します。
- プレースホルダーは「すべて」です。


#### 実行月
- 自動削除を実行する月を指定します。
- 未選択の場合、月を問わず実行します。
- プレースホルダーは「すべて」です。


#### 実行日
- 自動削除を実行する日を指定します。
- 未選択の場合、日に関係なく実行します。
- 実行曜日と実行日の両方を指定した場合は、両方の条件を満たす日時に実行します。
- プレースホルダーは「すべて」です。


#### 実行時間（時）
- 自動削除を実行する時刻（時）を指定します。
- 未選択の場合、時間を問わず実行します。
- プレースホルダーは「すべて」です。


#### 実行時間（分）
- 自動削除を実行する時刻（分）を指定します。
- 未選択の場合、分を問わず実行します。
- プレースホルダーは「すべて」です。


#### 自動削除を無効にするには
1. 「自動削除を有効にする」を「No」に設定します。
2. 「保存」をクリックします。

保存後、自動削除が無効になります。


### 操作ログの古いデータ削除
古くなった操作ログを削除するには、プラグイン(バッチ)を使用します。  
一定の日付(既定だと14日)より古くなった操作ログを物理削除します。  
以下のリンクより、プラグイン(バッチ)を導入してください。  
[プラグイン-操作ログ 古いログ削除](https://github.com/exment-git/plugin-sample/tree/main/batch/OperationLogDelete)




## ログファイル出力  
主にエラーが発生した場合に、サーバー上にログファイルを出力します。  
※後述の設定を追加することによって、エラー以外の値を出力こともできます。

### 確認方法
- Exmentを構築しているサーバーで、以下のパスにアクセスします。  
(Exmentのルートフォルダ)/storage/logs  

- laravel.logファイルをご確認ください。

### 設定値追加
- [設定値](/ja/config)を変更することによって、以下の内容も出力することができます。※設定手順は、[こちら](/ja/config)をご確認ください。

- ##### リクエスト値出力
    - 設定キー : EXMENT_DEBUG_MODE_REQUEST
    - 既定値 ： false
    - 役割 : trueにすることで、ExmentのWebサービスへのリクエスト値をログ出力します。  

- ##### SQLログ出力
    - 設定キー : EXMENT_DEBUG_MODE_SQL
    - 既定値 ： false
    - 役割 : trueにすることで、ExmentでSQLを実行時、SQL文をログ出力することができます。

- ##### SQLログ出力 - 関数表示
    - 設定キー : EXMENT_DEBUG_MODE_SQLFUNCTION
    - 既定値 ： false
    - 役割 : ExmentでSQLを実行時で、「EXMENT_DEBUG_MODE_SQL」がtrueのときに、trueにすることで、SQL文と同時に、呼び出し元の関数一覧をログ出力することができます。

### その他
- Laravelでは、ログファイルのサーバー出力以外にも、以下のような機能があります。
    - Slackなど、他の場所にログを出力する
    - ログのフォーマットを変更する
    - ログの出力ファイルを毎日切り替える

- これらの設定は、[こちらのマニュアル](https://readouble.com/laravel/6.x/ja/logging.html)に従い、設定を行ってください。
