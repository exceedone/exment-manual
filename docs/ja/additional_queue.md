# (上級者向け)通知処理の遅延実行
通知を送る処理を、画面の操作とは別に、あとから実行するための設定です。  
Exment は、ふつうはすべての処理をその場で実行します（同期実行）。この設定をすると、一部の処理を、あとから実行できます（遅延実行・キュー実行）。画面の待ち時間が短くなります。

いま、あとから実行できるのは、次の処理です。

- メール送信
- Slack送信
- Microsoft Teams送信
- Webhook（JSON）送信（v7.3.0 以降）
- データを保存したときの通知の、送る相手を探して送る処理（v7.3.0 以降。[通知を送るとき](#通知を送るとき)）

## 注意点
- 遅延実行では、処理（ジョブ）を「キュー」という順番待ちの場所にためておき、画面とは別のプロセスで実行します。
- ためたジョブを実行するには、コマンドで「キューワーカ」（ジョブを実行するプログラム）を動かします。ワーカは、動かし続ける必要があります。**ワーカが止まると、処理は実行されません**。  
ワーカが動いているかを監視するなど、十分にご注意ください。
- 画面から通知を実行した時点では、通知が成功したか失敗したかが分かりません。  
そのため、実際には通知が失敗していても、「通知が実行されました！」というメッセージが出ることがあります。
- キューのくわしい説明は、[Laravelマニュアル](https://readouble.com/laravel/12.x/ja/queues.html)をご覧ください。


## 設定手順
キュードライバー（ジョブをためる場所）を設定します。ここでは、データベースを使います。（設定によって、Redis なども使えます）

**(1) .env を開き、次の設定を書きます。**

```
#キュードライバー。Exmentのインストール手順で設定する値はsync(同期処理)
QUEUE_CONNECTION=database
```

**(2) 次のコマンドを実行します。** キューの情報を入れるテーブルを作ります。

```
php artisan queue:table
php artisan queue:failed-table
php artisan exment:update
```

> 「jobs」「failed_jobs」テーブルは、Laravel のプロジェクトを作ったときのマイグレーションで、すでに作られることがあります。「database/migrations」フォルダを見て、次のとおり実行してください。
>
> | 「database/migrations」フォルダの中 | 実行するコマンド |
> | ---- | ---- |
> | 「create_jobs_table」を含むファイルがある(Laravel 11以降で作成したプロジェクト) | 「php artisan exment:update」だけ（両方のテーブルは標準のマイグレーションで作られるので、「queue:table」「queue:failed-table」は実行しません） |
> | 「create_failed_jobs_table」を含むファイルだけがある | 「queue:table」と「php artisan exment:update」 |
> | どちらもない | 上の 3 つのコマンドをすべて |
>
> 「Migration already exists.」と出たときは、そのマイグレーションがすでにあります。エラーは気にせず、次のコマンドへ進んでください。

**(3) 次のコマンドを実行します。** ワーカが動きはじめます。  
このコマンドは、自分で止めるか、ターミナルを閉じるまで、動き続けます。

```
php artisan queue:listen
```

> queue:listen をバックグラウンドでずっと動かし続けるには、[Supervisor](https://readouble.com/laravel/12.x/ja/queues.html#supervisor-configuration)のようなプロセスモニタ（ワーカが止まっていないかを見張るしくみ）が必要です。

### ワーカーを動かし続けられないとき（レンタルサーバーなど）
レンタルサーバーなどで、ワーカーを動かし続けられないときは、cron で毎分、たまったジョブを片付けます（`--stop-when-empty` でジョブがなくなったら終わり、`--max-time=50` で次の cron までに終わります）。php は、Web と同じ版をフルパスで書いてください。

```
* * * * * cd /(Exmentのルートディレクトリ) && nice -n 15 /usr/bin/php8.3 artisan queue:work --stop-when-empty --max-time=50 >> /dev/null 2>&1
```

それもできないときは、`QUEUE_CONNECTION=sync`（インストールしたときの値）のままにしてください。

## 通知を送るとき
※この設定は、Exment v7.3.0 以降で使えます。

データを保存したときの通知（作成・更新・コメント・添付ファイル）は、保存の画面の答えを待たせずに、あとから送ります。通知を受ける人が多いときも、保存は速く終わります。送る相手と中身は、前と同じです。  
いつ送るかは、.env の `EXMENT_NOTIFY_MODE` で決めます。

| EXMENT_NOTIFY_MODE | いつ送るか |
|---|---|
| 書かない（auto） | `QUEUE_CONNECTION` が sync でなければ queue、sync なら after_response（画面の操作）・sync（コマンド） |
| queue | キューのワーカーが送ります |
| after_response | 同じ PHP のプロセスが、画面に答えを返したあとで送ります |
| sync | 保存の中で送ります（v7.2 までと同じ） |

- **`QUEUE_CONNECTION` を sync 以外にしたら、ワーカーを必ず動かしてください**（[設定手順](#設定手順)）。ワーカーが止まっていると、保存の通知も、メール・Slack・Teams・Webhook も送られません。
- after_response では、答えを返したあとも、そのプロセス（php-fpm のワーカーなど）は通知を送り終わるまでふさがります。通知を受ける人がとても多く、同時の保存も多いときは、queue にしてください。
- 共有・削除の通知は、今までどおり、その場で送ります。
- コマンド（データのインポートなど）からの保存は、auto のとき、その場で送ります。

## システムのアップデート時
キューワーカは、長い時間動き続けるプロセスです。再起動しないかぎり、新しいコードは使われません。  
そのため、システムをアップデートするときは、ワーカを再起動してください。queue:restart コマンドで、すべてのワーカを穏やかに再起動できます。

```
php artisan queue:restart
```


## 実行中ジョブの確認
いま実行しているジョブを確かめる方法です。

- データベースに接続し、次のコマンドを実行します。

```
select * from jobs;
```

- いま実行しているジョブの一覧が出ます。


## 実行失敗ジョブの確認
実行に失敗したジョブを確かめる方法です。

- データベースに接続し、次のコマンドを実行します。

```
select * from failed_jobs;
```

- 実行に失敗したジョブの一覧が出ます。
