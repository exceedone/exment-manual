# 更新手順 v7.3.0
v7.2.x から v7.3.0 に上げる手順です。v7 の中のアップデートですが、<span class="red bold">v7.3 だけは、`composer update` だけでは上がりません。</span>

v7.3 では、管理画面のライブラリ「exceedone/exment-admin-core」が 1.x から **2.x** に変わります。今までの `composer.json` は admin-core を `^1.0` に決めているので、そのまま `composer update` をしても「Nothing to install, update or remove」と出て、v7.2.x のままです。

| | v7.2.x | v7.3.0 |
| ---- | ---- | ---- |
| PHP | 8.2 以上 | 8.2 以上（変更なし） |
| exceedone/exment-admin-core | 1.x（`^1.0`） | **2.x（`^2.1.1`）** |
| QR コードのライブラリー | simplesoftwareio/simple-qrcode | bacon/bacon-qr-code 3.x |
| Laravel | 12 | 12（変更なし） |
| MySQL / MariaDB | 8.0 以上 / 10.11 以上 | 変更なし |

アップデートでエラーが出たときは、[トラブルシューティング](/ja/troubleshooting)をご覧ください。

## 1. バックアップを取る
<span class="red bold">必ず、上げる前にバックアップを取ってください。</span>

- データベースと、Exment のフォルダー全体（`composer.json`・`composer.lock`・`vendor`・`public/vendor`・`.env`・`storage` を含む）を控えます。
- <span class="red bold">バックアップのファイルができているかを、目で確かめてください。</span>`php artisan exment:backup` は、mysqldump が失敗しても（たとえば、データベースの TLS の証明書が自己署名のとき）、エラーにならずに終わることがあります。

## 2. composer で入れたサイト
Exment をインストールしたフォルダー（プロジェクトのルート）で、次を順に実行します。

~~~
# 1. composer.json に simplesoftwareio/simple-qrcode の行があるときだけ
composer remove simplesoftwareio/simple-qrcode --no-update

# 2. exment と exment-admin-core を 7.3 の版にする（-W が要ります）
composer require "exceedone/exment:^7.3" "exceedone/exment-admin-core:^2.1.1" -W

# 3. データベースなどを新しくする
php artisan exment:update --force
~~~

- **1.** v7.2 の zip や boilerplate から入れたサイトの `composer.json` には、`simplesoftwareio/simple-qrcode` の行があります（v7.3 では使いません）。残っていても上がりますが、使わない行が残るので、消すことをおすすめします。
- **2.** `-W`（`--with-all-dependencies`）を付けてください。付けないと「bacon … fixed to 1.0.2 by a partial update」のように止まります。これで exment 7.3、exment-admin-core 2.1.1 以上、bacon/bacon-qr-code 3.x になります（dasprid/enum も入ります）。
    - サイトが自分で `bacon/bacon-qr-code` の 1.x を require しているときは、`"bacon/bacon-qr-code:^3"` も同じ行に足します。
- **3.** `--force` は、本番（`APP_ENV=production`）での確認を省きます。
- `composer.json` に exment-admin-core も simple-qrcode も書いていないサイト（`exceedone/exment` だけを require しているサイト）は、ふつうの `composer update` と `php artisan exment:update` で上がります。
- 終わったら、ブラウザーで **Ctrl+F5**（スーパーリロード）を押してください。

## 3. zip で入れたサイト・レンタルサーバー
v7.3 の zip で入れかえます。

1. `php artisan down` で、メンテナンスの表示にします。
2. 上の「バックアップを取る」をします。
3. 今のフォルダーの名前を変えます（例：`exment` → `exment_old`）。
4. v7.3 の zip を[ダウンロード](https://exment.net/download/)して、もとの名前のフォルダーに展開します。
5. 新しいフォルダーの `storage` を消し、古いフォルダーの **`storage` を丸ごと**と、**`.env`** をコピーします。
6. 新しいフォルダーの `bootstrap/cache/*.php` を消します。
7. `php artisan exment:update --force` を実行します。
8. `php artisan up` で、メンテナンスの表示を終えます。

| | 扱い |
|---|---|
| `.env`・`storage` の全部（`app/admin`・`app/plugins`・`app/backup`・`app/templates`・`oauth-*.key` など） | 古いものをそのまま使う |
| `public` に自分で置いた・変えたファイル、`config/*.php` を手で変えたところ、自分で composer require したパッケージ（ldaprecord など） | 古いフォルダーを見ながら、手で戻す |
| `app/Exment/bootstrap.php` に書いた自分のコード | 手で戻す（ファイルは `exment:update` が作り直します） |
| `vendor`・`composer.json`・`composer.lock`・`public/vendor`・`bootstrap/cache` | 新しいもの（古いものは使わない。`public/vendor` は `exment:update` が作り直します） |

## 4. v7.3 で変わること
### プラグイン・独自のソース：メッセージは文字として出ます
admin-core 2.x では、`admin_info()`・`admin_success()`・`admin_warning()`・`admin_error()`（`*_once()` も）・`admin_toastr()` のメッセージは、**HTML ではなく文字として**出ます。名前やエラーの文に `<` などが入っていても、そのまま文字で出るので安全です。

メッセージに HTML（`<br>` やリンクなど）を使っているときは、`admin_html_message()` で包んでください。中に入れる値は `e()`（または `esc_html()`）で囲みます。

~~~php
// v7.2 まで
admin_info('完了', $name . ' を作りました。<br><a href="' . $url . '">開く</a>');

// v7.3 から
admin_info('完了', admin_html_message(e($name) . ' を作りました。<br><a href="' . e($url) . '">開く</a>'));
~~~

包まないと、`<br>` などがそのまま文字で出ます（動きは止まりません）。

### 機能の管理
v7.3 で増えた機能の多くは、「システム設定」→「[機能の管理](/ja/feature)」で使う・使わないを決めます。新しい機能には、初めは使わないになっているものがあります。

### 画面
左のメニューで、下にメニューがある項目は横に開きます（「システム設定」で前の開き方に戻せます）。くわしくは[リリースノート](/ja/release_note)をご覧ください。

## 5. Exment SaaS をお使いの方
Exment SaaS は、提供する側で上げます。この手順は要りません。

## 6. 元に戻すとき
上げる前に取ったバックアップに戻します。

1. データベースを、上げる前のバックアップでリストアします。
2. `composer.json`・`composer.lock`・`vendor`・`public/vendor` を、上げる前のものに戻します（zip のサイトは、名前を変えて残した古いフォルダーに戻します）。
3. `bootstrap/cache` の中を消して、`php artisan optimize:clear` を実行します。

<span class="red bold">`php artisan migrate:rollback` は使わないでください。</span>v7.3 で足したデータベースの変更には、元に戻す処理がないものがあり、メニューや列が残ります。
