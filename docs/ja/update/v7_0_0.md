# 更新手順 v7.0.0
Exment v7.0.0では、使用するLaravelのバージョンが変更となります。  
v7.0.0未満では、Laravel10を使用しておりましたが、Laravel10のセキュリティサポート期限が終了したため、Laravel12へと変更します。  
Laravel11はスキップし、Laravel10からLaravel12へ直接アップデートを実施します。  

その他の動作環境に変更はありません。v6.xと同じく、以下のバージョンをご利用ください。  

| | v6.x | v7.0.0 |
| ---- | ---- | ---- |
| PHP | 8.2以上 | 8.2以上 (変更なし) |
| Laravel | 10 | **12** |
| MySQL | 8.0 | 8.0 (変更なし) |
| MariaDB | 10.11 | 10.11 (変更なし) |

アップデート時にエラーが発生した場合、[トラブルシューティング](/ja/troubleshooting)をご参照ください。

## <span class="red bold">警告：管理画面ライブラリと名前空間が変更となります</span>
v6.xまでは、管理画面ライブラリとして「exceedone/laravel-admin」(名前空間 `Encore\Admin`)を使用していました。  
このライブラリはLaravel12に対応していないため、Exment v7.0.0では「exceedone/open-admin-core」(名前空間 `ExmentAdminCore\Admin`)を使用します。  

<span class="red bold">そのため、プラグイン、「config/admin.php」、ならびに独自に作成・カスタマイズしたソースコードは、そのままではご利用いただけません。</span>  
古い名前空間のクラスを呼び出している場合、アップデート後に以下のようなエラーが発生します。

```
Class "Encore\Admin\Widgets\Box" not found
```

変更となるのは名前空間の先頭部分のみです。クラス名・メソッド名・引数は今までと同じです。

| v6.x以下 | v7.0.0 |
| ---- | ---- |
| `Encore\Admin\` | `ExmentAdminCore\Admin\` |

(よく使用するクラスの例)

| v6.x以下 | v7.0.0 |
| ---- | ---- |
| `Encore\Admin\Form` | `ExmentAdminCore\Admin\Form` |
| `Encore\Admin\Widgets\Box` | `ExmentAdminCore\Admin\Widgets\Box` |
| `Encore\Admin\Widgets\Form` | `ExmentAdminCore\Admin\Widgets\Form` |
| `Encore\Admin\Widgets\Grid\Grid` | `ExmentAdminCore\Admin\Widgets\Grid\Grid` |
| `Encore\Admin\Widgets\Grid\Tools` | `ExmentAdminCore\Admin\Widgets\Grid\Tools` |
| `Encore\Admin\Auth\Database\Administrator` | `ExmentAdminCore\Admin\Auth\Database\Administrator` |
| `Encore\Admin\Facades\Admin` | `ExmentAdminCore\Admin\Facades\Admin` |

修正が必要なファイルは以下の通りです。後述の手順で修正を行ってください。  

- 「app/Admin」フォルダ内のファイル(「app/Admin/bootstrap.php」「app/Admin/Controllers」) → [app/Adminフォルダの修正](#appadminフォルダの修正)
- 「config/admin.php」 → [config/admin.php修正](#configadminphp修正)
- 独自に作成したプラグイン、独自にカスタマイズしたソースコード → [プラグインと独自ソースコードの修正](#プラグインと独自ソースコードの修正)

※「admin_url()」「admin_toastr()」などのヘルパー関数は、修正不要でそのまま使用できます。  
※Exment自体のクラス(「Exceedone\Exment\...」)に変更はありません。

※その他、Laravel12に対応していないライブラリがcomposer.jsonに記載されている場合、削除するか、Laravel12対応バージョンへ変更してください。

### アプリケーションのキャッシュファイル削除
「bootstrap/cache」内のキャッシュファイルには、v6.xまでに使用していたライブラリの情報が残っています。  
残したままアップデートすると、以下のエラーが発生し、Exmentが全く起動しなくなります。

```
Class "Encore\Admin\AdminServiceProvider" not found
```

- 以下の2ファイルを削除してください。(自動的に再作成されます。存在しない場合、作業は不要です)

```
bootstrap/cache/packages.php
bootstrap/cache/services.php
```

### コマンド実行1

- 以下のコマンドを実行します。

```
# Laravelフレームワーク、Exment、関連ライブラリのアップデート実施
composer update
```

※Xserver側のphpにsodium拡張機能が実装されてない場合は、以下のコマンドを実行します。
```
composer update --ignore-platform-req=ext-sodium
```

### アプリケーションのフォルダ構成について
Laravel11以降では新しいフォルダ構成になっていますが、**Laravel12では、Laravel10のフォルダ構成もそのまま使用できます**。  
そのため、v6.xまでに作成された以下のファイルは、そのまま使用でき、書き換えは不要です。

- bootstrap/app.php
- app/Http/Kernel.php
- app/Console/Kernel.php
- app/Exceptions/Handler.php
- app/Http/Middleware/TrustProxies.php

※独自にアプリケーションをカスタマイズしている場合は、[Laravel公式のアップグレードガイド](https://laravel.com/docs/12.x/upgrade)をご確認ください。  
特に、独自のマイグレーションで「change」メソッドを使用して列を変更している場合、Laravel11以降では、その列のすべての属性を再度記載する必要があります。

### app/Adminフォルダの修正
「app/Admin」フォルダ内のファイルは、Exmentのインストール時に作成されるファイルです。  
このうち「app/Admin/bootstrap.php」は<span class="red bold">Exmentの画面表示のたびに読み込まれる</span>ため、古い名前空間が残っていると、画面表示のたびにログ(「storage/logs/laravel.log」)にエラーが記録され、このファイルに記載した内容が反映されなくなります。

- 以下のファイルを開き、「Encore\Admin」を「ExmentAdminCore\Admin」に置き換えてください。
   - app/Admin/bootstrap.php
   - app/Admin/Controllersフォルダ内のすべてのファイル

``` php
// 修正前
Encore\Admin\Form::forget(['map', 'editor']);

// 修正後
ExmentAdminCore\Admin\Form::forget(['map', 'editor']);
```

### config/admin.php修正
「config/admin.php」には管理画面ライブラリのクラス名が記載されているため、修正を行ってください。  

- プロジェクトフォルダ直下の「config/admin.php」を開きます。
- ファイル内の文字列「Encore\Admin」を、すべて「ExmentAdminCore\Admin」に置き換えます。  
「auth.providers.admin.model」「database.users_model」「database.roles_model」「database.permissions_model」「database.menu_model」「grid_action_class」など、複数箇所に記載があります。

``` php
// 修正前
                'model'  => Encore\Admin\Auth\Database\Administrator::class,

// 修正後
                'model'  => ExmentAdminCore\Admin\Auth\Database\Administrator::class,
```

- また、v7.0.0では以下の設定項目が追加されています。v6.xまでに作成された「config/admin.php」には存在しないため、v7.0.0の初期設定ファイルに合わせて追記してください。

``` php
    'auth' => [
        // ...「auth」の項目内に、以下の4項目を追記します
        'guard' => 'admin',
        'throttle_logins' => true,
        'throttle_attempts' => 5,
        'throttle_timeout' => 900,
    ],
```

※「guard」(単数形)と、すでに記載されている「guards」(複数形)は、それぞれ別の設定項目です。  
「guards」は管理画面用のログイン方式(driver・provider)を定義する項目で、v6.xまでの「config/admin.php」にもすでに記載されています。<span class="red bold">「guards」はそのままにして、上記の4項目のみを追記してください。</span>

※上記4項目を追記しなくても、Exmentの動作に支障はありません。「guard」は未設定の場合「admin」として動作します。またログイン失敗時のロック機能は、Exment独自の仕組み(「.env」の「EXMENT_MAX_ATTEMPTS」「EXMENT_DECAY_MINUTES」。詳細は[こちら](/ja/config))で動作するため、上記の設定には依存しません。

※「config/admin.php」は手動で修正してください。「vendor:publish」コマンドで上書きすると、Exmentの設定(画面名、ロゴ、操作ログの設定など)が初期値に戻ってしまいます。

### プラグインと独自ソースコードの修正
独自にプラグインを作成している場合、または独自にソースコードをカスタマイズしている場合、[警告：管理画面ライブラリと名前空間が変更となります](#警告：管理画面ライブラリと名前空間が変更となります)に記載の通り、名前空間を修正してください。  

- 以下のファイルについて、「Encore\Admin」を「ExmentAdminCore\Admin」に置き換えてください。
   - 「app/Plugins」フォルダに配置しているプラグインのファイル
   - 「管理者設定」→「プラグイン」からアップロードしたプラグイン
   - 「app」フォルダ配下など、独自にカスタマイズしたソースコード

``` php
// 修正前
use Encore\Admin\Widgets\Box;

// 修正後
use ExmentAdminCore\Admin\Widgets\Box;
```

- 画面からアップロードしたプラグインについては、ソースコードを修正後、再度zipファイルに圧縮し、「管理者設定」→「プラグイン」からアップロードしてください。

※プラグインの記載方法は、[プラグイン作成方法](/ja/plugin_quickstart)をご確認ください。  
※第三者が作成したプラグインを使用している場合は、v7.0.0に対応しているか、配布元にご確認ください。

### (Laravel Sanctumを使用している場合のみ) config/sanctum.php修正
Exment自体はLaravel Sanctumを使用していないため、ほとんどの場合この作業は不要です。  
独自のプログラムでSanctumを使用している場合、Sanctum4で「config/sanctum.php」の「middleware」項目のキー名が変更となっています。(旧キー名「verify_csrf_token」も引き続き使用できます)  
「config/sanctum.php」を開き、以下のように修正します。

``` php
    'middleware' => [
        'authenticate_session' => Laravel\Sanctum\Http\Middleware\AuthenticateSession::class,
        'encrypt_cookies' => Illuminate\Cookie\Middleware\EncryptCookies::class,
        'validate_csrf_token' => Illuminate\Foundation\Http\Middleware\ValidateCsrfToken::class,
    ],
```

## 他のエラー
### 「Your requirements could not be resolved to an installable set of packages」エラー

- Laravel12に対応していないライブラリがcomposer.jsonに記載されている場合に発生します。

```
  Problem 1
    - Root composer.json requires laravel/framework ^12.0 -> satisfiable by laravel/framework[v12.0.0, ...].
    - xxxxx/yyyyy zzzz requires illuminate/support ^10.0 -> found illuminate/support[v10.0.0, ...] but these were not loaded.
```
- この場合、メッセージに表示されているライブラリ名をご確認いただき、composer.jsonから削除するか、Laravel12対応バージョンへ変更してください。  
修正後、再度「composer update」を実行してください。

### 「Class "Encore\Admin\AdminServiceProvider" not found」エラー

- Exmentが全く起動せず、画面・「php artisan」コマンドの両方で以下のエラーが発生します。

```
  In ProviderRepository.php line 205:

  Class "Encore\Admin\AdminServiceProvider" not found
```
- アプリケーションのキャッシュファイルに、古いライブラリの情報が残っています。以下の2ファイルを削除してください。

```
bootstrap/cache/packages.php
bootstrap/cache/services.php
```

### 「Class "Encore\Admin\XXXX" not found」エラー

- 「app/Admin」「config/admin.php」、プラグイン、独自にカスタマイズしたソースコードに、古い名前空間が残っている場合に発生します。

```
  Error

  Class "Encore\Admin\Form" not found (app/Admin/bootstrap.php)
  Class "Encore\Admin\Widgets\Box" not found (プラグイン)
```
- <span class="red bold">ファイルによっては、画面は正常に表示され、「storage/logs/laravel.log」にのみエラーが記録されます。</span>アップデート後、一度ログファイルをご確認ください。
- 該当のファイルについて、「Encore\Admin」を「ExmentAdminCore\Admin」に置き換えてください。  
詳細は[app/Adminフォルダの修正](#appadminフォルダの修正)、[config/admin.php修正](#configadminphp修正)、[プラグインと独自ソースコードの修正](#プラグインと独自ソースコードの修正)をご確認ください。

### アップデート後、画面が正しく表示されない

- 古いバージョンのキャッシュが残っている可能性があります。  
以下のコマンドを実行してください。

``` bash
php artisan config:clear
php artisan route:clear
php artisan view:clear
php artisan cache:clear
```
