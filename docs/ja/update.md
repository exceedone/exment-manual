# アップデート
Exment を新しい版にする手順です。  
どの版で何が変わったかは、[リリースノート](/ja/release_note)をご覧ください。

## アップデートの流れ
1. **今の版を確かめる**
2. **バックアップを取る**
3. **アップデートする**（今の版によって、手順が変わります）
4. **アップデートのあとに確かめる**（同梱の公式プラグインの新しい版も確かめます）

## 1. 今の版を確かめる
- 画面で見る：「システム設定」→「システムのバージョン情報」→「現在のバージョン」
- ファイルで見る：`composer.lock` の `exceedone/exment` の `version`

## 2. バックアップを取る
アップデートの前に、データのバックアップを取ってください。くわしくは[バックアップ](/ja/backup)をご覧ください。

- 管理者で Exment にログインし、左のメニューの「管理者設定」→「バックアップ」を開きます。
- 右上の［バックアップ］ボタンを押します。データと添付ファイルのバックアップができます。
- できたバックアップのファイルを押して、ダウンロードしておきます。

※ 下の「アップデートバッチ」を使うときは、バッチが自動でバックアップを取ります。

## 3. アップデートする
### どの手順を使うか
今の版と、上げたい版で決まります。

| 今の版 | すること |
|---|---|
| **v7.x**（v7 の中で新しくする） | 下の「[ふつうのアップデート](/ja/update?id=ふつうのアップデート)」で上がります |
| **v6.x 以下** | 先に、下の「[古い版から上げるとき](/ja/update?id=古い版から上げるとき)」の手順が必要です |

- v7.0.x から v7.1.0 以上に上げると、<span class="red bold">画面のデザインが「モダン」に変わります。</span>前の見た目に戻すには、「システム設定」の[画面のデザイン](/ja/system_setting?id=画面のデザイン)で「クラシック」を選んでください。

### ふつうのアップデート
方法は 3 つあります。どれも、することは同じです（バックアップ → 新しいプログラムを取る → データベースを新しくする）。

| 方法 | 向いている人 |
|---|---|
| **A. アップデートバッチ（おすすめ）** | サーバーでファイルを 1 つ実行するだけにしたい |
| **B. コマンドで行う** | 1 つずつ自分で実行したい |
| **C. 自動アップデート** | 毎日、自動で新しい版にしたい（[自動アップデート](/ja/update_auto)） |

#### A. アップデートバッチ（おすすめ）
**(1) バッチをダウンロードする（最初の 1 回だけ）**

Exment を入れたフォルダー（プロジェクトのルートディレクトリ）に置きます。

| サーバー | すること |
|---|---|
| Windows | [ExmentUpdateWindows.bat](https://exment.net/downloads/cmd/ExmentUpdateWindows.bat) をダウンロードして、フォルダーに置く |
| Linux | 下のコマンド（`ExmentUpdateLinux.sh`） |
| Xserver | 下のコマンド（`ExmentUpdateLinuxXserver.sh`） |
| さくらインターネット | 下のコマンド（`ExmentUpdateLinuxSakura.sh`） |
| Mac | [ExmentUpdateLinux.sh](https://exment.net/downloads/cmd/ExmentUpdateLinux.sh) をダウンロードしてフォルダーに置き、`chmod 775 ExmentUpdateLinux.sh` を実行する |

Linux・Xserver・さくらインターネットは、フォルダーの中で、次のコマンドを実行します（お使いのサーバーの 2 行だけ）。

~~~
# Linux
wget https://exment.net/downloads/cmd/ExmentUpdateLinux.sh
chmod 775 ExmentUpdateLinux.sh

# Xserver
wget https://exment.net/downloads/cmd/ExmentUpdateLinuxXserver.sh
chmod 775 ExmentUpdateLinuxXserver.sh

# さくらインターネット
wget https://exment.net/downloads/cmd/ExmentUpdateLinuxSakura.sh
chmod 775 ExmentUpdateLinuxSakura.sh
~~~

※ 2021 年 4 月 13 日より前にダウンロードしたバッチをお使いの場合は、新しいものに差し替えてください。

**(2) バッチを実行する**

フォルダーの中で実行します。

~~~
# Linux・Mac
sh ExmentUpdateLinux.sh

# Xserver
sh ExmentUpdateLinuxXserver.sh

# さくらインターネット
sh ExmentUpdateLinuxSakura.sh

# Windows
ExmentUpdateWindows.bat
~~~

バッチは、次のことを順に行います。

- データのバックアップ
- 新しいプログラムを取って、入れかえる
- データベースを新しくする

#### B. コマンドで行う
先に、上の「2. バックアップを取る」を行ってください。  
そのあと、フォルダーの中で、次のコマンドを実行します。

~~~
cd (プロジェクトのルートディレクトリ)
composer update
php artisan exment:update
~~~

- 新しい版が出た直後は、まだ見つからないことがあります。そのときは、10〜20 分待ってから、もう一度実行してください。
- 本番のサイト（`APP_ENV=production`）では、データベースを変える前に、確かめる質問が出ます。画面のないところ（スクリプト・cron・CI）で動かすときは、`php artisan exment:update --force` を使ってください。

**レンタルサーバー（Xserver など）のとき**

- Xserver では、`composer update` のかわりに、`composer update --ignore-platform-reqs` を実行してください。Xserver は、PHP の Sodium 拡張が最初から入っていないためです（どうしても入れたいときは、Xserver のサポートにお問い合わせください）。
- SSH で使う `php` が、サーバーの管理画面で選んだ PHP と違う版のことがあります。`php --version` で、同じ版か確かめてください。違うときは、`~/bin/php` をその版にリンクするか、`/usr/bin/php8.3 artisan exment:update` のように、場所を全部書いて動かします（[レンタルサーバー](/ja/install_rental)）。

#### C. 自動アップデート
毎日、新しい版があるかを調べて、あればアップデートバッチを動かします。設定のしかたは、[自動アップデート](/ja/update_auto)をご覧ください。

- 自動アップデートで上がるのは、「ふつうのアップデート」で上がる範囲だけです。**v6 から v7 のような、大きな版の変わり目は上がりません**。くわしくは、下の「[版の番号と、上がる範囲](/ja/update?id=版の番号と、上がる範囲)」をご覧ください。

### 古い版から上げるとき
次の版の変わり目には、手作業の手順があります。アップデートバッチや自動アップデートでは上がりません。  
今の版から最新の版までのあいだにある変わり目のページを、すべてご確認ください。

| 版の変わり目 | 手順のページ |
|---|---|
| v3.x 以下 → v4.0.x | [v4.0 へのアップデート](/ja/update/v4_0) |
| v4.3.x 以下 → v4.4.x 以上 | [v4.4 へのアップデート](/ja/update/v4_4) |
| v4.4.x 以下 → v5.0.0 以上 | [v5.0 へのアップデート](/ja/update/v5_0_php8) |
| v5.0.x 以下 → v6.0.0 以上 | [v6.0 へのアップデート](/ja/update/v6_0_php8) |
| <span class="red bold">v6.x 以下 → v7.0.0 以上</span> | <span class="red bold">[v7.0 へのアップデート](/ja/update/v7_0_0)</span>（Laravel の版と、管理画面のライブラリの名前空間が変わります） |

- どの版がいつまで修正されるかは、[サポートの期間](/ja/support_policy)をご覧ください。

## 4. アップデートのあとに確かめる
- ブラウザーで **Ctrl+F5**（スーパーリロード）を押して、画面を読み込み直してください。
- 「システム設定」→「システムのバージョン情報」で、新しい版になっているかを確かめます。
- エラーが出たときは、[トラブルシューティング](/ja/troubleshooting)をご覧ください。
- アップデートのあと、「機能の管理」で同梱の公式プラグインの新しい版を確かめます（下の「[アップデートと同梱の公式プラグイン](/ja/update?id=アップデートと同梱の公式プラグイン)」）。

## アップデートと同梱の公式プラグイン
Exment v7.2.1 から、無料の公式プラグイン（プロジェクト管理・IT サポート・Groupware）が Exment に同梱されています（パッケージ exceedone/exment-plugins-release）。

`composer update` と `php artisan exment:update`（アップデートバッチ・自動アップデートも同じ）では、新しい Exment と一緒に、新しい同梱のプラグインも届きます。**ただし、サイトで使っているプラグインは、自動では切りかわりません。** プラグインにはデータと設定があるので、いつ切りかえるかは、システム管理者が決めます。

そのため、アップデートのあとのサイトには、次の 2 つがあります。

| | どこにあるか | 変わるとき |
| --- | --- | --- |
| 使っているプラグイン | サイトのプラグインのフォルダーと、データベース | システム管理者が「機能の管理」で切りかえたとき |
| 同梱のプラグイン | Exment のパッケージの中（exceedone/exment-plugins-release） | Exment をアップデートしたとき |

### 切りかえ方
1. 「設定：システム」の「[機能の管理](/ja/feature?id=無料の公式プラグイン（exment-に同梱）)」を開きます。「無料の公式プラグイン（Exment に同梱）」の欄に、同梱のプラグインが並びます。
2. 新しい版があるときは、「新しいバージョン ○○ があります。」と出ます。「このバージョンに更新する」を押すと、切りかわります。設定・メニュー・権限は残ります。
3. 切りかえる前の版は残っています。うまく動かないときは、「前のバージョン（○○）に戻す」で戻せます。

- 並ぶのは、エクシード・ワンの署名を確かめられた公式プラグインだけです。
- 新しい版にセキュリティの修正が入っているときは、システム管理者のホームのお知らせとベルの通知（メールが送れるサイトではメールも）で、1 回だけ知らせます（[セキュリティの修正のお知らせ](/ja/feature?id=セキュリティの修正のお知らせ)）。
- まだ「使う」を押していないプラグインは、アップデートしてもインストールされません。
- 運営者が版を切りかえるサイト（Exment SaaS など）では、ボタンは出ません。運営者が切りかえます。

### 同梱のプラグインの新しい版が届くとき
- Exment 7.2.x は、パッケージ exceedone/exment-plugins-release を `~7.2.0` の範囲で使います。そのため、`composer update` をすると、**Exment に新しい版がないときでも**、7.2.x の最新の同梱のプラグインが届きます（たとえば、ExmentPM 1.7.24 は、パッケージの 7.2.22 で届きます）。
- 届いても、使っているプラグインは変わりません。切りかわるのは、システム管理者が「機能の管理」で「このバージョンに更新する」を押したときだけです。
- exment.net からダウンロードする zip には、その zip を作った日の同梱のプラグインが入っています。zip を作り直すのは、Exment の新しい版が出たときだけです。zip で入れたサイトにも、次に `composer update` をしたときに、新しい同梱のプラグインが届きます。
- Exment 7.3 でも同じで、同じマイナーの版の系列（7.3.x）の同梱のプラグインが届きます。

## 版の番号と、上がる範囲
Exment の版の番号は、「メジャー . マイナー . パッチ」（例：v7.1.0）です。どの数字が上がるかで、アップデートのしかたが変わります。

| 種類 | 例 | 中身 | アップデートのしかた |
|---|---|---|---|
| パッチ | v7.0.2 → v7.0.3 | 不具合・脆弱性の修正だけ | ふつうのアップデートで上がります |
| マイナー | v7.0.x → v7.1.0 | 新しい機能が入ります。画面が少し変わることがあります | ふつうのアップデートで上がります。上げる前に[リリースノート](/ja/release_note)をご確認ください |
| メジャー | v6.x → v7.0 | Laravel・PHP の要件や、プログラムの作りが大きく変わります | **ふつうのアップデートでは上がりません**。「古い版から上げるとき」の手順で上げてください |

### なぜ、メジャーの版は自動で上がらないか
- アップデートバッチと自動アップデートは、`composer update` を使います。`composer update` は、`composer.json` に書いてある範囲の中で、いちばん新しい版にします。
- たとえば、`"exceedone/exment": "^7.0"` と書いてあれば、v7.x の最新までです。v8 にはなりません。`"^6.2"` なら、v7 が出ていても、v6.x の最新までです。
- v6 をお使いのまま自動アップデートを動かしていると、自動アップデートは「もっと新しい版（v7）がある」と判断して、毎日アップデートバッチを動かします（版は v6.x の最新のままです）。v7 に上げるか、上げないあいだは自動アップデートを止めるかを、ご検討ください。
