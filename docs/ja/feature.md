# 機能の管理
新しい機能とプラグインを使うかどうか・使える人・メニューを決めます。  
Exment はたくさんのサイトで使われているので、新しい機能は、はじめは「使わない」です。システム管理者が「使う」にするまで、メニューに出ず、URL を開いても使えません。Exment を更新しただけで、画面やメニューが変わることはありません。

※この画面は、Exment v7.2.1 以降で使えます。

## 設定画面
システム管理者でログインし、「管理者設定」→「機能の管理」を開きます（URL は `/feature`）。  
この画面を開けるのは、システム管理者だけです。

![機能の管理](img/feature/feature1.png)

画面は、上の「Exment の機能」と、下の「プラグイン」に分かれています。

## Exment の機能
Exment 本体の新しい機能です。今は次のものがあります。

| 名前 | 内容 |
| --- | --- |
| ファイル共有 | ワークスペース・フォルダー・版の管理・共有リンクなど。使わないにしても、ファイルは消えません。（ファイル共有が入っている版だけに出ます） |
| スタジオ | 画面の一覧と画面の作成、スマホのアプリ（/app）。使えるのは、テーブルを設定できる人です。 |
| データメンテナンス | テーブルのデータをまとめて整理します（いまは添付ファイルのまとめての削除）。使えるのは、テーブルを設定できる人です。（v7.3.0 以降）[データメンテナンス](/ja/data_maintenance) |
| ゴミ箱 | すべてのテーブルの削除したデータを 1 つの画面で見て、元に戻す・完全に削除します。使えるのは、「削除データの表示」の権限などがある人です。（v7.3.0 以降）[ゴミ箱](/ja/trash) |

機能ごとに、次の 3 つを決めます。

| 項目 | 内容 |
| --- | --- |
| 使う | その機能を、このサイトで使うかどうか。はじめは「使わない」です。 |
| 使える人 | 「すべてのユーザー」か「選んだ役割グループのユーザー」。役割グループを 1 つも選ばないと、システム管理者だけが使えます。システム管理者はいつでも使えます。 |
| メニュー | メニューに「出す」かどうか。使える人にだけ出ます。メニューの行がないときは「メニューの行がありません。保存すると作ります。」と出ます。 |

「状態」の欄には、次のように出ます。

| 状態 | 意味 |
| --- | --- |
| 新しい | まだだれも決めていない機能です（「使わない」の扱いです）。 |
| 使っている | 「使う」になっていて、使える状態です。 |
| この環境では使えません | サーバーの設定で止めています（[サーバーの設定で固定する](/ja/feature?id=サーバーの設定で固定する)）。この画面からは「使う」にできません。 |
| 必要な機能が「使わない」なので、使えません。 | ほかの機能があって初めて動く機能（「「○○」を使っているときだけ使えます。」と出ます）で、その機能が「使わない」になっています。 |

※スタジオは、ここで選んだ人のうち、テーブルを設定できる人だけが使えます。  
※API・公開フォームなどを使うかどうかは、これまでどおり[システム設定](/ja/system_setting)にあります。

## プラグイン
インストールしているプラグインも、同じ画面に並びます。  
新しい設定を二重に持つのではなく、今ある設定をそのまま見せています。

| 項目 | 内容 |
| --- | --- |
| 使う | プラグインの有効・無効と同じものです。無効のときは「プラグインが無効です」と出ます。変えるときは「プラグインの設定で変える」から、[プラグイン](/ja/plugin)の画面で変えます。 |
| 使える人 | 役割グループのプラグインの「利用」の権限と同じものです。変えるときは、[役割グループ](/ja/role_group)の画面で変えます。 |
| メニュー | メニューに出すかどうか。これだけは、この画面で決めます。 |

※種類が「だれでも使える」プラグインや、プラグインの設定で「すべてのユーザーが使える」にしたプラグインは、そのことが出ます。  
※プラグインの中に、プラグインが登録した機能（たとえば、Web メールなど）があるときは、プラグインの下に 1 行ずつ出ます。プラグインの中の機能も、はじめは「使わない」です。使える人は、プラグインを使える人のうち、ここで選んだ人です。

## 無料の公式プラグイン（Exment に同梱）
Exment には、無料の公式プラグイン（プロジェクト管理・IT サポート・Groupware）が同梱されています。「機能の管理」の「無料の公式プラグイン（Exment に同梱）」の欄から入れます。詳細は[公式プラグイン](/ja/plugin_official)をご覧ください。

- 「使う（インストールする）」を押すまでは、インストールも読み込みもしません（テーブルも作りません）。
- 押すと、確かめてからインストールし、有効にします。そのプラグインの主な機能も「使う」になります。そのあとは、上の「プラグイン」の欄にも並び、使える人やメニューを決められます。
- 新しいバージョンがあるときは「新しいバージョン ○○ があります。」と出ます。自動では入れません。「このバージョンに更新する」で更新します（設定・メニュー・権限は残ります）。
- 更新する前のバージョンは残っていて、「前のバージョン（○○）に戻す」で戻せます。
- 前から手で入れていたプラグインは、そのまま使えます（入れ直しません）。同梱のほうが新しいときだけ、お知らせします。同梱のバージョンに置き換えると、手で入れたバージョンには戻せません。
- 同梱のプラグインは、エクシード・ワンの署名を確かめてから入れます。署名が合わないものは並びません。
- 運営者がバージョンを切り替えるサイト（SaaS など）では、「バージョンの切り替えは、このサイトの運営者が行います。」と出て、ボタンは出ません（`.env` の `EXMENT_BUNDLED_PLUGINS_UPDATES=false`）。

#### セキュリティの修正のお知らせ
入っている公式プラグインの新しいバージョンに、セキュリティの修正が入っているときは、システム管理者に知らせます。

- システム管理者のホームの上に、「公式プラグインの更新のお知らせ（○○）」が出ます。機能の管理の行にも、「セキュリティ修正」の印と「セキュリティの修正が入っています。「このバージョンに更新する」を押してください。」が出ます。
- ベルの通知と、メールが送れるサイトではメールで、同じ件名と本文を 1 回だけ送ります。
- ほかの利用者には何も出ません。更新するのは、システム管理者が「このバージョンに更新する」を押したときだけです。
- セキュリティの修正が入っていないバージョンに戻すときは、もう一度確かめます。

#### 新しい機能のお知らせ
Exment を更新して、まだ決めていない新しい機能が増えたときは、システム管理者のホームのお知らせとベルで 1 回だけ知らせます（「新しい機能があります（○○）。はじめは「使わない」になっています。…」）。メールは送りません。新しくインストールしたサイトでは出ません。

## 「使わない」にしたとき
- メニューに出なくなります（メニューの行は消さずに隠すだけです）。
- その機能のページと API は、URL を直接開いても使えません。
- データ（ワークスペース・ファイル・画面など）は消えません。もう一度「使う」にすれば、元に戻ります。
- 使っている人がいる機能を「使わない」にしたり、使える人を減らしたりして保存するときは、「次の機能・グループで、使えなくなる人がいます。保存しますか？」と確かめます。

## 使えないときに出るお知らせ
使えない機能の URL を開くと、次のお知らせが出ます。

| お知らせ | いつ出るか |
| --- | --- |
| この機能は、このサイトでは使っていません。 | その機能が「使わない」のとき（またはサーバーの設定で止めているとき）。システム管理者には、「機能の管理」へのリンクも出ます。 |
| この機能を使う権限がありません。管理者に聞いてください。 | 機能は「使う」になっているが、ログインしている人が「使える人」に入っていないとき。 |

どちらも「ホームへ戻る」のリンクから、ホームに戻れます。API から呼んだときは、同じお知らせが JSON で返ります（使っていないときは 404、権限がないときは 403）。

## 更新したサイトでは
Exment を更新しても、今まで使っていたものは、そのまま使えます。

- 更新の前から使っていた機能は、「使う」になります。今までどおり見えます。
  - ファイル共有：ワークスペースが 1 つでもあるサイト
  - スタジオ：だれかがスタジオの画面かスマホのアプリを開いたことがあるサイト（操作ログで確かめます）
- メニューがあるだけで使っていなかった機能は、「使わない」になります。
- プラグインの有効・無効と、役割グループの権限は変わりません。
- プラグインの中の機能のうち、そのプラグインが前から持っていたものは、前からプラグインを入れていたサイトでは「使う」のままです。
- 新しくインストールしたサイトでは、すべて「使わない」から始まります。
- 「管理者設定」の下に、「機能の管理」のメニューが足されます。

## サーバーの設定で固定する
サーバーの `.env` に `EXMENT_FEATURES_LOCKED` を書くと、サイトのシステム管理者が何を選んでも、その機能を「使わない」に固定できます。  
機能を出さないサービス（SaaS など）で使います。キーをカンマで区切って書きます。

~~~
EXMENT_FEATURES_LOCKED=file_server,studio
~~~

| キー | 機能 |
| --- | --- |
| `file_server` | ファイル共有 |
| `studio` | スタジオ（スマホのアプリを含む） |

固定した機能は、この画面で「この環境では使えません」と出ます。

※`.env` を変えたあとは、設定のキャッシュを使っているサーバーでは `php artisan config:clear`（または `php artisan config:cache`）を実行してください。

## 決める順番
使えるかどうかは、上から順に決まります。下の設定で、上の設定より広げることはできません。

1. **サーバーの設定**：`EXMENT_FEATURES_LOCKED` に書いた機能は、使えません。
2. **サイトの「使う」「使わない」**：「使わない」の機能は、だれも使えません。
3. **使える人**：すべてのユーザーか、選んだ役割グループのユーザー（システム管理者はいつでも使えます）。
4. **機能の中の設定**：スタジオならテーブルの権限、ファイル共有ならワークスペースの権限など。

## プラグインを作る方へ
プラグインは、自分の中の機能を登録して、この画面に 1 行出せます。登録した機能は、はじめは「使わない」です。

~~~php
use Exceedone\Exment\Services\Features;

// プラグインのクラスのコンストラクターなどで登録する。キーはプラグインの uri で始める
Features::register('exment_groupware.mail', [
    'label' => 'Web メール',
    'endpoints' => ['plugins/exment_groupware/mail'],
]);

// プラグインのページの中で確かめる
if (!Features::allowed('exment_groupware.mail')) {
    return Features::deny('exment_groupware.mail');
}
~~~

- `endpoints` に書いたページは、使えないときに上のお知らせが出ます。
- `existing => true` にすると、そのプラグインを前から入れていたサイトでは「使う」のままになります（前からあった機能を後から登録するとき）。
- `requires` に別の機能のキーを書くと、その機能が「使わない」のときは使えません。
