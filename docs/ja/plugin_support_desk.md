# サポートデスク（公式プラグイン）
「サポートデスク」は、IT サポート・ヘルプデスクのための、Exment の**公式プラグイン**です。お客様からの依頼（メール・受付フォーム・電話）と、監視やエラーログで見つけた問題を「チケット」で管理し、**進み具合をお客様とログインなしで共有**します。無料で使えます。

- ソースコード・説明：[exceedone/exment-plugins（support-desk）](https://github.com/exceedone/exment-plugins/tree/main/support-desk)
- ライセンス：GPL-3.0（Exment と同じ）
- プラグインの一覧に出る名前：Exment Support Desk（サポートデスク）。内部の名前は `ExmentSupportDesk`、URL は `/plugins/exment_support_desk` です。

## できること
| 分野 | できること |
| --- | --- |
| 担当者の画面 | 専用の**受付箱**（受付箱の種類と件数・チケットの一覧・会話と項目の 3 列）。チケットを切り替えてもページを読み直しません。キーボード操作（`J`/`K` 上下・`R` 返信・`N` 社内メモ・`Ctrl+Enter` 送る・`A` 自分が担当・`E` 解決・`?` 一覧）、下書きの自動保存、ダークモード、スマホ表示 |
| 受付 | **メール**（IMAP で 5 分ごとに受信。ISO-2022-JP・Shift_JIS・添付ファイルに対応）、**受付フォーム**（ログインなし・先に FAQ を案内）、**電話・来訪**（担当者が登録）、**監視・エラーログ**（API。同じエラーは 1 件にまとめて回数を数える）、**IT 資産の期限**（保守・ライセンス・ドメイン・証明書の期限が近づくと自動で起票） |
| やりとり | お客様への返信はメールで届き、お客様がそのまま返信すると同じチケットに入ります。引用の部分は自動で取り除きます。**社内メモ**はお客様に見えません。**定型文**と**ナレッジの候補**を返信欄の横に出します |
| 二重対応の防止 | ほかの担当者が同じチケットに返事を書いていると、画面に出ます |
| お客様との共有 | **ログインなしのリンク**（そのチケット 1 件だけが見える・期限と取り消し・開いた記録）。大事なチケットは**確認のコード**（メールに 6 桁）。ログインするお客様は**顧客ポータル**（会社の管理者は会社のチケットすべて） |
| SLA | お客様ごと・優先度ごとの、最初の返事と解決の目安。**営業時間と祝日で数え**、**お客様の返事待ちの間は止めます**。期限が近い・超えたら担当者に知らせます |
| 自動化 | 種類ごとの担当者か、対応中が少ない人に自動で割り当て。返事待ちのお願い → 自動で解決 → 自動で完了。解決したら満足度（5 段階）を聞きます |
| ナレッジ（FAQ） | 公開した記事は、お客様の FAQ ページと受付フォームに出ます。チケットからワンクリックで下書きできます |
| IT 資産 | お客様の PC・サーバー・ライセンスなどを登録し、チケットとつなぎます |
| レポート | 受付・解決・SLA の達成率・最初の返事までの時間・満足度など。**お客様ごとの作業時間と契約時間の比較**（月の報告に）、CSV |
| 検索 | 件名・本文・やりとり・メール・番号の部分一致。スペースで AND、タグは AND／OR を選べます |
| カスタマイズ | すべて Exment のテーブルなので、項目・画面・一覧・ワークフロー・API を Exment の画面で変えられます。チケットのボード（カンバン）も付いています |

## 動作要件
- Exment 7.0 以上（PHP 8.2 以上）。追加の PHP 拡張は要りません。
- メールの受信には、受付用のメールボックス（IMAP）が要ります。送信は Exment の[メール送信設定](/ja/mailsend_setting)を使います。
- 自動の処理（メールの受信・SLA・返事待ち・完了・資産の期限）は 5 分ごとに動きます。[タスクスケジュール](/ja/additional_task_schedule)を設定してください。
- 画面は日本語だけです。

## インストール
1. プラグインを入れます。Exment v7.2.1 以降は「機能の管理」から、それより前は zip のアップロードです。[公式プラグイン](/ja/plugin_official)をご覧ください。
2. Exment v7.2.1 以降では、「管理者設定」→「[機能の管理](/ja/feature)」で「サポートデスク：受付箱」をオンにします（オフのあいだは、セットアップの画面も開けません）。受付箱は、使える役割グループを選べます。お客様の窓口（`/support`）・メールの受信・監視からの起票を使うなら、「サポートデスク：お客様の窓口」もオンにします（受付箱がオンのときだけ動きます）。
   - 新しく入れたサイトでは、2 つとも最初はオフです。機能の管理の前からサポートデスクを使っていたサイトでは、2 つともオンのまま残ります。
   - 受付箱を「使わない」にすると、メニューの「サポートデスク」も消えます。チケットなどのテーブルはデータとして残り、Exment のふつうのテーブルとして URL（`/data/sd_ticket` など）や「管理者設定」→「カスタムテーブル」から開けます。メニューに出したいときは、「管理者設定」→「メニュー」でテーブルを足してください。見せたくないときは、役割グループでテーブルの権限を外してください。
3. メニューの「サポートデスク」（または `/plugins/exment_support_desk`）を開き、「セットアップする」を押します。テーブル・メニュー・権限・SLA・種類・定型文・FAQ の例まで入ります。
   - 左のメニューは「サポートデスク」1 つだけです（開くと受付箱）。チケット表・ナレッジ・お客様・連絡先・IT 資産・定型文は受付箱の上のメニューから、すべてのテーブル（チケットの種類・SLA も）は「設定」の「テーブル・権限」から開きます。
   - 1.0.6 までの「ITサポート」のフォルダー（受付箱とテーブル 8 つ）は、1.0.7 に上げたあと、最初に受付箱を開いたときに 1 つにまとまります。管理者が自分で足したメニューは残ります。
4. 「設定」で、受付用のメールボックス（IMAP）と窓口のアドレスを入れて保存し、「IMAP につながるか試す」を押します。メールの受信を使うなら、「差出人の確認」と「受信サーバーの名前」（受信したメールの Authentication-Results の先頭の名前）も入れます。入れるまでは、メールで来たチケットが「なりすましの疑い」になります。
5. 担当者を役割グループ「サポートデスク 担当者」に入れます。ログインするお客様は「サポートデスク お客様」に入れ、「お客様の担当者」の「Exment のユーザー」でつなぎます。
6. お客様には、窓口の URL（`https://あなたの Exment/support`）を案内します。

## 使い方

### 受付箱
メニューの「サポートデスク」を開くと、受付箱が出ます。画面は 3 列です。

| 列 | 中身 |
| --- | --- |
| 左 | 受付箱の種類と件数：対応が必要・自分の担当・担当者なし・お客様から返事・SLA 注意・超過・お客様の返事待ち・保留・監視・エラー・解決・完了・すべて。下に、メール受信のオン・オフと、自動処理が最後に動いた時刻が出ます |
| 中 | チケットの一覧。件名・本文・やりとり・メール・番号で探せます。絞り込み（状態・優先度・担当者・お客様・種類・タグ）と並び順（期限が近い順・優先度順・新しい順・古い順・更新順）を選べます。まとめて選ぶと、状態・優先度・担当者を一度に変えられます |
| 右 | 選んだチケットの会話と返信欄。その右に項目（状態・優先度・担当者・種類・お客様・タグ・お客様に見せる・開くときに確認のコード）、SLA、お客様、お客様のリンク、ナレッジ、ファイル、同じお客様のチケット、まとめる |

| キー | すること |
| --- | --- |
| `J` / `K` | 次・前のチケット |
| `/` | 探す |
| `R` | お客様へ返信 |
| `N` | 社内メモ |
| `Ctrl` + `Enter` | 送る |
| `A` | 自分を担当者にする |
| `E` | 解決にする |
| `\` | 右の欄を開く・閉じる |
| `?` | ショートカットの一覧 |
| `Esc` | 閉じる・入力から抜ける |

電話・来訪・社内で見つけたことは、上のメニューの「チケット」から登録します（「受付のメール」を選ぶと、お客様に番号とリンクを送ります）。

### チケットの流れ
状態は次の 6 つです。

新規 → 対応中 → お客様の返事待ち／保留（社内） → 解決 → 完了

- メール・受付フォームで来たチケットは「新規」です。担当者がお客様へ返信すると「対応中」になります。担当者が登録したチケットは、はじめから「対応中」です。
- 返信欄の「送ったあとの状態」で、送るのと一緒に状態を変えられます（例：お客様に質問したら「お客様の返事待ち」）。
- 「お客様の返事待ち」・「解決」・「完了」のチケットにお客様が書くと、「対応中」に戻ります。完了から 14 日より後に書いたときは、前のチケットを指す新しいチケットになります。
- 「お客様の返事待ち」のまま返事がないと、最後の返信から 3 日でお願いのメールを送り、7 日で「解決」にします。
- 「解決」は、`E` キー、右の欄の状態、お客様のリンクの「解決しました」でもできます。解決にすると、お客様に満足度（5 段階）を聞きます。
- 「解決」から 7 日たつと「完了」になります。
- 日数は「設定」の「自動で進める」で変えられます（0 でしません）。

### 返信と社内メモ
- 返信欄の「お客様へ返信」はメールで届きます。件名の頭にチケット番号（例：`[SUP-00012]`）が付き、進み具合のリンクも入ります。CC も入れられます。
- 「社内メモ」は、お客様に見えません。メールも送りません。
- 返事ごとに、作業時間（分）を入れられます。お客様ごとに合計して、契約時間とくらべます。
- お客様がそのまま返信すると、件名の番号か、どのメールへの返信か（Message-ID）で、同じチケットに入ります。引用の部分は取り除きます。依頼した人・CC・同じ会社の人でなければ、同じチケットには入りません。
- ほかの担当者が同じチケットに返事を書いていると、画面に出ます。

### 担当
- 右の欄の「担当者」で選びます。`A` キーで自分が担当になります。担当者のいないチケットに返信か社内メモを送ると、送った人が担当者になります。
- 自動で決めるときは、「設定」の「担当者の決め方」で選びます。
    - 種類ごとの「最初の担当者」（初期値）：チケットの種類に決めた人です。
    - 種類で決まらなければ、対応中が少ない人：役割グループ「サポートデスク 担当者」の中で、終わっていないチケットがいちばん少ない人です。
    - 自動では決めない

### 期限（SLA）
- チケットごとに「最初の返事の期限」と「解決の期限」を入れます。目安は「SLA」のテーブルで、優先度（緊急・高・中・低）ごとに決めます。最初の返事は分、解決は時間です。
- お客様に SLA が決まっていないときは、「標準にする」の SLA を使います。セットアップで「標準」（営業時間だけで数える）と「プレミアム（24 時間）」が入ります。
- 「営業時間だけで数える」SLA は、「設定」の「営業時間（SLA の時計）」の営業日・時間・休日だけを数えます。日本の祝日は、セットアップのときに今年と来年の分が入ります。年末年始などは自分で足します。
- 「お客様の返事待ち」の間は時計を止め、止めた分だけ解決の期限をあとにずらします。
- 残りが少なくなったとき（残りが全体の 4 分の 1、または 30 分を切ったとき）と、期限を過ぎたときに、担当者にベルとメールで知らせます。担当者がいないときは、担当者全員に知らせます。

### 定型文とナレッジ
- 返信欄の「定型文…」から選ぶと、本文に入ります。`{name}`（お客様の名前）・`{ticket_no}`・`{subject}`・`{link}` は、チケットの値に置き換わります。定型文に状態が決めてあれば、「送ったあとの状態」も変わります。定型文は、上のメニューの「定型文」で足せます。
- 右の欄の「ナレッジ」に、件名に合う記事が出ます。探すこともできます。押すと、公開した記事は題名とリンクが、ほかは本文が返信に入ります。
- 「このチケットからナレッジを作る」で、記事の下書きができます。

### お客様の側
お客様の窓口は `https://あなたの Exment/support` です（「サポートデスク：お客様の窓口」と、「設定」の「お客様の窓口（ログインなし）」の「使う」が、どちらもオンのとき）。

| URL | 中身 |
| --- | --- |
| `/support` | 窓口のトップ。FAQ を探す・依頼する・自分の依頼を見る |
| `/support/request` | 受付フォーム（ログインなし）。名前・メールアドレス・件名・内容が必須で、ファイルは 5 つまで（1 つ 10MB まで） |
| `/support/faq` | 公開したナレッジ（FAQ） |
| `/support/mine` | 自分の依頼を見る。メールアドレスを入れると、依頼の一覧のリンクがメールで届きます（7 日間使えます） |
| `/support/t/…` | チケット 1 件のページ。メールのリンクから開きます |

- チケットのページでは、受付・対応中・解決・完了のどこまで進んだかと、やりとり（社内メモは出ません）が見えます。返事とファイルを送れ、「解決しました」を押せます。
- リンクは、チケットが完了してから 30 日で開けなくなります（「設定」の「リンクの期限」）。
- 右の欄の「開くときに確認のコード」をオンにしたチケットは、登録のメールに届く 6 桁のコードがないと開けません。
- ログインするお客様（役割グループ「サポートデスク お客様」）が「サポートデスク」を開くと、自分のご依頼の一覧（`/plugins/exment_support_desk/my`）が出ます。お客様の担当者で「お客様の管理者」の人には、会社のご依頼がすべて出ます。

### メールの受付
- 「設定」の「メールで受け付ける（IMAP）」で、「受信する」をオンにし、IMAP サーバー・ポートと暗号化（SSL/TLS・STARTTLS）・ユーザー名・パスワード・フォルダを入れます。パスワードは暗号化して保存します。
- 受信は 5 分ごとです（1 回に 50 通まで）。「いますぐ受信する」でも受けられます。まだ読んでいないメールを読み、読んだ印を付けます。
- ISO-2022-JP・Shift_JIS のメール、添付ファイル（1 通 20 個まで）を取り込めます。
- 新しいメールは「新規」のチケットになり、お客様に受付のメール（番号とリンク）を送ります。件名の「Re:」などは取り、本文に「至急」「緊急」「止まって」などがあれば優先度を「高」にします。
- 差出人のアドレスが登録した連絡先にあれば、そのお客様のチケットになります。なければ、アドレスのドメインがお客様の「メールのドメイン」と合うお客様のチケットにし、連絡先を作ります。知らない差出人は「知らない差出人」の設定で、チケットにする（お客様なし）か、取り込まないかを選べます。
- 返信メールの扱いと、なりすましの疑いのメールは、上の「返信と社内メモ」と、下の「安全のための決まり」をご覧ください。

## 監視・エラーログから起票する
監視の仕組みから、API でチケットを作れます。キーは設定の画面にあります。

~~~sh
curl -X POST https://あなたの Exment/support/intake/alert \
  -H "X-SD-Key: （設定画面のキー）" \
  -H "Content-Type: application/json" \
  -d '{"title":"Disk full on web01","source":"web01.example.co.jp","severity":"error","detail":"/var 98%"}'
~~~

| 項目 | 意味 |
| --- | --- |
| `title`（必須） | 件名（`message` でも受けます） |
| `source` | 発生元（`host` でも受けます）。ドメインがお客様の「メールのドメイン」と合えば、そのお客様のチケットになります |
| `severity` | 優先度になります（`level` でも受けます）。critical・emergency・alert・fatal は「緊急」、error・high は「高」、それ以外は「普通」 |
| `fingerprint` | 同じエラーをまとめる印（なければ、発生元と件名から作ります） |
| `detail` | 本文 |
| `customer` | お客様コード |

元のメールをそのまま送れる仕組み（Postfix のパイプなど）からは、`/support/intake/mail` に POST できます（同じキー）。

- 監視から作ったチケットは、最初はお客様に見せません。
- 機能の管理で「サポートデスク：お客様の窓口」がオフのときは、`/support/intake/alert` と `/support/intake/mail` は 404 になります。

## 安全のための決まり
- お客様のリンクは推測できない長い番号で、データベースにはハッシュだけを保存します。リンクで見えるのは、そのチケット 1 件だけです（社内メモ・ほかのお客様・担当者のメールアドレスは出ません）。
- 確認のコードは 10 分・5 回まで・1 回きりです。リンクごとに、コードを送るのは 1 時間に 5 回まで、まちがいは 1 日 10 回までです（超えると、そのリンクのコードは翌日まで使えません）。
- 件名にチケット番号を書いても、依頼した人・CC・同じ会社の人でなければ、そのチケットには入りません。
- 差出人の確認は、初期値（おすすめ）では「受信サーバーの確認（DMARC か、From のドメインにそろった DKIM・SPF）に合格したメールだけ信じる」です。確かめられないメールは「なりすましの疑い」として受け付け、Cc を入れず、連絡先も作りません。今あるチケットへの返信なら、お客様に見えない社内メモ（タグ「要確認」）になります。設定で「確認に落ちたメールだけ疑う」にもできます。
- 受付フォームは、受け付けた画面にリンクを出さず、入力されたアドレスにメールで送ります。そのリンクを開くまで、チケットにタグ「メール未確認」が付き、連絡先は作りません。
- 自動返信・バウンス・自分のアドレスからのメールは取り込みません。
- 満足度のリンクは、開いただけでは保存しません。
- 担当者の画面を使えるのは、チケットのテーブルを「すべて編集」できる人（役割グループ「サポートデスク 担当者」など）だけです。「自分のデータだけ編集」では使えません。

### ログインなしのページについて
Exment は、安全のため、プラグインの `config.json` からはログインなしのページを作れないようにしています。ヘルプデスクにはアカウントのないお客様の入口が要るので、このプラグインは Exment が起動するときに `/support/...` のページを自分で登録します。Exment の公開フォームと同じ考え方で、URL の秘密が開けるものだけを見せます。
