# カスタムテーブル設定
Exment では、データを「カスタムテーブル」（表）に入れて管理します。顧客・見積・タスクなど、管理したいものごとに、テーブルを作ります。  
このページでは、テーブルを作る・直す・消す方法と、テーブルごとの設定（データで使える機能・権限など）を説明します。

- はじめてテーブルを作るとき：下の「新規作成」→「設定項目の詳細」→「保存」の順にご覧ください。
- 重複のチェックや、検索の候補に出す文言など、いくつかの列を使う設定：下の「拡張設定」をご覧ください。

## 一覧
メニューの「カスタムテーブル」を押します。  
今あるカスタムテーブルの一覧が出ます。  

![カスタムテーブル画面](img/table/table_grid.png)

※「基本情報」「ユーザー」「組織」「通知テンプレート」「メール送信履歴」「お知らせ」  
これらのテーブルは、Exment をインストールしたときから入っています。  
テンプレートでインポートしたテーブルも、この一覧に出ます。

## 設定項目の詳細

#### テーブル名(英数字) ※必須
- テーブルの名前を表します。(例：user , information , estimate )  
- ここで決めた英数字は、テーブルを開いたときの URL などに使われます。(例：http(s)://(ExmentのURL)/data/user)  
- 使用できるのは、半角英数字と記号の "-" と "_" です。
- 他のテーブルで使用しているテーブル名は使用できません。  
- テーブル名の文字数は30文字以内、テーブル名の先頭は英字を指定してください。  
- テーブルを新しく作るときにだけ決められます。保存したあとは変えられません。  

> ※URL は、「/admin」が付かない標準の設定（v7.2.1 以降に新しくインストールしたサイト）の場合です。`.env` の `ADMIN_ROUTE_PREFIX` に値がある場合（前の版で入れたサイトは「admin」）は、サイトの URL のあとにその値を足してください（例：`http(s)://(ExmentのURL)/admin/oauth/token`）。詳しくは[URLに含む「admin」の変更・削除](/ja/additional_prefix)をご覧ください。

![カスタムテーブル画面](img/table/table_detail1.png)

#### テーブル表示名 ※必須
- 画面に表示する名称です。日本語の使用も可能です。(例：ユーザー 、お知らせ 、見積 )  

![カスタムテーブル画面](img/table/table_detail2.png)  

#### ほかの言語の名前（v7.3.0 以降）
テーブルの設定画面の「ほかの言語の名前」に、ユーザーが選べる言語ごとの入力欄があります（サイトの言語は除きます）。  
言語を選んでいるユーザーには、その言語の名前が表示されます。空のときは、上で入力した名前が表示されます。  
くわしくは [名前を言語ごとに持つ](/ja/name_locales) を見てください。

#### コメント使用
- テーブルのデータに、[コメント](/ja/data_details?id=コメント)を書けるようにするときは、YESにしてください。既定値はYESです。  

![カスタムテーブル画面](img/table/table_detail11.png)

#### データ変更履歴使用
- だれが・どのような内容でデータを更新したかを、リビジョン（履歴）として残したいときは、YESにしてください。既定値はYESです。  

![カスタムテーブル画面](img/table/table_detail12.png)

#### 変更履歴バージョン数
- 「データ変更履歴使用」がYESのときに、変更履歴をいくつまで残すか（バージョン数）を、整数で入力します。  
「200」と入力すると、201回目の更新で、1回目の変更履歴が消えます。既定値は100です。  

![カスタムテーブル画面](img/table/table_detail13.png)

#### 一覧表示を最適化する
- YESにすると、データ一覧の画面を先に表示し、その後で行を自動的に読み込みます。件数や列の多いテーブルで、一覧の画面が出るまでの時間を短くします。既定値はNOです。
- 行の描画を後から行う設定です。データベースへの問い合わせを減らすものではありません。
- 設定は、データ一覧を開き直すと適用されます。

![一覧表示を最適化する](img/table/table_lazy_grid.png)

※v7.1.0より利用できます。

- YESにすると、すべてのユーザーが、このテーブルのすべてのデータを編集できます。ユーザーごとに権限を付ける必要がなくなります。既定値はNOです。

- YESにすると、すべてのユーザーが、このテーブルのすべてのデータを閲覧できます。ユーザーごとに権限を付ける必要がなくなります。既定値はNOです。  

※Exmentインストール時に、「お知らせ」テーブルのみ「全ユーザーが閲覧可能」がYESに初期設定されています。これは、すべてのユーザーが、お知らせ情報を閲覧できるようにするためです。

- YESにすると、すべてのユーザーが、このテーブルのすべてのデータを参照できます。ユーザーごとに権限を付ける必要がなくなります。既定値はNOです。

## 拡張設定
テーブルの中のいくつかの列を使う設定（重複のチェック・列どうしの比較・見出し・データの自動共有など）を行えます。

- カスタムテーブル一覧で、設定したいテーブルの［拡張設定］ボタンを押してください。  

- 設定画面に変わります。

![カスタムテーブル画面](img/table/table_extended_setting1.png)  



### 複合ユニークキー設定
いくつかの列をまとめてユニークキー（重複を許さない組み合わせ）にすると、データの新規登録のときに、同じ組み合わせの値が二重に登録されるのを防げます。  

- 組み合わせで重複を防ぎたい列を、２～３種類選んでください。
- データを新規登録するとき、選んだ列のすべてで、登録しようとする値が登録ずみの値と同じ場合に、エラーになります。  

例：下の画像のように「次回予定日」「名前」をユニークキーにすると、同じ次回予定日に同じ名前が何件も登録されるのを防げます。  
![カスタムテーブル画面](img/table/table_extended_setting2.png)

※１種類の列だけで重複を防ぎたいときは、[カスタム列設定](/ja/column.md)で、その列のユニークをYESにしてください。

※ 1:N のリレーション（[Exmentのリレーション設定参照](/ja/relation.md)）の場合、子テーブルに複合ユニークキーを設定するときに、親テーブルもユニークキーの 1 つとして選べます。  
こうすると、同じ親データの中だけで、重複をチェックできます。

### 2つの列を比較
データの新規作成と更新のときに、2つの列をくらべます。列の値が、設定した条件に合うときだけ保存できます。合わないときは、エラーメッセージを出します。  
次のようなときに使えます。  

- 「開始日」は「終了日」以前の場合のみ保存できる。
-  「X」の値は「Y」の値以上の場合のみ保存できる。
- 「担当者」と「確認者」は異なる場合のみ保存できる。

![2つの列を比較](img/table/compare1.png)    

#### 未入力の場合の扱い
片方または両方の項目が未入力のときは、選んだ条件によって結果が変わります。  
ここでは、保存できる場合を"true"、エラーになる場合を"false"と書きます。

- **AとBで合致する** : 値が両方とも未入力の場合true。どちらかのみ未入力の場合false。
- **AとBで合致しない** : 値がどちらかのみ未入力の場合true。両方とも未入力の場合false。
- **それ以外** : <span class="red">常にtrue。</span>日付や数値は、値が空のときは、ふつう比較ができないためです。  
未入力にさせたくないときは、カスタム列設定やカスタムフォーム設定で、必須にしてください。

#### 列の種類ごとの扱い
- 大小（AはBより大きい、AはBより小さい、AはB以上である、AはB以下である）の比較は、以下の列種類でのみ行えます。
    - 整数
    - 小数
    - 通貨
    - 日付
    - 時間
    - 日時

- それ以外の列種類で大小をくらべようとすると、常にtrueになります。

- 列の種類がそろっていないと、大小はくらべられません（たとえば「整数」と「日時」）。本来は、この設定を保存するときにエラーにするべきものです。  
ただし、今は、保存のときにこのチェックを行っていません。種類の合う2つの列を選んでください。

#### その他
- 3列以上の値での比較、特別な条件を使った比較、ほかのテーブルの値を使った比較などを行いたいときは、[プラグインのバリデーション](/ja/plugin_quickstart_validate)を作成してください。



### 見出し表示列設定
検索バーの候補や、選択肢の一覧に出す文言（見出し）を、どの列の値で作るかを決める設定です。  
  
たとえば、下のような「顧客情報」というテーブルがあるとします。  
顧客情報テーブルには、「顧客コード」「顧客名」「電話番号」「メールアドレス」といった列があります。  
![見出し表示列設定](img/table/label1.png)    

検索バーに検索ワードを入力すると、検索の候補が出ます。  
この候補を、次のように出したいとします。  
「(顧客コード) (顧客名)」  
![見出し表示列設定](img/table/label2.png)    
  
そのときは、カスタムテーブルの拡張設定画面で、見出しに出したい列を、次のように登録します。  
![見出し表示列設定](img/table/label3.png)  
  
こう登録すると、ページの上の検索バーに文字を入力したときに、候補が次のように出ます。  
候補の文字列は、拡張設定画面で上から登録した列の順に並びます。  
![見出し表示列設定](img/table/label5.png)  
  
「メールアドレス」も出したいときは、「メールアドレス」の列を追加してください。  
![見出し表示列設定](img/table/label4.png)  
![見出し表示列設定](img/table/label6.png)  
  
また、カスタムテーブル設定に、「IDをラベルに使用する」の項目があります。

この設定をYESにすると、ラベルの頭に、「#(id)」という文言が追加されます。

#### その他
- この見出し表示列設定を登録していないときは、カスタム列設定で1番目の列の値を表示します。
- カスタム列設定で1番目の列の値が空のときは、IDを表示します。
- IDを追加できるのは、ラベルの先頭だけです。ほかの場所には追加できません。  



### データ自動共有設定

> データ共有設定については、[Exmentにおける役割・権限の概要](/ja/permission)ページを、はじめにご確認ください。

データを保存するときに、列の値に入っている組織やユーザーに、自動でデータを共有できます。  
次のようなときに使えます。  

- データ「契約情報」の新規作成時に、列「主担当者」に割り振られたユーザーに、自動的に編集権限を追加する。  
- データ「契約情報」の更新時に、列「関係組織」に割り振られた組織に、自動的に閲覧権限を追加する。  
- データ「タスク管理」の新規作成時に、列「担当者」に割り振られたユーザーに、自動的に編集権限を追加する。  

※先に、カスタムテーブルに、列種類が「ユーザー」か「組織」の列が必要です。

その後、担当者をユーザー「user1」とするデータを新規作成時に、
![カスタムテーブル画面](img/table/table_extended_share2.png)

ユーザー「user1」に、このデータが、編集権限で共有されます。

![カスタムテーブル画面](img/table/table_extended_share4.png)

#### 設定方法

- ##### トリガー
データを共有するタイミングです。  
「新規作成時」または「更新時」を選択できます。  

- ##### 対象列
データ共有の対象となる、ユーザーまたは組織です。

- ##### 対象の権限
編集権限と閲覧権限のどちらで共有するかを選びます。


#### 共有の同期設定
はじめの設定では、トリガーが「更新時」のとき、対象の列のユーザー・組織を変えても、前に入っていたユーザー・組織への共有は消えず、共有されたままになります。  

![カスタムテーブル画面](img/table/table_extended_share5.png)

設定を変えると、データの更新のときに、「列に入っているユーザー・組織」と「更新したユーザー」以外のユーザー・組織を、共有から外せるようになります。

![カスタムテーブル画面](img/table/table_extended_share6.png)

そうするには、オプション設定の「更新時、データ自動共有設定を同期する」をYESにしてください。

![カスタムテーブル画面](img/table/table_extended_share7.png)


### 画面からの実行不可設定

データの新規作成・編集・削除や、インポート・エクスポートを、画面から行わせたくないときに設定します。  
設定すると、そのボタンが画面に出なくなります。  

- 「画面からの変更不可」項目が表示されます。

### データ画面のシステム項目表示位置

データ編集画面とデータ詳細画面で、システム項目を出す位置を決めます。  
「システム設定に合わせる」「上部」「下部」「非表示」から選択可能です。（初期値は「システム設定に合わせる」）  
※システム全体の表示位置はシステム設定で変更できます。  

![データ画面のシステム項目表示位置](img/table/system_display1.png)  

### 行クリック時の画面遷移

データ一覧画面で行を押したときに、どの画面を開くかを決めます。  
「既定値に合わせる」「データ編集画面」「データ詳細画面」「遷移しない」から選択可能です。（初期値は「既定値に合わせる」）  
※システム全体の既定値は「データ詳細画面」ですが、.envの設定値（`EXMENT_GRIDROW_SELECT_EDIT`・`EXMENT_GRIDROW_SELECT_DISABLED`。[設定値](/ja/config#一覧グリッド)）により変更できます。  

![行クリック時の画面遷移](img/table/row_click1.png)  

### 見出しフォーマット設定
> この設定は、[エキスパートモード](/ja/additional_expert)を有効にしていた場合のみ表示されます。

パラメータ変数を使って、見出しに出す値を、自由な形で決められます。  

- エキスパートモードを有効にし、拡張設定画面を開きます。

- 「フォーマット文字列入力」項目が表示されます。  

![見出しフォーマット列設定](img/table/label_format1.png)  

- データに保存している値を見出しに出すときは、[パラメータ変数](/ja/params)を使います。  
例：ユーザー情報で、「ユーザー名&lt;admin@admin.admin&gt;」と表示する場合  
${value:user_name}&lt;${value:email}&gt;  
![見出しフォーマット列設定](img/table/label_format2.png)  

- このように入力すると、見出しに出す項目を決められます。  
![見出しフォーマット列設定](img/table/label_format3.png)  


#### その他
- この見出し表示フォーマット設定を設定していると、「見出し表示列設定」は無効になります。
