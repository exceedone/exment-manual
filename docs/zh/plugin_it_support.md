# IT 支持（官方插件）
“IT 支持”（ITサポート）是面向 IT 支持、服务台的 Exment **官方插件**。用“工单”管理来自客户的请求（邮件、受理表单、电话）以及通过监控和错误日志发现的问题，并**与客户共享进展，客户无需登录**。可以免费使用。

- 源代码和说明：[exceedone/exment-plugins（it-support）](https://github.com/exceedone/exment-plugins/tree/main/it-support)
- 许可证：GPL-3.0（与 Exment 相同）
- 插件列表中显示的名称：Exment Plugin IT Support（ITサポート）。内部名称为 `ExmentITSupport`，URL 为 `/plugins/exment_it_support`。

## 可以做的事
| 领域 | 可以做的事 |
| --- | --- |
| 负责人的页面 | 专用的**受理箱**（受理箱的种类和条数、工单的列表、对话和项目共 3 列）。切换工单时也不重新加载页面。键盘操作（`J`/`K` 上下、`R` 回复、`N` 内部备注、`Ctrl+Enter` 发送、`A` 由自己负责、`E` 解决、`?` 一览）、草稿的自动保存、深色模式、手机显示 |
| 受理 | **邮件**（用 IMAP 每 5 分钟接收一次。支持 ISO-2022-JP、Shift_JIS 和附件）、**受理表单**（无需登录，先引导查看 FAQ）、**电话、来访**（由负责人登记）、**监控、错误日志**（API。相同的错误合并为 1 条并统计次数）、**IT 资产的期限**（维保、许可证、域名、证书的期限临近时自动建单） |
| 往来 | 给客户的回复通过邮件送达，客户直接回复后会进入同一张工单。引用的部分会自动去掉。**内部备注**客户看不到。在回复栏旁边显示**常用语**和**知识库的候选** |
| 防止重复处理 | 其他负责人正在给同一张工单写回复时，会显示在页面上 |
| 与客户共享 | **无需登录的链接**（只能看到那 1 张工单，有期限和撤销，有打开的记录）。重要的工单使用**确认码**（邮件中的 6 位数字）。登录的客户使用**客户门户**（公司的管理员可以看到公司的所有工单） |
| SLA | 按客户、按优先级设定首次回复和解决的目标时间。**按营业时间和节假日计算**，**在等待客户回复期间暂停**。期限临近或超过时通知负责人 |
| 自动化 | 自动分配给各种类的负责人，或处理中工单较少的人。等待回复的催促 → 自动解决 → 自动完成。解决后询问满意度（5 级） |
| 知识库（FAQ） | 公开的文章会显示在客户的 FAQ 页面和受理表单中。可以从工单一键生成草稿 |
| IT 资产 | 登记客户的 PC、服务器、许可证等，并与工单关联 |
| 报表 | 受理数、解决数、SLA 的达成率、到首次回复为止的时间、满意度等。**按客户比较工作时间和合同时间**（用于月度报告），CSV |
| 搜索 | 对标题、正文、往来、邮件、编号进行部分匹配。用空格表示 AND，标签可以选择 AND／OR |
| 自定义 | 全部是 Exment 的表，所以可以在 Exment 的页面上更改项目、页面、列表、工作流和 API。还附带工单的看板 |

## 运行要求
- Exment 7.0 及以上版本（PHP 8.2 及以上版本）。不需要额外的 PHP 扩展。
- 接收邮件需要受理用的邮箱（IMAP）。发送使用 Exment 的[邮件发送设置](/zh/mailsend_setting)。
- 自动的处理（邮件的接收、SLA、等待回复、完成、资产的期限）每 5 分钟运行一次。请设置[任务计划](/zh/additional_task_schedule)。
- 页面只有日语。

## 安装
1. 安装插件。Exment v7.2.1 及以上版本从“功能管理”安装，更早的版本上传 zip。请参阅[官方插件](/zh/plugin_official)。
2. 在 Exment v7.2.1 及以上版本中，在“管理员设置”→“[功能管理](/zh/feature)”中打开“ITサポート：受付箱”（IT 支持：受理箱）（关闭期间，设置的页面也打不开）。受理箱可以选择能使用的角色组。要使用客户窗口（`/support`）、邮件的接收、来自监控的建单时，也打开“ITサポート：お客様の窓口”（IT 支持：客户窗口）（只在受理箱打开时运行）。
   - 在新安装的站点上，这 2 项最初都是关闭的。在有功能管理之前就使用 IT 支持的站点上，这 2 项都保持打开。
   - 把受理箱设为“不使用”后，菜单中的“ITサポート”（IT 支持）也会消失。工单等的表作为数据保留，可以作为 Exment 的普通表，通过 URL（`/data/its_ticket` 等）或“管理员设置”→“自定义表”打开。想显示在菜单中时，请在“管理员设置”→“菜单”中添加表。不想让人看到时，请在角色组中取消表的权限。
3. 打开菜单的“ITサポート”（IT 支持）（或 `/plugins/exment_it_support`），点击“セットアップする”（进行设置）。会创建表、菜单、权限、SLA、种类、常用语，直到 FAQ 的示例。
   - 左侧菜单中只有“ITサポート”（IT 支持）1 项（打开后是受理箱）。工单表、知识库、客户、联系人、IT 资产、常用语从受理箱上方的菜单打开，所有的表（包括工单的种类和 SLA）从“設定”（设置）的“テーブル・権限”（表、权限）打开。
   - 1.0.6 及以前的“ITサポート”（IT 支持）文件夹（受理箱和 8 个表），在升级到 1.0.7 之后第一次打开受理箱时会合并为 1 项。管理员自己添加的菜单会保留。
4. 在“設定”（设置）中填入受理用的邮箱（IMAP）和窗口的地址并保存，然后点击“IMAP につながるか試す”（测试能否连接 IMAP）。要使用邮件的接收时，还要填入“差出人の確認”（发件人的确认）和“受信サーバーの名前”（接收服务器的名称，即收到的邮件中 Authentication-Results 开头的名称）。在填入之前，通过邮件来的工单会被标为“なりすましの疑い”（疑似冒充）。
5. 把负责人加入角色组“ITサポート 担当者”（IT 支持 负责人）。把登录的客户加入“ITサポート お客様”（IT 支持 客户），并用“お客様の担当者”（客户的联系人）的“Exment のユーザー”（Exment 的用户）关联。
6. 向客户说明窗口的 URL（`https://你的 Exment/support`）。

## 使用方法

### 受理箱
打开菜单中的“ITサポート”（IT 支持），会显示受理箱。页面分为 3 列。

| 列 | 内容 |
| --- | --- |
| 左 | 受理箱的种类和条数：“対応が必要”（需要处理）、“自分の担当”（自己负责）、“担当者なし”（无负责人）、“お客様から返事”（客户已回复）、“SLA 注意・超過”（SLA 临近、超过）、“お客様の返事待ち”（等待客户回复）、“保留”（搁置）、“監視・エラー”（监控、错误）、“解決”（已解决）、“完了”（已完成）、“すべて”（全部）。下方显示邮件接收的开关，以及自动处理最后一次运行的时间 |
| 中 | 工单的列表。可以按标题、正文、往来、邮件、编号搜索。可以选择筛选（状态、优先级、负责人、客户、种类、标签）和排列顺序（期限从近到远、按优先级、从新到旧、从旧到新、按更新时间）。选中多张工单后，可以一次更改状态、优先级、负责人 |
| 右 | 所选工单的对话和回复栏。其右侧是项目（状态、优先级、负责人、种类、客户、标签、“お客様に見せる”（给客户看）、“開くときに確認のコード”（打开时的确认码））、SLA、客户、客户的链接、知识库、文件、同一客户的工单、合并 |

| 键 | 操作 |
| --- | --- |
| `J` / `K` | 下一张、上一张工单 |
| `/` | 搜索 |
| `R` | 回复客户 |
| `N` | 内部备注 |
| `Ctrl` + `Enter` | 发送 |
| `A` | 由自己负责 |
| `E` | 设为已解决 |
| `\` | 打开、关闭右侧的栏 |
| `?` | 快捷键的一览 |
| `Esc` | 关闭、退出输入 |

电话、来访以及在公司内部发现的问题，从上方菜单的“チケット”（工单）登记（选择“受付のメール”（受理邮件）后，会把编号和链接发给客户）。

### 工单的流程
状态有以下 6 种。

“新規”（新建） → “対応中”（处理中） → “お客様の返事待ち”（等待客户回复）／“保留（社内）”（搁置（内部）） → “解決”（已解决） → “完了”（已完成）

- 通过邮件、受理表单来的工单为“新規”（新建）。负责人回复客户后，变为“対応中”（处理中）。负责人登记的工单，一开始就是“対応中”（处理中）。
- 用回复栏的“送ったあとの状態”（发送后的状态），可以在发送的同时更改状态（例：向客户提问后设为“お客様の返事待ち”（等待客户回复））。
- 客户在“お客様の返事待ち”（等待客户回复）、“解決”（已解决）、“完了”（已完成）的工单上写内容后，会回到“対応中”（处理中）。在完成 14 天之后写的内容，会成为一张指向以前工单的新工单。
- 停留在“お客様の返事待ち”（等待客户回复）而没有回复时，在最后一次回复的 3 天后发送催促邮件，7 天后设为“解決”（已解决）。
- 也可以用 `E` 键、右侧栏的状态、客户链接中的“解決しました”（已解决）设为“解決”（已解决）。设为已解决后，会询问客户的满意度（5 级）。
- “解決”（已解决）7 天后变为“完了”（已完成）。
- 天数可以在“設定”（设置）的“自動で進める”（自动推进）中更改（为 0 时不执行）。

### 回复和内部备注
- 回复栏中的“お客様へ返信”（回复客户）会通过邮件送达。标题开头会加上工单编号（例：`[SUP-00012]`），还会带有进展的链接。也可以填入 CC。
- “社内メモ”（内部备注）客户看不到，也不发送邮件。
- 每次回复都可以填入工作时间（分钟）。按客户合计，并与合同时间比较。
- 客户直接回复后，会根据标题中的编号，或回复的是哪封邮件（Message-ID），进入同一张工单。引用的部分会去掉。不是提出请求的人、CC 中的人或同一家公司的人时，不会进入同一张工单。
- 其他负责人正在给同一张工单写回复时，会显示在页面上。

### 负责
- 在右侧栏的“担当者”（负责人）中选择。按 `A` 键由自己负责。给没有负责人的工单发送回复或内部备注后，发送的人成为负责人。
- 自动决定时，在“設定”（设置）的“担当者の決め方”（负责人的决定方式）中选择。
    - 種類ごとの「最初の担当者」（各种类的“首个负责人”）（初始值）：为工单的种类设定的人。
    - 種類で決まらなければ、対応中が少ない人（按种类定不下来时，选处理中较少的人）：在角色组“ITサポート 担当者”（IT 支持 负责人）中，未完成的工单最少的人。
    - 自動では決めない（不自动决定）

### 期限（SLA）
- 每张工单填入“最初の返事の期限”（首次回复的期限）和“解決の期限”（解决的期限）。目标在“SLA”表中按优先级（“緊急”（紧急）、“高”（高）、“中”（中）、“低”（低））设定。首次回复以分钟为单位，解决以小时为单位。
- 客户没有设定 SLA 时，使用标为“標準にする”（设为标准）的 SLA。设置时会添加“標準”（标准，只按营业时间计算）和“プレミアム（24 時間）”（高级（24 小时））。
- “営業時間だけで数える”（只按营业时间计算）的 SLA，只计算“設定”（设置）中“営業時間（SLA の時計）”（营业时间（SLA 的时钟））的营业日、时间和节假日。日本的节假日会在设置时添加今年和明年的部分。年末年初等请自己添加。
- 在“お客様の返事待ち”（等待客户回复）期间时钟暂停，并把解决的期限推后暂停的时间。
- 剩余时间不多时（剩余不到全部时间的 4 分之 1，或不到 30 分钟时），以及超过期限时，用铃铛和邮件通知负责人。没有负责人时，通知所有负责人。

### 常用语和知识库
- 从回复栏的“定型文…”（常用语…）中选择后，会填入正文。`{name}`（客户的名称）、`{ticket_no}`、`{subject}`、`{link}` 会被替换为工单的值。常用语设定了状态时，“送ったあとの状態”（发送后的状态）也会改变。常用语可以在上方菜单的“定型文”（常用语）中添加。
- 右侧栏的“ナレッジ”（知识库）中会显示与标题相符的文章。也可以搜索。点击后，公开的文章会把标题和链接、其他文章会把正文填入回复。
- 用“このチケットからナレッジを作る”（从这张工单创建知识库）可以生成文章的草稿。

### 客户一侧
客户窗口为 `https://你的 Exment/support`（“ITサポート：お客様の窓口”（IT 支持：客户窗口），以及“設定”（设置）中“お客様の窓口（ログインなし）”（客户窗口（无需登录））的“使う”（使用）都打开时）。

| URL | 内容 |
| --- | --- |
| `/support` | 窗口的首页。搜索 FAQ、提出请求、查看自己的请求 |
| `/support/request` | 受理表单（无需登录）。名称、电子邮件地址、标题、内容为必填，文件最多 5 个（每个最多 10MB） |
| `/support/faq` | 公开的知识库（FAQ） |
| `/support/mine` | 查看自己的请求。填入电子邮件地址后，请求列表的链接会通过邮件送达（7 天内有效） |
| `/support/t/…` | 1 张工单的页面。从邮件中的链接打开 |

- 在工单的页面上，可以看到进展到了“受付”（受理）、“対応中”（处理中）、“解決”（已解决）、“完了”（已完成）中的哪一步，以及往来（不显示内部备注）。可以发送回复和文件，也可以点击“解決しました”（已解决）。
- 工单完成 30 天后，链接就打不开了（“設定”（设置）的“リンクの期限”（链接的期限））。
- 在右侧栏中打开了“開くときに確認のコード”（打开时的确认码）的工单，没有发到登记地址的 6 位确认码就打不开。
- 登录的客户（角色组“ITサポート お客様”（IT 支持 客户））打开“ITサポート”（IT 支持）后，会显示自己的请求列表（`/plugins/exment_it_support/my`）。客户的联系人中设为“お客様の管理者”（客户的管理员）的人，可以看到公司的所有请求。

### 邮件的受理
- 在“設定”（设置）的“メールで受け付ける（IMAP）”（通过邮件受理（IMAP））中，打开“受信する”（接收），填入 IMAP 服务器、端口和加密方式（SSL/TLS、STARTTLS）、用户名、密码、文件夹。密码加密后保存。
- 每 5 分钟接收一次（每次最多 50 封）。也可以用“いますぐ受信する”（立即接收）接收。读取还没有读过的邮件，并标为已读。
- 可以接收 ISO-2022-JP、Shift_JIS 的邮件和附件（每封最多 20 个）。
- 新邮件会成为“新規”（新建）的工单，并给客户发送受理邮件（编号和链接）。去掉标题中的“Re:”等，正文中有“至急”“緊急”“止まって”（紧急、停止了）等词时，把优先级设为“高”（高）。
- 发件人的地址在登记的联系人中时，成为该客户的工单。没有时，成为地址的域名与客户的“メールのドメイン”（邮件的域名）一致的客户的工单，并创建联系人。不认识的发件人，可以用“知らない差出人”（不认识的发件人）的设置，选择建单（无客户）还是不接收。
- 回复邮件的处理和疑似冒充的邮件，请参阅上方的“回复和内部备注”和下方的“安全方面的规则”。

## 从监控、错误日志建单
可以从监控系统通过 API 创建工单。密钥在设置页面中。

~~~sh
curl -X POST https://你的 Exment/support/intake/alert \
  -H "X-ITS-Key: （设置页面中的密钥）" \
  -H "Content-Type: application/json" \
  -d '{"title":"Disk full on web01","source":"web01.example.co.jp","severity":"error","detail":"/var 98%"}'
~~~

| 项目 | 含义 |
| --- | --- |
| `title`（必填） | 标题（也接受 `message`） |
| `source` | 发生来源（也接受 `host`）。域名与客户的“メールのドメイン”（邮件的域名）一致时，成为该客户的工单 |
| `severity` | 成为优先级（也接受 `level`）。critical、emergency、alert、fatal 为“緊急”（紧急），error、high 为“高”（高），其他为“普通”（普通） |
| `fingerprint` | 用来合并相同错误的标记（没有时，由发生来源和标题生成） |
| `detail` | 正文 |
| `customer` | 客户代码 |

可以原样发送原始邮件的机制（Postfix 的管道等），可以 POST 到 `/support/intake/mail`（使用同一个密钥）。

- 从监控创建的工单，最初不会给客户看。
- 功能管理中“ITサポート：お客様の窓口”（IT 支持：客户窗口）为关闭时，`/support/intake/alert` 和 `/support/intake/mail` 会返回 404。

## 安全方面的规则
- 客户的链接是无法猜到的长编号，数据库中只保存哈希值。通过链接能看到的只有那 1 张工单（不会显示内部备注、其他客户、负责人的电子邮件地址）。
- 确认码的有效时间为 10 分钟，最多可试 5 次，只能使用 1 次。每个链接每小时最多发送 5 次确认码，每天最多输错 10 次（超过后，该链接的确认码到第二天为止不能使用）。
- 即使在标题中写了工单编号，如果不是提出请求的人、CC 中的人或同一家公司的人，也不会进入该工单。
- 发件人的确认，初始值（推荐）为“只信任通过接收服务器的确认（DMARC，或与 From 的域名一致的 DKIM、SPF）的邮件”。无法确认的邮件按“なりすましの疑い”（疑似冒充）受理，不加入 Cc，也不创建联系人。如果是对现有工单的回复，会成为客户看不到的内部备注（标签“要確認”（需确认））。也可以在设置中改为“只怀疑未通过确认的邮件”。
- 受理表单不在受理后的页面上显示链接，而是通过邮件发到填写的地址。在打开该链接之前，工单会带有标签“メール未確認”（邮件未确认），不创建联系人。
- 不会接收自动回复、退信以及来自自己地址的邮件。
- 满意度的链接，只是打开并不会保存。
- 能使用负责人页面的，只有可以对工单的表“すべて編集”（全部编辑）的人（角色组“ITサポート 担当者”（IT 支持 负责人）等）。“自分のデータだけ編集”（只编辑自己的数据）不能使用。

### 关于无需登录的页面
为了安全，Exment 不允许通过插件的 `config.json` 创建无需登录的页面。服务台需要给没有账户的客户提供入口，所以本插件在 Exment 启动时自己登记 `/support/...` 的页面。和 Exment 的公开表单是同样的思路，只显示 URL 中的密钥能打开的内容。
