# 更新步骤 v7.3.0
从 v7.2.x 升级到 v7.3.0 的步骤。这是 v7 内部的更新，但<span class="red bold">只有 v7.3 仅靠 `composer update` 无法升级。</span>

v7.3 将管理页面的库“exceedone/exment-admin-core”从 1.x 改为 **2.x**。以往的 `composer.json` 将 admin-core 固定为 `^1.0`，因此直接运行 `composer update` 会显示“Nothing to install, update or remove”，仍停留在 v7.2.x。

| | v7.2.x | v7.3.0 |
| ---- | ---- | ---- |
| PHP | 8.2 以上 | 8.2 以上（无变化） |
| exceedone/exment-admin-core | 1.x（`^1.0`） | **2.x（`^2.1.1`）** |
| 二维码库 | simplesoftwareio/simple-qrcode | bacon/bacon-qr-code 3.x |
| Laravel | 12 | 12（无变化） |
| MySQL / MariaDB | 8.0 以上 / 10.11 以上 | 无变化 |

更新时出现错误，请参阅[故障排除](/zh/troubleshooting)。

## 1. 备份
<span class="red bold">升级前请务必备份。</span>

- 备份数据库和 Exment 的整个文件夹（包括 `composer.json`、`composer.lock`、`vendor`、`public/vendor`、`.env`、`storage`）。
- <span class="red bold">请亲自确认备份文件已生成。</span>即使 mysqldump 失败（例如数据库的 TLS 证书为自签名时），`php artisan exment:backup` 也可能不报错就结束。

## 2. 用 composer 安装的站点
在安装 Exment 的文件夹（项目根目录）中，按顺序运行：

~~~
# 1. 仅当 composer.json 中有 simplesoftwareio/simple-qrcode 这一行时
composer remove simplesoftwareio/simple-qrcode --no-update

# 2. 将 exment 和 exment-admin-core 升到 7.3 的版本（需要 -W）
composer require "exceedone/exment:^7.3" "exceedone/exment-admin-core:^2.1.1" -W

# 3. 更新数据库等
php artisan exment:update --force
~~~

- **1.** 从 v7.2 的 zip 或 boilerplate 安装的站点，其 `composer.json` 中有 `simplesoftwareio/simple-qrcode` 这一行（v7.3 不再使用）。保留也能升级，但建议删除不再使用的行。
- **2.** 请加上 `-W`（`--with-all-dependencies`）。不加会出现类似“bacon … fixed to 1.0.2 by a partial update”的提示并停止。这样会升到 exment 7.3、exment-admin-core 2.1.1 以上和 bacon/bacon-qr-code 3.x（也会加入 dasprid/enum）。
    - 如果站点自己 require 了 `bacon/bacon-qr-code` 1.x，请在同一行加上 `"bacon/bacon-qr-code:^3"`。
- **3.** `--force` 会跳过正式环境（`APP_ENV=production`）中的确认。
- `composer.json` 中既没有 exment-admin-core 也没有 simple-qrcode 的站点（只 require 了 `exceedone/exment`），用普通的 `composer update` 和 `php artisan exment:update` 即可升级。
- 完成后，请在浏览器中按 **Ctrl+F5**（强制刷新）。

## 3. 用 zip 安装的站点・租用服务器
用 v7.3 的 zip 替换。

1. 用 `php artisan down` 进入维护模式。
2. 进行上面的“备份”。
3. 更改当前文件夹的名称（例：`exment` → `exment_old`）。
4. [下载](https://exment.net/download/) v7.3 的 zip，解压到原名称的文件夹中。
5. 删除新文件夹中的 `storage`，复制旧文件夹中**整个 `storage`** 和 **`.env`**。
6. 删除新文件夹中的 `bootstrap/cache/*.php`。
7. 运行 `php artisan exment:update --force`。
8. 用 `php artisan up` 结束维护模式。

| | 处理方式 |
|---|---|
| `.env`、整个 `storage`（`app/admin`、`app/plugins`、`app/backup`、`app/templates`、`oauth-*.key` 等） | 直接使用旧的 |
| 自己放到或修改过的 `public` 中的文件、手动修改的 `config/*.php`、自己用 composer require 的包（ldaprecord 等） | 参照旧文件夹手动恢复 |
| 写在 `app/Exment/bootstrap.php` 中的自己的代码 | 手动恢复（文件会由 `exment:update` 重新生成） |
| `vendor`、`composer.json`、`composer.lock`、`public/vendor`、`bootstrap/cache` | 使用新的（不使用旧的；`public/vendor` 由 `exment:update` 重新生成） |

## 4. v7.3 中的变化
### 插件・自己的代码：消息以文字显示
在 admin-core 2.x 中，`admin_info()`、`admin_success()`、`admin_warning()`、`admin_error()`（包括 `*_once()`）和 `admin_toastr()` 的消息以**文字而非 HTML** 显示。名称或错误文本中含有 `<` 等也会原样以文字显示，因此是安全的。

消息中使用 HTML（`<br>`、链接等）时，请用 `admin_html_message()` 包起来。其中放入的值请用 `e()`（或 `esc_html()`）包起来。

~~~php
// 到 v7.2 为止
admin_info('完成', '已创建 ' . $name . '。<br><a href="' . $url . '">打开</a>');

// 从 v7.3 起
admin_info('完成', admin_html_message('已创建 ' . e($name) . '。<br><a href="' . e($url) . '">打开</a>'));
~~~

不包起来的话，`<br>` 等会原样以文字显示（功能不会停止）。

### 功能管理
v7.3 新增的功能大多在“系统设置”→“[功能管理](/zh/feature)”中决定是否使用。部分新功能一开始是不使用的。

### 页面
左侧菜单中，带有下级菜单的项目会向侧面展开（可在“系统设置”中改回以前的展开方式）。详细请参阅[发布说明](/release_note)。

## 5. 使用 Exment SaaS 的用户
Exment SaaS 由提供方升级，无需此步骤。

## 6. 恢复到原来时
恢复到升级前的备份。

1. 用升级前的备份恢复数据库。
2. 将 `composer.json`、`composer.lock`、`vendor`、`public/vendor` 恢复为升级前的（zip 站点请恢复到改名后保留的旧文件夹）。
3. 删除 `bootstrap/cache` 中的内容，并运行 `php artisan optimize:clear`。

<span class="red bold">请不要使用 `php artisan migrate:rollback`。</span>v7.3 新增的数据库变更中有些没有回滚处理，菜单和列会残留。
