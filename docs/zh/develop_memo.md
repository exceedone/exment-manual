# 开发备忘
这是面向开发者的备忘。  
这里汇总了一些规格等内容：写进各页面的手册里过于琐细，但希望在开发者之间共享。

## 权限“引用所有数据”不能与“编辑负责的数据”等组合的原因
目前，对于特定的表，不能把权限“引用所有数据”与“编辑负责的数据”“查看负责的数据”组合起来。  
原因在于下面的规格。

#### 前提
权限会被合并，以较强的权限（“允许做某事”一类的权限）为优先。  
例如，“可以取得所有数据”与“只能取得共享给自己的数据”组合在一起时，以“可以取得所有数据”为优先。

#### 权限“引用所有数据”的详情

- 执行 SQL 时，不添加数据共享的 where 子句，可以取得所有数据。
- 不能显示列表页面。也不能在菜单中显示项目。
- 不能新建、编辑数据。

#### 权限“编辑负责的数据”的详情

- 执行 SQL 时，执行按数据的 where 子句，只能取得共享给自己的数据。
- 可以显示列表页面。也可以在菜单中显示项目。
- 可以新建数据、编辑共享给自己的数据。


#### 结果
把这两个权限组合起来，结果是下面这样的详情。

- 执行 SQL 时，不添加数据共享的 where 子句，可以取得所有数据。
- 可以显示列表页面。也可以在菜单中显示项目。
- 可以新建数据、编辑共享给自己的数据。

也就是说，所有数据都会显示在列表页面中，并且可以新建数据、编辑共享给自己的数据。  
  
也可以在各页面中加入“在列表页面中，不允许取得所有数据，只能取得共享给自己的数据”这样的处理，但是在自己的插件和其他页面中都必须加上这个处理，可能成为漏洞。  
而且，这种状况与把“查看所有数据”和“编辑负责的数据”组合起来完全相同。  
因此，目前在设置上不能把“引用所有数据”与“编辑负责的数据”等组合起来。  

#### “引用所有数据”的用途
用途主要是下面这样的情况。  

- 税率  
    →给负责人等授予“引用所有数据”和“编辑所有数据”权限，把它作为主数据来维护。  
    →普通用户只授予“引用所有数据”，使他们可以把它作为选项取得。




## 删除自定义数据时的规格
从 v4.0.7 起重新整理。

#### 逻辑删除时
※因为有可能恢复，所以基本上保留  

- 自定义列“文件”“图片”的文件：不删除
- 附件：不删除
- 关系(1:n，删除父数据时的子数据)：逻辑删除
- 关系（除此以外）：不删除
- 权限控制：不删除
- 修订版本：不删除，并添加删除日期时间的历史
- 通知：执行
- 工作流历史：不删除

#### 彻底删除时
物理删除

- 自定义列“文件”“图片”的文件：删除
- 附件：删除
- 关系：全部物理删除
- 权限控制：删除
- 修订版本：删除
- 通知：不执行
- 工作流历史：删除

#### 立即物理删除时
※把设置值 EXMENT_DELETE_FORCE_CUSTOM_VALUE 设为 1，就会立即物理删除

- 自定义列“文件”“图片”的文件：删除
- 附件：删除
- 关系：全部物理删除
- 权限控制：删除
- 修订版本：删除
- 通知：执行
- 工作流历史：删除



## 函数 getOrganizationIdsForQuery 的结果与实际的组织相反的原因
函数 \Exment::user()->getOrganizationIdsForQuery 取得的结果，与实际所属的组织是相反的。  
例如，假设有下面这样的组织结构。

```
 Ex. (O):Ogganization, (U):User
 
     (O)Company
         (O)develop-team
             (U) Manager
 
             (O) develop-team1
                  (U) User1
                  (U) User2
             (O) develop-team2
                  (U) User3
```

这里，登录用户是 Manager，$filterType 是 JoinedOrgFilterType::ONLY_UPPER 时，看起来似乎会取得 (O)develop-team、(O)Company，  
**但实际上取得的是 (O)develop-team、(O) develop-team1、(O) develop-team2。**
  
这是因为，这个函数的目的始终是取得被共享的数据、取得有权限的数据，而不是取得实际的组织。  
例如，在“数据 A 共享给了 (O)develop-team1”“数据的共享包含上级层级的组织(JoinedOrgFilterType::ONLY_UPPER)”这样的设置下，Manager 会取得共享给 (O)develop-team、(O) develop-team1、(O) develop-team2 的数据。  
这时，在查询的处理上，把 Manager 视为属于 (O)develop-team、(O) develop-team1、(O) develop-team2，然后执行 SQL。  

因此，与 Enum 值给人的印象不同，实际取得的结果是相反的。


## 插件的加载处理
通常，加载 PHP 文件使用 autoload。  
它由 composer 生成，程序的开发者和使用者几乎不用在意。  
  
但是，用插件安装的 PHP 文件不能使用 autoload。  
这是因为，Exment 的插件文件可以放在 AWS S3、FTP 等外部服务上，插件文件的实体有时并不在服务器上。  
※这个功能的详情，请查看[这里](/zh/additional_file_saveplace)  
  
因此，插件的加载处理做了特殊的对应。  
下面是它的详情。  

### 下载插件文件(插件文件放在外部服务上时)
插件文件放在外部服务上时，进行下载。  
先做下面的判定，只在需要时才下载。

- 确认服务器上目标插件文件夹“/storage/app/plugins/(插件名)”中是否有“updated_at.txt”文件  
→没有时，需要下载

- 打开“updated_at.txt”文件，确认里面写的时间戳

- 与数据库的表“插件”的更新日期时间比较，确认日期时间是否不同  
→不同时，需要下载

需要下载时，从外部服务下载插件文件。  
之后，在目标插件文件夹中生成“updated_at.txt”文件，并写入时间戳。

### 把目录添加到自己的 ClassLoader
循环各插件文件，把目标插件文件夹和与该插件相符的命名空间，添加到自己的 \Exceedone\Exment\Services\ClassLoader。

### 执行加载处理
插件的类被调用时，通过 spl_autoload_register 调用自己的 ClassLoader。  
这样，就以被调用的类的 namespace 和目标插件文件夹为键，对相符的 PHP 文件执行 require_once。  
通过这个处理，即使是还没有加载的类，也会动态读取类，并执行 require_once。




## 列类型“选项（从其他表中选择）”“用户”“组织”的筛选设置
在自定义数据的输入页面中，列类型“选项（从其他表中选择）”“用户”“组织”显示的选项，并不总是全部显示。  
下面写出选项的筛选模式。  
  
※作为说明用的例子，假设有下面这样的表。  

- 当前显示的表：合同
- 通过列类型“选项（从其他表中选择）”引用的表 1：客户
- 通过列类型“选项（从其他表中选择）”引用的表 2：联系人  
※客户表和联系人表设置了 1:n 的父子关系


### 列类型“选项（从其他表中选择）”的筛选情况

#### 登录用户的权限
在引用目标的表（客户）中，只显示登录用户有访问权限的数据。  
没有权限的数据不会显示在选项中。  

##### 这个设置的处理方法
没有显示预期的选项时，请做下面其中一项，添加权限。  

- 请把想显示在选项中的、引用目标的表（客户）的数据共享给登录用户。  
详情：[数据共享](/zh/data_details)

- 请给登录用户所属的角色组，添加“引用目标的表（客户）”的“编辑所有数据／查看所有数据”权限。  
详情：[角色组](/zh/role_group)


#### 列设置“条件视图”
设置了列设置“条件视图”时，显示的选项会按该条件视图的筛选条件进行筛选。  
※条件视图是用来筛选引用目标的表（客户）的数据的视图。

##### 这个设置的处理方法
没有显示预期的选项时，请做下面其中一项。  

- 请重新检查想显示在选项中的、引用目标的表（客户）的条件视图的条件。  
详情：[条件视图](/zh/view)

- 请删除列设置“条件视图”的设置。


#### 数据有 100 条以上
引用目标的表（客户）的数据有 100 条以上时，初始显示时不显示选项。  
输入搜索词后，只把与搜索词匹配的数据作为选项显示。   
另外，把自定义列设置“每次搜索选项”设为 YES 时，不管数据条数多少，都用这种方式显示选项。  


#### 关联筛选设置
在自定义表单的设置页面中，有“关联筛选”设置。  
这个功能是：有父子关系的选项在同一个表单内时，选择父选项(客户)后，子选项(联系人)会自动被筛选。  
详情：[表单设置](/zh/form)  
 
有了这个设置，动作如下。

- 没有选择父(客户)时，子(联系人)的选项  
→一条选项都不显示。

- 选择了父(客户)时，子(联系人)的选项  
→在子(联系人)的数据中，把父(客户)的值等于父选项中所选值的数据，以列表显示。  




### 列类型“用户”“组织”的筛选情况

#### 当前显示的表的用户和组织的权限
只有可以访问当前显示的表(合同)的用户和组织，才显示在选项中。  
<span class="red">※登录用户的权限没有影响。</span>判定的基准是“要显示在选项中的用户和组织，对当前显示的表是否有权限”。  

##### 这个设置的处理方法
没有显示预期的选项时，请做下面其中一项。  

- 请在角色组设置中，给对“当前显示的表（合同）”有权限的角色组，添加“想显示在选项中的用户和组织”。  
详情：[角色组](/zh/role_group)

- 请在自定义列设置中，把“同时显示没有权限的用户和组织”设为 YES。  
把这个设置设为 YES 后，就不再检查“在当前显示的表（合同）中，用户和组织是否有权限”。


#### 面向外部门户网站的设置(构建多个组织的用户登录的系统时)
在数据列表页面、编辑页面中显示用户和组织时，有时会做“**只显示登录用户所属的组织及其所属用户**”这样的设置。  
做了这个设置时，登录用户显示组织、用户的选项时，只显示与登录用户有父子关系的用户和组织。  
详情：[面向外部门户网站的设置](/zh/multiuser)


#### 列设置“条件视图”
设置了列设置“条件视图”时，显示的选项会按该条件视图的筛选条件进行筛选。  
※条件视图是用来筛选引用目标的表（用户）的数据的视图。

##### 这个设置的处理方法
没有显示预期的选项时，请做下面其中一项。  

- 请重新检查想显示在选项中的、引用目标的表（用户）的条件视图的条件。  
详情：[条件视图](/zh/view)

- 请删除列设置“条件视图”的设置。


#### 数据有 100 条以上
引用目标的表（用户）的数据有 100 条以上时，初始显示时不显示选项。  
输入搜索词后，只把与搜索词匹配的数据作为选项显示。   
另外，把自定义列设置“每次搜索选项”设为 YES 时，不管数据条数多少，都用这种方式显示选项。  


#### 关联筛选设置
在自定义表单的设置页面中，有“关联筛选”设置。  
这个功能是：有父子关系的选项在同一个表单内时，选择父选项(组织)后，子选项(用户)会自动被筛选。  
详情：[表单设置](/zh/form)  
 
有了这个设置，动作如下。

- 没有选择父(组织)时，子(用户)的选项  
→一条选项都不显示。

- 选择了父(组织)时，子(用户)的选项  
→在子(用户)的数据中，把属于父(组织)的数据，以列表显示。
